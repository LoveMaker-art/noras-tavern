# Tavern 2.0.0 — main-branch promotion

Status: source prepared for 2.0.0; stable publication is blocked, not completed.

## Complete product source

The source is promoted from `v2.0.0-rc.9`
(`ebf16d42b81ca636f7561f3f435119197bb46a8a`) onto `main`. It replaces the old
Python application tree without retaining a second online implementation.

- `app/`: World-centered Node Tavern, ST compatibility engine, extensions,
  lifecycle adapters, frontend and generated Story Profile snapshot.
- `story-profile/`: complete authoritative Story Profile source and tests.
- `nora-mcp/`: MCP source, locked dependencies and tests.
- `ops/skills/`: Tavern, Tavern Ops, Tavern Updater and CardForge skills, plus
  the managed Tavern AGENTS block.
- `ops/updater/`: the canonical Bootstrap, full-directory update transaction,
  Python data migration and recovery implementation.

This promotion changes the Tavern release version and current entrypoint
documentation. It does not rewrite runtime behavior, bundle author model
configuration, update a remote machine, or claim new end-to-end verification.
The updater continues to use the target machine's data and model configuration.

## Default update entrypoint

After a stable 2.0.0 Release with all checked assets has been published:

```sh
curl -fsSL https://raw.githubusercontent.com/LoveMaker-art/noras-tavern/main/ops/updater/install.sh | sh -s -- --apply --confirm
```

The script lives on `main`; installation uses the latest published stable
manifest and its pinned archives. No RC tag or candidate opt-in is required.
Until publication, `releases/latest` still resolves the older stable release;
the command must not be presented as an available 2.0.0 update yet.

After installation, the owner sends `/restart` in ClawChat. Publishing the code
does not execute an update or restart on any user's machine.

## Outstanding stable-release gates

The production lockfile audit on 2026-09-01 still reports `image-size` (high)
and `showdown` (moderate), with no fix offered by `npm audit`. Those previously
deferred dependency changes have not been silently implemented or waived.

The stable packager also requires a fresh target-environment workflow report
matching the exact release commit and source digest. It covers opening worlds,
complex-card import, send/edit/regenerate/smart reply, card-library creation,
refresh/restart and timing thresholds. No qualifying report is available for
this promotion. Unit tests and the rc.9 candidate are not substitutes.

The existing stable gates remain unchanged. There is no `candidate: false`
artifact or public stable tag produced by this source-only promotion.
