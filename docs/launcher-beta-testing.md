# 启动器 Beta 测试

Beta 按本轮授权固定源码和 `v*-beta.*` 标签。构建与验收工作流只生成内部制品，不自动公开发布。公开预发布消费验收过的同一批包，沿用[发布流程的 seal／prepare／promote 阶段](release-process.md#4-明确选择发布阶段)；构建、推送及发布授权分别判断。正式启动器不读取 Beta 通道。

本文说明测试路径，不维护另一套发布规则。构建范围、制品身份、失败续跑和 APP-only 批次限制统一见[发布流程](release-process.md)。

## 下载与隔离

- Mac Apple 芯片下载名称含 `mac-arm64` 的 `.dmg` 或 `.zip`；Mac Intel 选 `mac-x64`；Windows 选 `win-x64-setup.exe` 或 `win-x64.zip`。`nora-system-*` 等组件文件不是给用户双击安装的程序。
- 从 GitHub Pre-release 下载完整启动器，在空的测试安装目录开始。
- macOS 数据目录为 `~/Library/NoraTavern-Beta`；Windows 为 `%LOCALAPPDATA%/NoraTavern-Beta`。
- Beta 各版本共用测试目录，便于保留模型、配对和故事进行更新测试；不读取正式目录或本地候选测试目录。
- 默认酒馆端口为 `18998`。不要同时启动两个使用该端口的测试实例。
- 发布包不包含用户 Key、配对或故事。公开仓库的预发布也是公开内容。
- 测试包未进行正式代码签名和 Apple 公证，系统可能要求额外确认来源。

## 首次安装验收

1. 打开下载的启动器，点击开始安装，确认版本来自 Beta 发布并通过所有组件校验。
2. 配置模型并测试成功，填入 ClawChat 配对码。
3. 确认联系人名字、头像正确，并收到符合 Nora 人格的首次消息。
4. 从手机进入酒馆，创建测试世界、角色和聊天。
5. 停止、重开启动器并再次打开酒馆，确认没有重复安装或要求重新填写 Key。

## 更新验收

1. 先安装一个 Beta 版本，保留上述测试数据。
2. 按发布流程准备并获授权发布目标 Beta，不覆盖旧标签或旧资产；固定本次源版本、目标核心／APP 版本及安装包摘要。
3. 在启动器检查更新，分别核对 APP 与核心结果及 Beta 通道。旧版入口按其实际协议单独验收，不能假定旧技能或旧 APP 已取得新能力。
4. APP 更新通过启动器自身更新或对应安装包覆盖更换。核对实际 APP 版本、原核心版本及配置保持，替换交接和重开只续接同一 APP 任务。
5. 核心更新由用户在诺拉对话中授权并提交独立核心任务。断开后查询同一任务，核对实际核心版本、适用运行结果及任务结束；APP 未被该任务替换。
6. 对各自更新路径分别测试下载断网、缺少平台组件、校验失败、替换后验证失败和执行中断。未替换时确认原程序保持；替换后的失败按本任务实际写入恢复，并核对写者退出、原任务结束及后续合法操作。
7. 正常更新和恢复后，核对原 Key、配对、自定义人格、世界和会话仍可用。普通程序更新保留当前用户内容，不将恢复旧程序解释为恢复整份旧聊天或配置树；必要备份与历史恢复按各自事务合同判断。

存量联合任务另按[历史收尾边界](product/README.md#shared-update)验收：保留已发生的结果及备份，不创建新联合任务或自动续接未执行的另一组件。历史记录恢复不能由上述新任务结果代替。

本地自动测试覆盖通道选择、文件校验、资料同步与更新事务。
CI 构建通过不等于各平台实际界面、用户模型、ClawChat 和手机端验收通过。
Hermes 跨版本行为还需用对应的两个真实运行时包进行验证，不能只靠模拟文件测试宣布兼容。

早期 Beta 的实测结果见[历史验收记录](launcher-beta-acceptance.md)，只证明其记载的候选和场景；当前候选范围及证据入口见[可靠性交付执行与证据导航](launcher-reliability-plan.md)。
