# 启动器实测修复方案

日期：2026-09-08。基线：`codex/launcher-beta` / `2.2.10-beta.2`。
状态：2026-09-08 已根据确认的前端实施，并生成本地 `2.2.10-beta.3` 候选测试包。
实际验收范围见 `launcher-beta-acceptance.md` 的本地重构测试记录；以下方案保留为原始需求基线。

## 目标与边界

完整中文首次安装、准确的阶段反馈、完整开场白与可选体验样例，以及独立的 Nora / 酒馆运行控制。
保留现有立绘、跟随和固定互动区域、字体、配色、固定窗口、对话主视觉及安装完成后的过渡形式。
不改为控制台或卡片式仪表盘，不重新加入技术日志，不增加语言选择页，不改变隔离安装目录。
不修改远端参考机器，不推送、不发布。用户本轮已授权生成新的本地测试包；现有 Beta 安装、配对和桌面测试 Key 保留。

服务控制建议为同一对话内容里的两行无嵌套卡片布局：服务名、文字状态、图标启停；

此局部布局已在独立预览中由用户确认，并接入真实 IPC；没有将模拟安装逻辑用于桌面运行。

## 01 阶段完成反馈

源码证据：`first_install.py` 先发酒馆阶段运行和完成，再发 Nora 完成；
`launcher-controller.js::displaySteps` 将第一段事实绑定到整个系统的 `systemReady`。
因此不能简单在解压 Hermes 后伪造“Nora 已完整就绪”。用户反馈的实际点亮时序尚需回归复现。

建议保留五段，区分“安装就绪”和“运行联通”：

1. Nora：运行环境、身份、技能、开场白、样例及独立配置安装校验完成。
2. 酒馆：程序、依赖、本机实例配置安装并通过本机健康检查。
3. 模型：真实模型测试成功且配置已保存。
4. ClawChat：真实配对及所需资料初始化完成。
5. 启动检查：服务、MCP、ClawChat 与 Liveware 的最终联通检查。

需要在首次安装事务内调整工作顺序，将依赖酒馆的 MCP 联通证明与 Nora 文件安装证明拆开；
跨组件总体验收仍保留，不因拆分阶段降低完整性要求。
每段具有 pending/running/done/error 状态并可持久恢复；具体失败归属具体阶段。
事务回滚后同步撤销失效的完成事实，不能继续显示绿色完成。

验收：观察真实空目录安装，第一段完成与第二段进行中同时可见；重开、失败重试和回滚不产生假完成。

## 02 完整中文开场白

参考来源：用户提供机器的 `/opt/data/clawchat/greeting.md`，已只读检查。
保留简体中文正文、QQ群、两项故事介绍和真实入口；移除语言路由与英文、繁体正文。
资料同步继续由可验证的程序负责，不再要求模型重复修改头像昵称。
安装包统一中文不等于禁止用户后续用其他语言对话，不强制改写模型协议和供应商名称。

初始化使用完整模板；升级不能仅依赖“文件不存在才复制”。
需要记录托管模板版本和哈希：已知旧默认模板可升级，用户自定义内容保留并提示差异。
自动首次问候只在真实首次会话触发，重启、更新不得反复发送；发送失败与已发送需有明确区别。

验收：不仅比较文件，还核对实际首次会话所用提示及用户收到的正文；真实发送另行获得测试授权。

## 03 酒馆入口

参考开场白使用 `/opt/data/skills/creative/tavern/scripts/tavern_cli.py app-link`，该文件不存在。
必须使用当前实例的 Liveware 注册结果及现有工具契约，不复制旧绝对路径，不拼造 URL。
入口获取应有可测试的结构化结果；成功时按 ClawChat 契约独行发送，失败时不伪造卡片或重发整段问候。

额外风险：当前 `command_start` 先启动 gateway，随后才显式完成 Liveware 初始化。
首次问候可能早于入口就绪。需验证实际触发时序，并通过初始化顺序或问候就绪条件解决。
不能只修改 greeting 文案后假定入口稳定送达。

验收：干净账号首次连接收到真实可用入口；重启不重复问候；入口失败可恢复且不重放配对码。

## 04 隐藏体验样例

只制作两个中文原创样例：陈屿的苏州雨巷、许清禾的厦门海风。
原始样例作为技能附属资源随包分发，包含版本、稳定标识及哈希；不放入用户角色卡库或世界目录。
包含完整角色设定、场景、首条消息和必要世界书，不只是开场白里的两句简介。
卡内不包含可执行脚本、MVU 或重型插件。附属暂存工具仅校验和复制用户选中的样例，不直接写入世界数据。

用户选择后才由 Nora 将确定的样例复制到本实例允许的上传暂存区，经现有 `nora.world.import` 导入。
不直接写酒馆运行数据；同一次请求重试复用幂等键，新开一场使用新键。
检查 operation 完成及世界读回后再回复已加载，不能把文件导出当成导入成功。
未选样例时不发生写入，不影响聊天、自创或导入用户卡；升级只更新原始样例，不覆盖用户生成的世界。
隐藏仅指默认不展示，不宣称模板是保密文件。

验收：空库安装后仍为空；选一个只创建一个匹配世界；重试无重复；更新不改已创建世界。

## 05 中文一致性

统一启动器可见状态、错误、安装提示、开场白、默认昵称和样例为简体中文。
`nora_profile.py` 目前根据 owner locale 选择 Nora / 诺拉，需将新安装默认昵称统一为“诺拉”。
保持既有头像昵称初始化回执，尊重用户后续自定义；不更新已自定义账号来强行统一名称。
API Key、模型标识、路径及协议名称保持原样；未知底层错误中文概括，不泄露密钥。

## 06 独立服务控制

按两个用户可理解的服务建模，不按“恰好两个 PID”实现：Nora / Hermes gateway 与酒馆，
另有 Liveware、MCP 等子进程或连接，归属和停止范围必须明确。

源码证据：已有 `running` 与 `gatewayRunning` 两个事实，但 `openTavern` 通过 `allRunning` 要求两者均运行；
`command_stop` 同时停止 gateway、Liveware 和酒馆。
启动 Hook 的 `recover-existing` 在已有入口时调用 `start_runtime`；单改按钮无法实现真正独立控制。
更新恢复逻辑也会在此前任一服务运行时重新启动两者，必须一起修正。

建议契约：

- 独立 start/stop/restart 指定服务，全部操作保留为明确的聚合动作。
- 状态区分停止、启动中、运行、停止中、异常；ClawChat 连接状态不是 gateway 进程状态。
- 打开酒馆只启动必要的酒馆服务并打开页面，不悄悄启动被用户停止的 Nora。
- 停止 Nora 保留酒馆；酒馆中依赖 Hermes 的模型或管理能力会不可用，不承诺所有玩法不受影响。
- 停止酒馆保留 Nora 对话；明确酒馆访问和管理暂不可用。
- 启动 Hook、恢复、更新、失败回滚尊重独立服务的目标状态，不能反向拉起用户停止的服务。
- Liveware 生命周期与酒馆手机访问一致，不能误把单独停止 Nora 等同于停止手机入口。
- 停止一个失败不掩盖另一个的结果；只操作本实例可验证归属的进程。
- 配置失效或服务停止不应让已完成安装重新进入安装向导。

关窗建议保持后台服务现状，首次关闭时以简短提示说明；“全部停止”才显式关闭所有本实例服务。
退出应用、关闭窗口、停止服务需分别验证，尤其 macOS 与 Windows 的进程存活差异。
具体默认启动策略和关窗提示属于待确认交互，不以平台偶然行为当成产品约定。

1. 固定复现：阶段事件时序、独立控制、首次问候与入口就绪顺序。
2. 修复后端阶段和服务契约，同时覆盖 Hook、更新恢复与回滚。
3. 完整中文内容、样例、托管模板升级及发布清单校验。
4. 在现有 UI 中接线，预览与实际 IPC 使用相同状态语义，不用定时器假装安装完成。
5. 无需重新打包的开发模式检查状态和交互，再测试真实平台包。
6. Mac / Windows 验证新装、续装、重开、更新、各服务组合、停止失败及不污染用户目录。
