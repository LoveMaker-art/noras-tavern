# 启动器再次更换自定义模型修复

日期：2026-10-01。修复最初在 `codex/launcher-model-reconfigure`（基于 `688bc5e`）实现，现已通过 `68e58e7` 合入本地 main；尚未发布或替换已安装启动器。

## 问题与原因

本机启动器 1.1.2 实际表单测试中，新地址通过测试并保存，但 Hermes 将裸 `custom` 再次规范化为旧命名服务。运行时优先选取旧服务注册项和旧凭证池。文件与验证标记相符，并不能证明实际调用使用新连接。

## 行为变化

- 共享模型写入器使用一个有明确归属的稳定自定义服务身份 `custom:nora-launcher`。再次设置更新同一记录，不复用旧服务身份，也不每次创建新记录。
- 对启动器输入的 OpenAI 兼容连接，明确绑定测试所用的 `chat_completions` 协议，避免继承旧服务的其他协议。
- 保存阶段调用真实 Hermes 运行时解析器，核对地址、凭证、模型及协议；不一致则报错，回滚配置与凭证文件。
- 启动器完成模型配置前再执行运行时复核，避免仅凭文件读回就宣布成功。
- 保留其他服务、旧凭证记录、酒馆模型、世界与聊天。运行中的诺拉仍需重启才能加载新的设置。
- 如果同名服务存在且不属于启动器，拒绝覆盖。服务解析异常返回固定错误，不输出旧凭证。

共享写入器同时覆盖启动器 `save` 与本地技能 `save-local`；没有修改 Hermes 上游源码、没有添加另一套运行时解析器。

## 验证

先新增可复现回归测试：旧源码实际解析的地址、凭证、模型、协议四项不符，测试失败。修复后通过。

21 项 Python 测试通过，包含真实 Hermes 源码在隔离临时实例中的保存、解析、重复替换及密钥轮换、原服务保留、命名冲突拒绝、写入失败回滚。另通过实际解析结果向 loopback 假服务发送 HTTP 请求，确认新地址收到新凭证及新模型名。

19 项 JavaScript 测试通过，包含启动器测试/保存/同步/复核的顺序、复核不符不报告完成、失败后的 busy 状态释放、无需鉴权以及模型连接协议。补齐测试 harness 中 main 已有 telemetry 全局，不改生产遥测功能。

未调用付费模型。没有更改本机正式配置、安装包、世界或聊天。源码已合入本地 main；未推送、发布、部署，未做 Windows 实机和修复版启动器 UI 验收。源码和受控技术验证完成，不等于用户安装的 1.1.2 已修复。
