## 先选择你的安装方式

Linux云端及服务器按实际安装来源选择下表的源码或独立部署流程；无需安装桌面启动器。设计范围见[部署平台与实例边界](product/README.md#deployment-support)，当前代码与目标之间的差异见[Linux适配缺口](product/nora.md#differences)。本次设计修订没有发布新的更新资源，不会使未发布源码自动进入用户更新入口。

| 你当时怎么安装的？ | 使用这条流程 |
| :--- | :--- |
| 下载 DMG 或 EXE，通过启动器安装 | [启动器完全版](#启动器完全版) |
| 运行 `git clone`，用 `npm start` 启动 | [源码版更新步骤](install-tavern.md#更新源码版) |
| 以前在 Hermes 环境中用独立部署脚本安装，不由启动器管理 | [旧独立部署更新](update-standalone-tavern.md) |

不知道选哪个？平时从“诺拉·酒馆”桌面启动器启动，就选择第一项；从终端进入源码目录启动，就选择第二项。仍不确定时先[询问并附上安装方式](https://github.com/LoveMaker-art/noras-tavern/issues)，不要试运行多个更新命令。

## 启动器完全版

### 更新诺拉与酒馆

从启动器 **2.2.9** 开始，诺拉与酒馆核心由诺拉对话中的独立更新器处理。

1. 结束正在生成的对话，让诺拉「检查更新」。确认目标版本后，再明确同意更新。
2. 等同一任务确认完成。接管后会话断开时，重新连接并查询原任务。更新期间保持安装盘连接，避免关机、休眠或移动安装目录。
3. 打开酒馆，核对原有世界、会话及模型配置。自行修改过人格或规则的用户可查看[文件管理范围](launcher-managed-files.md)。

旧版技能若仍要求启动器处理核心更新，或提示更新入口不兼容，可按[官方独立入口](update-standalone-tavern.md#旧技能要求启动器时的一次接入)核对原安装并继续。Windows 和 macOS 使用各自的命令。原任务仍在写入或恢复时，先查询同一任务并保留备份。

### 提示需要更新启动器时

启动器 **2.2.9** 的 **更多 → 检查更新** 分别显示启动器和酒馆核心版本。页面提供启动器更新时，可点击按钮替换桌面 APP。已保存的世界、会话及模型配置会留在原目录。

旧 APP 自身不能安全自动升级时，按下面步骤覆盖升级一次，保留原数据。普通系统内容更新核验更新器的执行协议，不再仅因 APP 版本较旧而拒绝执行。不要绕过安装归属或备份检查强行更新。

下载入口指向可用的完整安装包。若最新发行仅更新组件，安装后请让诺拉检查核心版本。Windows 便携版暂不支持启动器自动替换，可使用对应安装版。 [选择对应平台下载](../README.md#下载安装包)

1. 在 [README 下载区](../README.md#下载安装包) 选择对应平台的安装包。
2. 完全退出启动器（Mac 使用菜单“退出”或 ⌘Q），保留原来的 Nora 安装目录和安装记录；正在安装或更新时先等待任务结束。
3. **Windows**：运行新的安装程序覆盖升级，不要先执行“彻底卸载”。
4. **Mac**：打开新的 DMG，将 App 拖入“应用程序”，按系统提示替换原 App。
5. 打开新启动器，确认它识别的是原安装位置，再检查版本。

使用过自选目录或外置磁盘时，确保原位置可以访问。若新启动器显示未安装，先核对安装位置，不要立即新建或清空旧目录。

## 更新没有完成

| 界面提示 | 下一步 |
| :--- | :--- |
| 当前已是最新版本 | 不需要操作 |
| 本机版本高于最新正式版 | 不要手动降级覆盖，先确认是否使用测试包 |
| 暂时无法检查更新 | 检查网络，点击“重新检查” |
| 最新发布暂不可用于完整安装 | 保留现有安装；等待对应组件补齐，或提交反馈 |
| 更新失败 | 保留错误提示和日志，确认原服务是否恢复，不要反复删除重装 |

**不要为了更新而彻底卸载、清空数据或手动删除备份。** 回滚失败时先保留现场；“尝试恢复”不等于已经恢复成功。

诺拉返回“已接管”或任务编号仅表示更新正在执行。重新连接后让诺拉查询同一任务：只有 `succeeded` 且版本和系统核验正确才是更新成功；`rolled-back` 表示恢复旧版，升级尚未完成。

<details>
<summary>需要反馈错误时，如何保留现场？</summary>

记录本机系统、启动器版本、原版本、目标版本、任务编号及错误提示。总体操作记录位于 `<诺拉根目录>/installer/operations/<operationId>/operation.json`；系统文件事务位于 `<酒馆安装目录>/tavern-updates/transaction.json`。不要直接上传整个安装或备份目录，其中可能包含 Key 和会话；只分享脱敏后的错误信息。

</details>
