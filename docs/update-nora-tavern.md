# 核心更新与恢复

[项目首页](../README.md) · [安装与日常启停](install-nora-tavern.md) · [旧版本独立接入](update-standalone-tavern.md)

本页用于已经安装的诺拉与酒馆。更新对象是本实例核心程序，不附带升级整个 Hermes 环境。用户配置、密钥、世界、角色、会话、账本、偏好和记忆继续保留；程序恢复不自动回退这些内容。

## 选择方式

| 你的安装 | 操作入口 |
| --- | --- |
| 只用 Git 源码运行酒馆 | 按[源码版更新](install-tavern.md#更新源码版)保留修改、数据和依赖锁，再拉取、构建、启动 |
| 已有诺拉，能正常对话且已装独立更新技能 | 按下文在当前诺拉对话中检查、确认并提交一次 |
| 旧技能提示缺少独立更新组件 | 按[旧版本接入](update-standalone-tavern.md#legacy-core-entry)核对正式入口与摘要；其中固定 v2.6.5 的示例不是所有新版本的通用命令 |
| 诺拉无法对话或原任务结果不明 | 先按下文查询与检查服务；不把重新安装或再次更新当作诊断 |

## 正常更新：先检查，再授权一次

1. 在**要更新的那套诺拉**对话中发送：“检查当前这套诺拉与酒馆的核心版本和可用正式版本，先不安装。请说明当前实例、目标版本及来源；检查失败不要说已经是最新版。”
2. 核对她返回的是原实例和预期目标。先保存正在编辑的内容，结束生成。源码 main、Beta 与正式版是不同输入，不因某份代码已合并就推断用户程序已更新。
3. 确认后发送：“我授权把刚才核对的当前实例核心更新到该目标版本，保留原配置、配对、世界和会话。只提交一次，告诉我本次 requestId／operationId；断线后查询同一任务，不重新提交。”
4. 记录编号和目标。诺拉短暂断线或提交命令返回 0，只说明可能已经受理，不代表安装成功。重新连接后发送：“查询刚才编号为……的原更新任务，不要重新提交。”
5. 等待终态，再按下表核对实际结果。保留原错误及恢复结果，不用后一次重试覆盖前一次失败记录。

## 怎样判断结果

| 返回结果 | 含义与下一步 |
| --- | --- |
| `selecting`／`downloading`／`prepared`／`applying`／`verifying`／`recovering` | 仍在处理；查询同一任务，不再点一次安装或另起更新 |
| `succeeded` | 还要核对编号、实际核心版本、对应操作结果及 `systemReady: true`，再检查原世界、会话与模型是否可用 |
| `rolled-back` | 目标更新失败、发生程序回退；不是新版本安装成功。分别检查原程序、当前配置、酒馆和诺拉服务以及原写者是否结束 |
| 失败、恢复未完成、`unknown` 或查询本身失败 | 保留现场、编号和首个错误。结果不明不等于没有执行，不能换编号盲目重提 |
| 指向另一个编号或缺少可核对字段 | 不能拿“最新任务”替代原任务；先核对当前实例及原操作身份 |

普通程序维护不得要求会话、偏好或当前配置等于旧快照。只有实际文件、恢复记录与服务结果支持时，才报告恢复完成；不能无条件保证磁盘故障、备份缺失或状态未知时旧版必然可用。

## 无法对话时：先查原实例，不开始新更新

按[日常启停与故障定位](install-nora-tavern.md#下次使用停止与重启)检查酒馆和诺拉网关。它们是不同服务；不能因酒馆 HTTP 健康就认定诺拉能回复，也不能因为诺拉断线就反复重启酒馆。

在已经设置实际 `HERMES_HOME` 和 `TAVERN_PYTHON` 的终端，可以调用**已安装**的更新技能。不要直接运行 Git 作者目录里的技能来操作用户安装。

macOS／Linux：

```sh
"$TAVERN_PYTHON" -B "$HERMES_HOME/skills/system/tavern-updater/scripts/update.py" --check-environment
```

Windows PowerShell：

```powershell
& $env:TAVERN_PYTHON -B (Join-Path $env:HERMES_HOME 'skills\system\tavern-updater\scripts\update.py') --check-environment
```

检查成功后，以返回的绝对 `python` 路径作为后续解释器，不改用裸 `python3`。同一入口的 `--check` 只检查版本，`--status` 读取最近独立任务及规范操作结果。每次只执行一条状态查询；返回编号必须与原编号一致。结果不符、技能缺失或环境核验失败时，保留错误，按旧版接入说明或由熟悉该部署的人核对原任务，不新建状态文件。

失败恢复须使用原任务所属执行器和已核对的恢复记录，并取得对应操作授权；不在本页拼装通用强制恢复、删除锁或删事务目录的命令。原任务结束后，只有明确请求新一次更新才再次提交。

## 更新后确认

- 实际版本与目标一致，原任务及实际写者已结束；清单存在或命令退出不能单独代替这些结果。
- 酒馆能打开原世界与会话；当前模型、配对和偏好保留。程序回退不应回退用户新写的故事。
- 需要诺拉和远程应用入口时，分别确认真实回复以及 Tavern／Story Profile 的可访问性。
- 有失败时记录原错误、任务编号、恢复状态与未通过项；不要公开 Key、连接码或完整聊天。

实现及测试层次见[核心维护合同](core-maintenance.md)，发行要求见[发布流程](release-process.md)。这些操作指引不是本轮重新完成历史版本升级或目标机器恢复验收的证明。
