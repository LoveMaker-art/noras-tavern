# 更新器整目录与数据迁移：隔离演练

## 范围

用户授权：只在隔离副本实现、验证；不改在线服务、不启用正式升级入口。
源码基线为候选分支 `1b6365e`。原本地 main 的未提交改动保持不动。

实现沿用原发布包校验、技能安装审阅、AGENTS 合并和 MCP 配置接口。
`isolated_update.py` 是受临时目录/标记/独立端口限制的目录事务适配器；默认入口仍
使用原文件事务。这个过渡状态为了验证和兼容已有回滚记录，不能宣传为生产架构
已经切换。批准生产上线前，应明确默认入口迁移以及旧事务仅留恢复的收敛方案。

## 已实现

1. 完整新代码目录准备后再切换。旧 app/ops/MCP、四个技能及退役技能退出活动路径，
   原树保留于事务备份。已知第三方插件目录单独保留，其他额外代码列入审核报告。
2. 复制整个 tavern-state，只在副本迁移。世界、聊天、角色卡、世界书、MVU、账本、
   模型配置和 Profile 原文件随原树保留。额外覆盖 Profile 的 USER.md/MEMORY.md
   投影恢复，但不替换整个 Hermes 主目录。
3. Node World v1 使用项目已有转换逻辑产生 v2。正常 v2 保持原身份，不重新计算其
   Session ID。检查资源关联、对话内容不变、原档案格式和迁移前后 World 对账。
4. 不认识的格式、损坏记录、冲突绑定会失败退出。不会为通过检查创建假世界、调用
   模型重新生成档案或删除旧数据。
5. 每次目录重命名前记录意图；支持两个重命名之间强制退出后恢复。坏备份或并发
   改动阻止覆盖。升级后新对话/新记忆会阻止覆盖式回滚，避免静默丢失新增内容。
6. 空间预算包括整个状态副本，限制同文件系统重命名；状态符号链接和特殊文件拒绝。
   npm 依赖空间仍有估算余量，磁盘预检不等于绝对不会 ENOSPC。

## 测试方法与边界

- 首先在旧更新器复现两个失败断言：旧程序残留、启动写数据后文件回滚无法恢复。
- 隔离事务测试涵盖连续三次升级、回滚、损坏备份、自定义插件、旧技能退出、投影
  恢复、磁盘写错误，以及子进程 `os._exit` 强制终止后的日志重放。
- Node 数据测试使用真实历史 v1 格式与仓库脱敏 MVU PNG；含 30 轮双向消息、
  思考、swipes、MVU 值和 Profile schema-1 文件。它不是在线用户数据库，也不是
  30 轮真实模型生成；所有检查均为零模型调用。
- 真实进程演练使用历史提交 `053646a2bf65dbc6ce234ff3788d2e4648a14c12` 的
  Tavern **1.25.1**，不是给新版本改一个旧版本号。升级后检查 Node 健康、两 App
  路由、MCP 0.3.1 新进程、HTTP World 列表与激活快照，再恢复原聊天/配置/代码。
- MCP 初始文件取自候选包，因此没有证明所有旧 MCP 版本的迁移；验证的是新 MCP
  可启动、只读发现清单正确。自定义插件文件保留不等于插件行为全兼容。

本轮实际结果：60 项 Python 更新器/技能测试、5 项 Node 数据迁移测试通过。
完整候选构建另通过 394 项 Tavern 测试中的 393 项（1 项真实模型测试跳过）、
25 项架构契约、MCP 单元/stdio 集成与 Story Profile 投影测试。
最终隔离进程验收读取了迁移后的 HTTP World 激活快照及保留的档案 revision；
随后恢复 1.25.1 原代码、原始 JSONL 对话和用户配置。没有付费模型调用或远端部署。

## 未完成、不能声称可给所有老用户自动升级

- 原 Python `production/story/runtime_cast/story_state` 的无损业务转换。原代码
  一个 production 可关联多角色、动态角色状态及独立压缩结果，当前 World 模型
  不能靠改字段名完整表达。当前遇到这类数据明确拒绝，未做有损“先导进去”。
- 真实在线聊天、复盘、MCP 写入的维护窗口和排空；隔离实验采用停服前置条件。
- 远端 Liveware UI、所有插件行为、正式发布依赖安全门禁。
- 普通生产入口仍有上一阶段记录的限制；隔离实验成功不能解除保护开关。

结论：新目录事务与 Node 迁移已经有可重放的技术验证，不等于全历史 Python 数据
迁移完成，更不等于已部署正式更新器。生产部署需要单独授权和验收。
