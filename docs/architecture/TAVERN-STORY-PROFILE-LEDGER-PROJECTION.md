# 剧情账本 → Story Profile → Hermes 记忆投影

日期：2026-08-30。先完成本地源码接入与隔离验证，后经用户单独授权部署远端；最新部署范围与证据见末尾。没有提交 Git。

## 目标与不变项

复用同级 `story-profile/core/story_profile.py` 的原投影规则，让 Nora 已生效账本进入共同故事记忆。原 UI、偏好复盘、模型配置、每批轮数和上下文替换规则不变；投影不调用模型。`codebase-design` 的模块设计原则用于将选取、合并通知、失败恢复集中在一个后台投影模块，调用方仅提交同步通知。

这不是把剧情塞进“我对你的了解”或把剧情账本改成页面的成长年表。两条来源仍独立：

- 模型偏好复盘 → `taste_profile` → `USER.md` 的故事口味。
- 已生效剧情账本 → `shared_story_memory` → `MEMORY.md` 的共同虚构经历。

## 什么时候投影

1. 压缩生成候选 `pending` 时不投影。
2. 最终模型请求确实携带该账本、上游接受请求后，原账本逻辑将其持久化为 `active`；此时后台请求同步。并非等待整次回复完成。
3. 通过 World Core 获取 READY 世界及 Session 绑定；校验 JSONL 世界/Session 身份及账本覆盖历史摘要。失配的账本不进入投影。
4. 同一世界有多个分支时，只选最近激活账本的 Session，不把冲突分支拼成一段共同经历。
5. 适配为原 Python `productions[].story_state`，只传世界名称、覆盖轮数、事件、未完线索和激活时间。
6. 复用 Python `sync_story_states`。没有新增模型调用或前台 Python 等待；文件读取异步，校验和 JSON 处理仍在 Node 进程执行，并非零开销。

## 原规则的内容限制

| 输出 | 内容来源 | 限制 |
| --- | --- | --- |
| `USER.md` 托管块 | 故事口味：角色风格、人物关系、题材、节奏、叙事方式、参与方式、边界、回答适配 | 投影正文合计最多 900 字符；每类最多 4 条；口味入库时每条最多 240 字符 |
| `MEMORY.md` 托管块 | 世界名称、账本覆盖轮数、剧情事件、未完线索 | 投影正文合计最多 1300 字符；最近 3 个世界，每世界最多最近 4 条事件、前 2 条线索 |
| `story_profile.json` 的 `shared_story_memory` | 上述剧情投影的结构化数据，不是完整账本 | 最近 3 个世界；每世界最近 12 条事件，每条最多 420 字符；前 6 条线索，每条最多 320 字符 |
| `actor_self.md` 派生档案 | 原身份、确认偏好、最近成长记录、阶段摘要 | 原渲染逻辑没有整份文件字符上限；最近成长记录 8 条，旧记录按 20 条形成阶段摘要。此文件不是 Hermes `SOUL.md` |
| 显式 `context` 输出 | USER 与 MEMORY 两份正文，加故事用途说明 | 内部拼接正文另有 3000 字符兜底；当前两份上限合计本就小于 3000。不是新增自动注入路径 |

注意：

- **字符不等于 token，也不是整个 USER/MEMORY 文件的大小限制。**标题、换行和投影 revision 注释计入正文额度；外层 START/END 标记、原有非酒馆内容不计入。
- 沿用原实现的逐行限额：遇到下一行放不下即停止；不再调用模型二次缩写，也不保证三世界、所有分类都能同时放下。超出部分不从完整账本删除。
- 当前 Nora 账本入库时事件已限制为每条 120 字符、线索每条 140 字符，因此上述 420/320 是原投影模块的接受上限，不会扩充 Nora 数据。
- 不是全量对话导出。不直接复制原始聊天、推理文本、MVU 状态、物品表、秘密表或场景状态表；事件/线索自身已经描述的信息仍会出现在摘要中，这不是保密过滤器。
- MEMORY 块保留“酒馆中的虚构故事”说明，不能将其当作用户的现实经历。
- `SOUL.md`、`AGENTS.md` 不是本链路的写入目标。原人格编辑接口可单独编辑配置的人格文件（上限 20000 字符），不等于自动剧情投影。本次没有触碰它。
- 先前压缩模型的 `max_tokens=20000` 与这些投影字符上限是不同概念，本次没有改变模型参数。

## 写入、恢复与边界

- USER 标记：`TAVERN_USER_PROFILE_START/END`；MEMORY 标记：`TAVERN_SHARED_MEMORY_START/END`。只替换第一个对应托管块；没有块时添加块，保留原文件其他内容及空白。
- 修正正则替换把正文反斜杠误当作替换指令的问题。现在地图路径等文本按字面写入。
- 所有原档案提交使用可重入进程锁及文件锁（当前 macOS/Linux 的 flock），保护“读取最新档案→改对应字段→投影”事务，避免剧情同步覆盖新偏好。Windows 的原 fcntl 回退不提供跨进程互斥，本次不声称验证 Windows。
- 无变化的账本投影不递增 revision，不反复改文件。发生部分记忆文件写入失败时，下次同步仍重试托管块写入。
- Nora 后台同步合并并发通知，失败按 5、10、20、40、60 秒退避重试，最多间隔 60 秒；失败不撤销已生效账本，不阻断聊天。日志只含事件/错误代码，不输出摘要正文。
- 删除持有账本的 Session 时触发重新汇总；删除世界的共同记忆移除，其他世界及 USER 偏好保留。
- 进程重启后，**首次使用账本运行时**从已持久化 active 记录恢复同步；不是独立常驻扫描器。现有已生效账本因此可补投影，无需重新压缩。
- 保留原 Hermes 提示词缓存处理：写入发生变化后，尝试清空当前仍活动、旧 revision 的 ClawChat `system_prompt`，让后续请求重建；不删除会话，不改变正在进行的模型请求。依赖匹配的 Hermes 数据库结构/权限，缺失或不兼容时不能声称 Hermes 已刷新。
- 仍沿用既有的单 Hermes 档案目录配置，不增加多账户记忆隔离系统。多个不同用户实例必须配置各自档案与 Hermes 目录，不能共用同一投影目标。

路径沿用原配置：结构化档案为 `TAVERN_STATE_DIR`；记忆目录优先 `TAVERN_HERMES_MEMORIES_DIR`，否则 `HERMES_HOME/memories`；提示词数据库优先 `TAVERN_HERMES_STATE_DB`，否则 `HERMES_HOME/state.db`。
