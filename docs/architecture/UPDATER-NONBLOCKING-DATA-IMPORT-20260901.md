# 更新器：程序升级与 Python 数据导入分开判定

## 本次范围

基于本地 main `3450447` 修改更新器、配套技能说明和回归测试。
不修改 Tavern / Story Profile / MCP 的业务实现，不新增 Node 数据版本迁移，
不发布、不推送、不操作用户远端，不删除用户原件。

目标：先保护原始数据，再安装新版；某条 Python 数据不兼容不能否决整个安装。
这不是“忽略所有错误”，也不宣称任意旧 JSON 都能通过当前角色卡导入界面载入。

## 行为变化

| 情况 | 现在的处理 |
| --- | --- |
| 命名空间里的普通非 JSON 文件、备份子目录 | 原样归档，计入 archived，不算数据导入失败 |
| 坏 JSON、非规范卡、未适配世界书 | 逐条列入 deferred，保留原件，其他记录继续 |
| 世界缺少依赖、聊天不合法、旧背景缺失 | 整个世界待转换；不提交其运行卡、聊天、世界清单、额外世界书绑定 |
| 账本不兼容但聊天有效 | 保留完整聊天；旧账本待转换，不激活错误压缩结果 |
| 有效 Story Profile | 原文件保留，不改写内容 |
| 非法 Profile 文件 | 在准备副本中原样归档，移出活动文件位置，报告待转换 |
| 非法模型记录或失效选择 | 原配置保留并报告；只使用目标机器可读取的有效模型，不携带开发者配置 |
| 所有旧世界都无法转换 | 新版得到空世界列表，原始世界仍可从备份和归档找回 |
| 新版和两个既有 App 绑定已确认，但公网检查失败 | 安装保留；单独报告 external-entry-unverified，不称公网已验收 |

`ImportPlan.record()` 是导入边界：只接收明确的 `DeferredData` 兼容性失败，
撤掉该记录的内存输出计划。目录写入仍统一在所有目标预检后进行。
磁盘错误、非法路径、链接、目标冲突、依赖损坏和未知代码异常仍上抛，触发原有安全恢复。
没有新增按某个 `.bak_*` 后缀打补丁的名单，也没有包住整个迁移函数吞异常。

## 数据位置与结果

- 成功切换后，完整更新前数据树位于事务的 `backup/state`。
- 原始 cards / worldbooks / productions 位于新状态树的 `python-source`。
- 不兼容 Profile 文件位于 `python-source-profile`，有效文件保持原位。
- 原始 `model_configs.json` 保持不变；有效配置转换为 Node 设置和私有 secrets。
- 事务 `migration.json` 和状态树 `python-import.json` 保存导入报告。
  每条 `deferred` / `archived` 都给出相对状态目录的 `archiveFile`。
- 最终结果 `dataImport` 分别给出导入数、待转换数、辅助文件归档数、备份和报告路径。
  `partial` 表示程序可以安装但仍有数据待处理，不表示这些数据已可玩。

正常 Node 更新依然只验证现有数据；本次不增加 Node v1→v2 迁移。
AGENTS 受管块之外内容、自定义技能、目标模型密钥和两个 Liveware App ID 的保留规则不变。
公网观察失败和不确定的 App 写操作不同：绑定/注册身份不明的写操作仍进入恢复，不能伪装成功。

## 恢复重试

旧 Python 服务恢复后立即持久化新进程身份，再做身份绑定的健康检查。
重试优先验证已记录的新进程；旧收据也可通过同用户、同入口、同 argv/cwd 的唯一进程发现恢复。
只匹配端口或 `server.pid` 不够，不会因此杀掉未知进程或启动重复实例。

新更新可自动结清旧预切换收据，但必须同时满足：

1. 属于当前安装，计划摘要匹配，模式/端口一致，Python 布局未变。
2. 没有目录切换意图、恢复条目或平台写入。
3. 旧基线、程序目录和受管文件仍与旧计划一致。
4. 原服务经独立进程和监听端口健康核验，或能够证明原本离线且仍离线。

只更正该收据状态，不调用旧引擎重做目录回滚，不再停一次正常旧服务。
已经人工换过版本、真正切换到一半、修改了代码或服务身份不明的历史事务仍需明确恢复；
本次没有把这些情况伪装成已恢复。

回归入口：

```sh

node --test ops/tests/test_python_migration.mjs

```

覆盖真实准备脚本、正常/部分/全坏数据、完整原件保留、坏记录不留下半个世界、
有效 Profile 字节不变、目标模型处理、重复迁移保护、程序/数据结果分离、
公网未验证不回滚、真实临时进程恢复与重复恢复、安全收据结清以及危险条件继续拒绝。

测试使用临时数据与临时服务，无模型调用；沙箱禁止端口/ps 时，进程测试需相应权限。
这些是本地技术验证，不是该反馈用户的数据验收、Liveware 公网实测或正式版本发布。
更新器技能仍只要求“开始 + 最后总结”，不新增人工浏览器验收门槛。
