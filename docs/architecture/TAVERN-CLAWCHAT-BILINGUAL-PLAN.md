## 1. 交付目标与完成定义

用户要求：**固定、通用的系统内容提供完整中英文显示，跟随 ClawChat 的语言设置更换。**

这不是“首页增加几个英文按钮”，也不是“读取操作系统语言即可”。交付必须同时满足：

1. ClawChat 中文时，Tavern 固定系统文案显示中文；ClawChat 英文时显示英文。
2. 启动、世界切换、聊天操作、资料库、模型配置、错误提示、ST 通用弹窗及内置插件公共提示都覆盖。
3. 同一页面只有一个当前界面语言决定者；刷新、异步加载、跨页面跳转不能互相覆盖语言。
4. 默认验收包含：ClawChat 更改语言后，已经打开的 Tavern 能获得新语言并更新固定系统文字，不丢输入、不取消生成、不重建世界。
5. 如果宿主只在重新打开时传入语言，必须明确报告限制并取得用户对“宿主配合”或“重新打开生效”的选择；不得自行降低第 4 项标准。
6. 翻译不更改模型请求、卡片内容、MVU 配置键、世界数据、脚本命令和现有交互语义。
7. 固定文案覆盖检查、业务回归、实际 ClawChat 联调和部署验证全部通过后，才能称为完成。

证据等级分开记录：已分析、已实施、技术验证、目标环境用户流程验证、已部署。文档完成不代表功能完成。

“系统提示”必须按用途分类：通知用户的固定 UI 提示纳入；发送给模型的 system prompt 不纳入，不能因名字中有 system 就翻译。

### 2.2 保留、不翻译、不迁移

- 用户消息、模型正文、实际思考内容、智能回复生成内容。
- 角色名、世界名、人物资料、世界书正文、卡片标签、作者信息及档案生成内容。
- 已保存的“未命名世界”等名称仍是用户数据，不能按字符串猜测后自动改名；未填写时的界面占位文字可以翻译。
- 供应商/模型的真实名称、用户自定义模型配置名称、Tavern/ClawChat/Hermes/MVU 等专有名称。
- JSON 属性名、MVU 中文字段键、变量路径、正则表达式、宏、Slash 命令、事件名、错误码和 DOM 选择器。
- 卡作者自己的 HTML/iframe 页面和第三方插件自己写死的业务内容；不注入全页机器翻译。
- 终端日志、技术栈、原始供应商诊断、开发文档不是用户界面翻译目标；界面须有对应的通用本地化错误说明。
- 浏览器/操作系统原生文件选择器及 ClawChat 自己的窗口、注册列表名称由宿主管理，不伪装成 Tavern 可独立控制的文字。

### 2.3 UI 与架构约束

- 保留现有控件、显示/隐藏条件、默认折叠状态、排序、事件处理和返回值。
- 不新增独立的 Tavern 语言设置按钮，不与 ClawChat 争夺语言控制权。
- 不重新显示已移除的 ST 设置页，不重构 World Core、发送队列、角色卡导入或 MVU 执行器。
- 允许为英文长度做最小布局适配，例如自适应宽度、必要的换行；不借机重新设计界面。
- 不整体替换聊天区或弹窗 DOM 来切换语言，不触发正在进行的保存、发送、取消、导入操作。
- Story Profile 仍是独立源码项目；本次不改其偏好生成、年表、存储与记忆投影。

## 4. 语言契约与宿主适配

### 4.1 权威来源

在 ClawChat 内：使用其明确传入的当前应用语言；不使用服务器地区、聊天正文语言、模型语言或旧 ST 设置猜测。

首次进入由已核实的宿主初值初始化；有效的后续宿主语言更新覆盖这个初值。页面内部跳转显式携带当前语言。

仅在独立浏览器打开且确无宿主上下文时，允许浏览器语言作为兜底。不能把缺失宿主语言静默兜底成“ClawChat 跟随验证成功”。

本次交付简体中文与英文两套 Tavern 文案：中文语言家族映射到中文、英文家族映射到英文；其他语言回退英文。P0 确认 ClawChat 实际返回的代码，包括 `zh`、`zh-CN`、`zh-Hans`、`en`、`en-US` 等；不额外开展六语言翻译。Profile 已有繁体资源不删除、不回退改造。若用户要求 Tavern 独立繁体词表，在实施前明确新增范围。

### 4.2 已打开页面的更新

P0 必须查清宿主采用哪种方式，并记录实际证据：

| 实际能力 | 处理原则 |
| --- | --- |
| 官方桥可获取初值并订阅变更 | 按实际协议接入；核实发送来源、取消订阅、页面恢复和版本支持 |
| 宿主更新页面 URL 或重新导航 | 验证是否销毁页面与中断会话；不能当作无损热更新；保持未发送/未保存内容的方案须另核实 |
| 只在新开 Liveware 时设置 `lang` | 新开可跟随，但已开页面实时跟随未满足；停止这部分实施并报告需要宿主提供信号，或请用户接受重开生效 |
| 只有传闻或二进制符号 | 不足以编写生产 Adapter；获取官方源码/文档或经授权复现宿主行为 |

Tavern 不自动刷新页面来完成语言切换，不轮询聊天记录、系统配置文件或外部接口猜测语言。

若实际协议使用 `postMessage`，只接收约定来源和 schema；卡片 iframe、任意跨域窗口和未验证来源不能改变宿主语言。若原生桥的来源规则不同，按原生契约验证，不盲套 Web 规则。

## 5. 实现设计

### 5.1 一个语言 Module，小 Interface

建议源码集中在 `public/scripts/nora-i18n/`，最终文件拆分在 P0 清单中固定，不引入独立服务、新仓库或大型国际化框架。

- Locale 状态：规范化语言、来源、修订号；只存在于当前页面显示状态中。
- 固定词表：Tavern 的中文/英文语义 key，参数占位符、单位和单复数规则。
- 宿主 Adapter：只负责经过验证的初值、更新和生命周期，不引用世界或生成逻辑。
- 显示绑定：将稳定 key/参数关联到应用拥有的文字节点和属性。
- ST Adapter：将既有翻译 Interface 接到同一语言状态，保留原调用约定。

业务显示调用者只需当前语言、`t(key, params)` 及必要的语言订阅；宿主消息校验、词典加载和回退留在 Module 内部。

依赖方向：语言基础 Module 不反向 import `script.js`、World Core、模型管理或控制器。避免 ST `i18n.js` 的既有循环引用扩散到首屏。

### 5.2 切换只更新文案，不重新执行流程

- 固定文本及属性使用明确的本地化绑定，避免扫全页匹配“中文句子”。
- 状态说明保存“文案 key + 参数 + 原状态”，而非只保存已经翻译的字符串。
- 已打开的通知、进度、确认窗和模型设置通过显示绑定更新；不得再次执行回调或重建表单。
- 保留输入值、光标、选区、IME 输入状态、焦点、滚动位置、菜单/弹窗展开状态。
- 保留正在进行的流式生成、复制任务、导入/保存、世界选择和 MVU 执行；不得新增命令请求。
- 异步任务完成时使用当时有效的语言；旧语言词典迟到不能覆盖新语言（按修订号或等价机制防止竞态）。
- 已渲染消息只更新系统操作按钮和思考标题，不重新解析正文，不重建卡片 iframe。
- `innerHTML`、`textContent` 的写入位置须限定到文字容器，不能清掉图标、子控件和处理器。

### 5.3 ST 与插件兼容

- 保留 `t` 模板字符串、`translate(text, key)`、`getCurrentLocale()`、`addLocaleData()`、`applyLocale()` 的可用契约。
- Nora 使用统一 locale；如 ST 调用者需要 `zh-cn` 等标识，由 Adapter 映射，不能另造一套语言选择。
- 插件 locale 文件按“准确代码 → 合法别名/基础语言 → 插件默认”解析；绝不把任意语言文件强制当作中文。
- 词典按语言/扩展身份隔离，切语言时不能混合上个语言的数据，也不能让插件覆盖系统保留词条。
- 自动翻译仅应用于已确认的原生模板、弹窗和受管插件根节点；不用全页 MutationObserver 改写卡片内容。
- 动态弹窗必须在显示前处理默认文字和模板属性；调用者提供的自定义正文/标签需辨别是系统词条还是内容，不能猜测翻译。
- 内置酒馆助手词典使用当前受管发行版本；如公共界面仍有硬编码，记录位置并从可维护源/受管构建链处理，不在压缩包内随手替换。
- 语言更新不得重启插件。若某个受管插件缓存了初始化语言，需补显示层刷新能力并验证；不能以“接口已接”宣称该插件可实时更新。
- ST `t()` 的调用点要区分显示和模型/存储用途；不得把提示词、消息持久化文本随 UI 语言重写。

### 5.4 文案、错误与内容隔离

- 词条 key 表示语义，例如 `message.retry`、`reasoning.completedDuration`；保留插值参数，不拼接零碎句子。
- 中英 key 集及参数集合必须一致；缺失词条在开发和发布校验中报错，不依靠静默回退掩盖漏翻。
- 错误分类优先使用稳定错误码；上游只能返回文本时，在既有错误归一化处识别一次，再产生 UI 描述。
- 不修改服务端错误码和 retryable 含义；若缺少区分所必需的错误码，只作小范围、兼容的补充并单独验收。
- 未知错误显示本地化的通用说明并保留已有诊断渠道，不把原始英文/中文堆栈当作已双语化的用户说明。
- 对插值的世界名、角色名和外部错误数据按原显示安全规则转义；翻译不得引入任意 HTML 执行能力。
- 日期/数字只改变显示格式，不改变 UTC 值、轮数、token 数、持续时间或业务阈值。
- 英文布局使用自然短文案；不靠无限缩小字体或隐藏关键按钮解决长度问题。

### 5.5 首屏、资源与发布

- 首屏语言选择与必要词条必须在可见中文占位出现之前可用；不能等 ST、模型配置或世界打开后才翻译。
- 同一份受维护源码生成早期 bootstrap；不得手写另一份首屏语言判断。运行时接管同一页的 locale 状态。
- 早期 bootstrap 与核心词典分别进入现有 HTML/资源构建链，核心完整词典不重复内联到多个位置。
- 为 data URL/import-map、普通模块与 Webpack 路径验证单一 locale 状态，不依赖“路径不同但应该是同一模块”的假设。
- 不使用语言参数改变不可变资源的内容；一个 release 的同一个资源 URL 内容必须固定。页面按本地语言选择打包好的文案。
- 不新增首屏关键路径上的远程翻译/语言 API 请求；内置词典随现有交付加载。第三方可选词典按需，不阻塞世界列表。
- 继续沿用内容哈希、压缩和 manifest 校验。源码修改后走正规构建，不手改 `dist`、压缩副本或部署目录。

### 5.6 Story Profile 的有限接入

- Tavern 去程带当前 `lang`；返回时保持最新语言，不让旧 `return` 参数恢复过期语言。
- 不依赖跨 App 域名共享 `sessionStorage`；每个 Liveware App 从宿主取得语言。
- 将已发现的亲密度等级/默认说明等固定标签与生成内容分开；只本地化前者。
- 若需修改 Profile 前端语言生命周期，改 `../story-profile/public/` 源码并单独记录差异，再显式同步快照；不改变 `core/reflection.py`、`core/story_profile.py`。
- 对独立 Story Profile App 的完整实时切换验证须纳入明确目标环境清单；若实施授权仅为 Tavern，不擅自扩展其独立业务功能或注册配置。

## 6. 执行阶段与每阶段出口

所有阶段使用同一条双语化实施线，不把未完成译文或兼容接口单独部署给用户。每阶段完成后对照本计划提交检查结果。

| 阶段 | 工作 | 必须产出的证据 / 出口 |
| --- | --- | --- |
| P0 协议与清单冻结 | 核实宿主初值/变更/恢复协议；确认客户端范围；盘点 S01–S16 的实际入口、所有状态、文案和非翻译内容；比对本地/远端基线 | 宿主契约证据；可核对文案清单；异常路径清单；范围与未决项明确。宿主缺口不得标为通过 |
| P1 语言基础 | 建立统一 locale、词表、参数与显示绑定；处理来源优先级、别名、更新和竞态 | 契约/词表/安全测试；新语言不触发业务副作用；没有接入旧设置页 |
| P2 Tavern 完整显示 | 覆盖首屏、所有控制器、动态状态、提示、配置与辅助标签；补齐英文布局 | S01–S11、S14–S15 每项都有代码映射和中英结果；控件清单与行为不变 |
| P3 ST 和内置插件 | 翻译 Interface 适配、原生思考、弹窗模板、系统提示、插件 locale 注册与更新 | S12–S13 全覆盖；插件 API 合同不变；脚本/生成/停止/思考正文回归通过 |
| P4 交接与异步场景 | 完成 S16，测试跨页/返回、多次语言变化、流式输出/导入/表单编辑中的切换 | 不丢值、不多发、不重复初始化；过期请求不覆盖当前语言；必要 Profile 差异单独列出 |
| P5 全覆盖与产品验收 | 静态清单、精准测试、英文布局检查、实际 ClawChat 中英切换、性能对比 | 下节全部强制项通过；记录环境、版本和剩余排除项。只有技术测试不算完成 |
| P6 完整发布 | 用户明确授权后，构建一个完整候选版本、保留有限回滚点、部署、核验实际运行版本和用户流程 | 同一候选发布；源码/产物一致；目标 Liveware 验证通过；无新数据迁移、无未记录改动 |

停止条件：需更改 ClawChat 客户端、需跨到生成/卡片数据重构、需重做 UI、或无法确保切换不丢状态时，停止相关实现并说明原因取得授权。不要用静默降级换取“完成”。

## 7. 验收矩阵

### 7.1 语言来源与生命周期

- [ ] ClawChat 中文 + 系统/浏览器英文：固定系统文案仍中文。
- [ ] ClawChat 英文 + 系统/浏览器中文：固定系统文案仍英文。
- [ ] 有旧 ST `language`、旧 `cc_lang` 记录时，新宿主语言仍优先。
- [ ] 独立浏览器无宿主信号时正确兜底；不把此结果当成 ClawChat 验收。
- [ ] `en-US`/`en-GB` 等能找到酒馆助手 `en` 词典；中文代码映射符合冻结契约。
- [ ] 无效/不支持语言有确定回退，不使 UI 空白，不写用户配置。
- [ ] ClawChat 中→英→中；已经打开的页面按真实协议更新，行为有实测证据。
- [ ] 前后台恢复、关闭重开、刷新、页面返回后没有恢复旧语言。
- [ ] 重复/乱序通知与迟到词典不会产生混合语言或重复订阅。
- [ ] 非宿主窗口、卡片 iframe、非法 payload 不能改变语言；存储不可用时不崩溃。

### 7.2 系统文案完整性

- [ ] S01–S16 清单中每条纳入项有中英文词条、参数、来源文件、触发步骤和检查结果。
- [ ] 两语言 key/参数集合一致，缺词条与误显示内部 key 为零。
- [ ] 静态模板、运行时创建的按钮、弹窗默认属性、CSS 固定文字、title/aria/placeholder 均检查。
- [ ] 正常、空、加载、成功、失败、重试、取消、只读、禁用、降级等实际可达状态均覆盖。
- [ ] 进行源码扫描与 AST/模板提取；注释、日志、用户内容、协议字段的排除项逐条有原因，不以“中文字符数量为零”代替验收。
- [ ] 程序英语原文同样登记，不仅搜索中文，避免中文环境漏掉 ST 英文提示。
- [ ] 用明显不同的中英文及模拟长文案检查拼接、插值、单复数；保留品牌与用户数据的合理原文。

### 7.3 用户流程与不变性

- [ ] 打开 Tavern → 自动恢复当前设计规定的初始世界 → 连续切世界，语言一致。
- [ ] 空世界、直接创建、从卡库创建、文件导入、失败重试/恢复的系统提示一致。
- [ ] 发送 → 等待 → 流式思考 → 流式正文 → 完成；切语言不新增模型请求、不清空思考正文。
- [ ] 编辑/取消/保存并发送/重生成/智能回复/切换回复/停止均正常，调用次数与原语义一致。
- [ ] 已输入未发送、IME 组合输入、模型表单未保存、世界书编辑未保存时切换，值与光标不丢。
- [ ] 确认删除等弹窗切换后，确认仍确认、取消仍取消；不因重渲染执行操作。
- [ ] 角色卡库、模型未配置、Hermes 默认、自定义模型、删除配置、MVU 开关的双语状态覆盖。
- [ ] 至少用一个含脚本/MVU/自定义 iframe 的复杂卡夹具检验：按钮仍响应、iframe 不重建、变量键不变。
- [ ] 相同固定输入下，中英文 UI 的业务请求结构/模型提示词一致；只允许显示相关的语言参数差异，忽略请求 ID/时间等自然变化。
- [ ] 语言切换本身不写 chat、world、card、模型配置或 Story Profile 内容，不改变已有名称与档案。
- [ ] 桌面与窄屏英文不裁切主要操作，深浅色样式与现有产品一致；辅助标签和页面 `lang` 正确。

### 7.4 性能、构建与发布

- [ ] 首屏到世界可用的关键链路没有新增串行语言网络请求、远程翻译或模型调用。
- [ ] 构建输出报告中文/英文及插件词典的 raw/Brotli 增量、首次加载请求数；不以运行时缓存掩盖新增负担。
- [ ] 建议资源预算：新增首屏内联语言内容 Brotli ≤ 8 KiB，初始必需资源新增 Brotli ≤ 128 KiB；超出须解释和复审，不擅自删译文达标。
- [ ] 以同设备、同世界、同网络配置做配对前后测，分别记录冷/热启动、渲染与语言切换耗时。建议启动 P95 回退容忍为 `max(200ms, 基线的 5%)`；网络波动需分项解释，不能直接归咎翻译。
- [ ] 语言信号已到达且资源已就绪后，正常界面更新建议目标为桌面 ≤100ms、移动端 ≤200ms；作为待测目标，不宣称已达成。
- [ ] 扩展 locale 失败有本地化可恢复说明，不使主体无法进入；恢复后使用最新语言。
- [ ] 正规构建、import-map/别名、静态资源版本、Profile 快照校验通过，无孤立的手改产物。
- [ ] 已授权目标客户端的真实 ClawChat 切换流程验证；测试环境包含桌面/移动端实际交付范围。
- [ ] 已授权部署后核实进程版本、资源内容哈希、实际 Liveware 页面和中英流程，不只检查 HTTP 200。

验收中的 UI/浏览器/ClawChat 操作必须先取得授权。测试涉及创建、发送、删除时使用隔离夹具或明确的测试世界，不在用户真实世界里写测试内容。真实模型调用另需明确授权；可先用受控流式夹具验证 UI 与请求不变性。

## 8. 清理与交付纪律

1. 在替换功能确实被验证后，移除 Nora 模式里失效的硬编码显示分支与重复语言判断；保留外部仍使用的 ST Interface。
2. 不进行与双语化无关的“顺手清理”；不删除整个 ST i18n、上游资源或独立 Profile 词典。
3. 新译文、适配、构建与测试作为一套完整候选交付，不在远端逐块打补丁。
4. 不保留调试语言开关、重复译表、无消费者的旧文案和无限增长的缺词条日志。
5. 每阶段记录：修改文件、对应 S 编号、行为差异、验证范围、未完成项、是否偏离计划。
6. 正式提交/部署前总结行为变化并取得相应授权；本计划不是部署、修改 ClawChat 或重注册 Liveware 的授权。
7. 发布回滚只恢复本次受影响的应用源码/产物，保留世界、对话、角色卡、模型密钥和档案数据；不得回滚用户新产生的数据。
