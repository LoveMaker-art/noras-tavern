# 产品需求变更模板

用途：在改变产品行为前把结果、范围和验收讲清楚。依据：[产品设计的执行与变更控制](README.md#change-control)。本模板只组织任务记录，不新增产品规则。

先判断工作性质：改变用户行为、范围或支持承诺时使用下表；修正偏离既有规则的实现时，只在原任务／修复报告说明“问题与规则、必要改动、实际验证、未验范围”，不启动新一轮产品设计。文字和链接整理按实际规模记录。

将下表填写在现有任务／设计记录中；有记录可补充时不另外创建平行文档。填写模板不代表用户已确认，也不代表获得实施、推送或发布授权。

| 项目 | 必须说明的内容 |
| --- | --- |
| 问题与依据 | 谁在什么场景遇到什么结果；哪些是事实，哪些是假设；引用日志、规则或复现证据 |
| 用户目标 | 改完后用户能完成什么，用可观察结果描述 |
| 当前与目标流程 | 原来怎样操作，之后怎样操作；明确是否改变按钮、默认路径和支持范围 |
| 规则与需求 | 当前设计版本、总览／模块的具体条款及适用 PB／PR；属于实现偏离修正，还是要改变规则 |
| 范围 | 必须改变、必须保留、不做和延期项；明确数据、配置、现有入口及兼容范围 |
| 方案与取舍 | 首选方案、必要替代方案、收益和风险；新增机制为什么不能用已有能力完成 |
| 验收 | 对应用户流程、异常和恢复场景、目标环境、通过依据；说明哪些检查可复用及理由 |
| 实施与交付 | 必要改动、先后依赖、所需制品与分发范围；具体发布方式遵守 PB-09 |
| 决策与授权 | 记录用户已确认、取消、待定内容及时间；实施、合并、推送、暂存、正式发布分别核对 |
| 实际结果 | 源码／制品身份、实际验证与证据、未验项、直接阻断和范围外发现分别记录 |

确认产品规则后，在[总览与受影响模块](README.md#authority)的唯一归属处维护结论、同步设计版本与验收条件，本记录保留问题、理由和确认来源。交付前对照实际差异，说明是否符合确认结果；实施和验收继续跟踪，不将设计确认或归档当作已发布。后续改设计另记并关联原结论。
