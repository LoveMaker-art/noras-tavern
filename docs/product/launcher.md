## 一 目标、范围与交接

目标是让普通用户通过桌面入口完成安装、首次设置、启停和维护，并准确理解结果。保留现有控件和操作路径；本次补齐规格，不授权重新布局、隐藏入口、扩大权限或增加任务系统。

| 本模块负责 | 交给其他模块的结果 |
| --- | --- |
| 程序包入口、安装目录、首次设置、模型／配对表单、启动检查 | 诺拉连接与模型执行见[诺拉设计](nora.md#connection)，故事业务见[酒馆设计](tavern.md) |
| 当前实例的服务控制、打开酒馆、状态和日志呈现 | 服务归属与实际健康由生命周期管理验证，不用窗口或端口存在代替 |
| 核心／自身更新入口、APP 替换、恢复与卸载入口 | 核心使用[同一独立更新器](README.md#shared-update)，维护共同遵守[数据与备份规则](README.md#data-and-models) |
| 安装信息、社区与作者、人物反馈、诊断选择 | 外部客户端和供应商账号各自管理；启动器不代替用户授权或服务商结果 |

桌面交付面向 Windows x64、Mac Apple 芯片和 Mac Intel。具体系统版本支持、原生兼容及签名状态按发行证据说明；不能因系统分支有代码便宣布提供 Linux 桌面安装包。云端和源码部署仍可使用适用核心业务与更新，不依赖桌面 APP。

## 二 页面、状态与入口全景（L-01）

正式桌面使用同一窗口中的内容区域切换；状态由实际安装、配置、连接、任务和恢复结果决定。页面存在不代表对应业务已成功。

| 页面／区域 | 进入条件与呈现 | 离开方式／边界 |
| --- | --- | --- |
| 初始化与连接失败 | 启动后检查安装；桌面桥接缺失则明确“启动器连接失败” | 成功后按事实路由；连接失败提示关闭重开，不展示模拟安装成功 |
| 欢迎／继续安装 | 未安装或部分安装，展示目录及安装动作 | 安装进入任务；已运行服务先按要求停止，保留已完成部分 |
| 首次设置步骤 | 诺拉、酒馆、模型、ClawChat、启动检查五个里程碑 | 按实际结果推进，完成首次设置后收起步骤条 |
| 日常页 | 首次设置完成且无优先维护／恢复阻断 | 服务控制、打开酒馆、模型设置、更多菜单和版本提示 |
| 模型表单／同步待完成 | 首次配置、日常修改或已保存但同步未结束 | 验证保存、查询、继续同步或按允许条件返回 |
| ClawChat 连接页 | 首次配对、查看连接、重新配对或失败后重新输入 | 提交新码、连接检查及允许的返回 |
| 更新结果页 | 手动检查或点击版本提示 | 安装适用更新、重查、版本说明、日志及返回 |
| 执行任务／已有任务监视 | 当前请求或其他入口已接管的维护任务 | 查看进度／日志；仅安全阶段取消，不创建竞争任务 |
| 错误／恢复页 | 当前失败、状态未知、未完成核心或 APP 恢复、部分完成 | 只展示后台允许的检查、重试、恢复、配置、日志等动作 |
| 安装信息／社区与作者 | 从更多进入的辅助页 | 只读信息、目录或外链操作及返回 |
| 日志面板 | 菜单、表单、任务、更新或恢复页请求日志 | 返回原操作上下文、复制、滚动查看；读取不等于重试业务 |
| 更多弹层 | 可显示管理入口时点击“更多” | 选项导航、关闭按钮、遮罩、Escape及焦点恢复 |
| 卸载进度与系统对话框 | 正式安装包进入卸载 | 选择、确认、取消、错误或系统卸载交接；详见卸载章 |

页面路由有优先关系：未知状态先处理查询；正在执行的任务先监视；保留数据卸载未完成、APP／核心恢复和未处理失败先进入对应处理，再判断普通安装、配置和日常页。不得用落回欢迎页或空白数据掩盖原现场。

| 入口／控件 | 行为及返回 | 不可用或异常 |
| --- | --- | --- |
| 右侧正文、说明与步骤条 | 展示当前阶段、结果与下一步；步骤条只表达进度 | 不将点选步骤条当作跳过验证的入口 |

## 四 安装包与启动程序入口（L-03）

用户下载与自身系统、架构对应的正式安装包。Windows 使用 setup 向导，可选择启动器应用安装位置；Mac 使用 DMG 中的 APP，按系统方式安装后启动。桌面 APP 的放置位置与诺拉酒馆程序／数据位置是两个概念。

现状：Windows 构建配置还允许 portable／ZIP 产物，但菜单卸载要求存在唯一系统卸载程序，缺失时提示使用 setup 安装版。不能把有压缩包等同于完整受支持的安装与卸载体验。Mac 从挂载卷直接运行时，卸载会要求将 APP 移出挂载位置。

启动时目录和本机记录初始化失败，可能在主窗口出现前就退出。此时使用系统错误框说明启动器未能打开、实际原因和已有日志位置；保留原数据及记录。详细根因未确认时如实标明，不归因为模型或服务商。

重复启动现状：同一启动器实例通过单实例机制唤醒已有窗口，已有窗口最小化时恢复并聚焦；不因此再次安装或重复启动服务。窗口关闭后 Mac 的再次激活行为见[生命周期](#close-and-disconnect)。

## 五 安装位置与已有安装识别（L-04）

| 用户过程 | 当前保留的行为与保护 |
| --- | --- |
| 查看默认位置 | 欢迎页显示真实实例数据目录；默认位置按平台及通道确定，不要求用户理解内部子目录 |
| 更改位置 | 仅在没有已开始安装、受管程序、保留数据记录及竞争任务等条件下提供；打开系统文件夹选择器 |
| 取消选择 | 保持原目录和当前流程，不当作安装错误 |
| 确认选择 | 使用专属目录，校验可写、目录类型、实例归属和正式／测试隔离；成功后重新读取位置 |
| 目标已有文件／属于其他实例 | 不覆盖未知文件，不把启动器 APP 自身目录当数据目录；拒绝后保留原位置并显示原因 |
| 已经开始安装或有历史数据 | 不将“更改位置”变成隐式迁移功能；按已有安装、维护或恢复流程处理 |
| 自定义磁盘暂不可用／记录无法核验 | 说明需连接磁盘或核对记录；不静默回退默认位置生成另一套空数据 |
| 保留数据卸载后重装 | 识别原内容及归属，继续原数据；不能新建数据冒充恢复 |

选择的父目录可能自动附加专属子目录；最终页面展示实际结果。默认目录、端口和路径拼接是实现参数，具体值及平台差异见覆盖审计，不成为跨平台统一承诺。

## 六 首次安装与设置流程（L-05／PB-03）

默认路径：**安装诺拉与酒馆 → 配置并验证模型 → ClawChat 配对 → 启动检查 → 日常使用。**

| 阶段 | 用户操作 | 可以进入下一阶段的依据 | 失败后的去向 |
| --- | --- | --- | --- |
| 安装 | 确认位置并开始安装 | 本实例程序、依赖和安装结果通过适用检查 | 留在安装／恢复流程，说明修改范围；保留已存在的用户内容 |
| 模型 | 选择服务、模型并提交配置 | 配置保存及规定的模型验证成功 | 回到本次模型配置，说明保存和调用各自的结果；不重复安装 |
| 配对 | 获取连接码并显式提交 | 配对执行返回有效成功结果 | 显示原失败原因；允许按重试规则重新提交，包括新连接码 |
| 启动检查 | 按现有流程启动并等待检查 | 各项必需检查有实际结果 | 区分本地服务、模型及外部连接问题，进入对应处理路径 |
| 日常使用 | 打开酒馆、与诺拉对话 | 本地游玩与诺拉连接分别具有可用证据 | 受影响部分按[共同状态规则](README.md#state-and-retry)处理 |

首次必须配置诺拉并完成配对。ClawChat 是当前适配平台，不承诺任意 IM 都可直接接入；其不可用会影响首次设置完成。程序已安装、模型已配置、已经配对和当前在线分别判断，后一个失败不自动抹去前一个事实。

安装阶段包含适用的资源查询与校验、运行环境准备、受管内容与酒馆部署；界面按后台里程碑呈现，不靠固定延时模拟完成。现有安装向导保留已确认完成阶段，失败后依据任务提供继续、恢复或重试。

现状：为了恢复首次设置或进入日常，控制器可在已安装且系统就绪时尝试一次启动酒馆，这不代表首次模型及配对要求已经完成；该自动启动的长期策略见[差异登记](#differences)。安装需要的资源可用性与完全离线首装能力必须分别证明，不由“安装包包含底包”推断任意环境都能离线完成。

<a id="daily-use"></a>
## 七 日常首页、服务控制与打开入口（L-06／L-07／PB-04）

下次使用沿用原安装、世界和配置，无需重走首装。用户打开已有世界或创建新世界，进行故事互动并保存，下次仍能继续原世界和会话。基础游玩与增强能力的可用性按[共同状态规则](README.md#state-and-retry)分别表达。

| 日常动作 | 确定的产品行为 |
| --- | --- |
| 查询状态 | 读取安装、配置、配对及当前服务事实；查询不隐式重新安装、迁移用户数据或启动更新 |
| 启动／停止 | 保留现有独立控制；只作用于当前确认的实例，停止结果须能核验 |
| 修改模型／重新配对 | 进入现有表单，处理相应配置；不重置世界、聊天或无关配置 |
| 日常关闭启动器窗口 | 保留现有关闭行为，不新增两平台统一关窗停服要求；实际触发停服时核验相应结果 |
| 停服失败或无法确认 | 保留可见说明及适用的检查／重试入口，不以窗口消失证明停服 |

用户已取消“两平台日常关窗统一停服”的要求，不再作为待实施项。取消该要求不授权改变现有关闭行为，也不代表已确认新的统一后台常驻或退出策略。维护任务进行中的关闭规则见[退出与断开](#close-and-disconnect)；服务器及无桌面部署按对应部署方式管理进程。

| 控件／区域 | 用户结果与执行条件 | 失败／后续 |
| --- | --- | --- |
| 诺拉服务行 | 显示网关运行状态，提供启动／停止与重启 | 停止状态不提供有效重启；连接是否在线另行表达，进程运行不等于 ClawChat 已连通 |
| 酒馆服务行 | 显示酒馆运行状态，提供启动／停止与重启 | 服务归属、启动与停止均核验当前实例，不能因端口占用就结束其他程序 |
| 单服务启动、停止、重启 | 只改变所选服务；执行中显示启动中／停止中并限制重复提交 | 后台完成后重新查询所选服务，不把按钮动画结束当作成功 |
| 更多中的“停止诺拉与酒馆” | 停止当前实例两项服务，保留故事与配置 | 无服务运行时不可用；任一项未确认停止就不能报告全部停止 |
| “打开酒馆” | 已运行时打开当前实例地址；未运行时先只启动酒馆，再请求系统浏览器打开 | 不隐式同时启动诺拉；服务就绪与浏览器请求成功分别判断 |
| “去 ClawChat 找我” | 已配对时提供；网关与连接可用后请求打开客户端 | 诺拉停止时引导先启动；连接失败引导检查，无法打开客户端时提示手动打开 |
| 首次完成引导 | 首次设置完成且两项服务与连接就绪后提供联系人问候提示 | 不反复要求用户走首次引导；当前窗口会话中的展示标记不代替配对事实 |
| 版本提示 | 在日常页展示适用更新或检查未完成提示，进入更新详情 | 后台查询不自动安装，不打断编辑和菜单上下文 |

状态文案包含运行中、已停止、启动中、停止中、状态未知。已配置但当前停止与安装损坏分别处理；外部连接失败保持已证实可用的本地酒馆能力。

## 八 模型配置、列表、验证与同步（L-08／L-09）

### 表单与字段

| 字段／控件 | 当前交互要求 |
| --- | --- |
| 模型服务 | 从桌面返回的支持目录选择；现有目录包括 OpenRouter、DeepSeek、Anthropic、OpenAI、Google Gemini 和自定义模型，实际选项以固定交付目录为准 |
| “获取 API Key” | 仅有已配置服务商入口时显示，交由系统打开；自定义服务不伪造申请入口 |
| API Key 与显示／隐藏按钮 | 默认遮蔽，用户可临时显示；不回填本机已保存密钥，切换服务清空输入，成功后清空本次输入 |
| 自定义接口地址 | 仅自定义服务显示，填写基础 HTTP／HTTPS 地址；校验格式，禁止账号信息、查询参数或片段，使用现有兼容协议规范化 |
| 认证方式 | 自定义服务可显式选择 API Key 或“无需认证（本地服务）”；免认证时隐藏 Key 输入并提示先启动服务；预置云服务仍要求 Key |
| 模型名称 | 可手动输入或从候选列表选取；列表只说明可选择名称，不证明模型一定可调用 |
| “获取模型列表” | 提交当前服务、地址及认证条件；执行中锁定表单，结果更新候选项 |
| “验证并继续／验证并保存” | 校验必要字段，执行真实模型验证后保存并复核；首次和日常修改使用不同按钮文案 |
| 表单日志与状态重查 | 错误可看本次模型操作日志；保存已发生但结果不完整时先查询，避免重复保存 |
| 返回按钮 | 首次配置按流程推进；日常编辑按合法状态回日常或操作页，恢复入口焦点 |

切换服务时清空旧候选项，按同一服务的已有非密钥配置或默认值初始化。默认模型名属于交付参数，不因文档列出候选就保证供应商支持或返回速度。

### 请求与保存结果

1. 空 Key、空模型、自定义空地址、不支持的服务、超长或非法控制字符等先反馈输入问题；具体长度限制由交付校验器维护。免认证仅允许自定义服务选择，不绕过预置服务的 Key 要求。
2. 查询列表失败保留可编辑表单。服务不提供列表时，说明可按服务商公布名称手工填写；鉴权、超时、网络和响应格式错误分别归因，不默认是模型名称错误。
3. 验证使用用户选择的真实服务并要求有效响应；HTTP 成功、模型在列表中和保存成功均不能代替调用验证。
4. 验证后保存模型，并执行适用的酒馆初始化／同步。诺拉、酒馆、MVU 分用途配置的共同保护规则保持。
5. 首次配置已保存但酒馆同步未完，提供“继续同步”和“更换模型配置”；继续同步不要求再次输入原 Key。
6. 保存已发生但末尾复核失败，显示已保存事实、日志和重查入口，限制不确定状态下重复提交。
7. 日常更改成功，诺拉运行时提示重启诺拉生效并提供“重启诺拉”；停止时提示下次启动生效，不暗中重启其他服务。

免认证选项的文案定位本地服务，当前地址格式校验并未将其限制为回环地址；这不构成对任意公网服务安全性或免认证可用性的承诺。精确等待时限与供应商默认值属技术参数，超时只证明本次等待未完成。

沿用[共同状态与重试规则](README.md#state-and-retry)。启动和后台刷新读取当前安装、系统就绪、模型、配对、服务、维护任务及恢复事实。当前刷新周期属于实现参数，不能把刷新次数或缓存当作健康证明。

<a id="desktop-update"></a>
## 十二 版本检查、下载与桌面更新（L-13／PB-06）

### 查询、提示与操作

日常设置完成后可进行一次后台版本检查，用户也可从更多、版本提示或适用的未完成配置入口手动检查。后台只查询，不代替安装授权。

现状另有新包续接路径：已有诺拉与酒馆、且新 APP 的封装目标高于当前核心时，控制器可自动尝试一次升级该目标；失败按原任务处理，未开始或可继续时显示“继续完成版本升级／继续更新”。这是安装或替换新包后的目标续接，不等于普通后台查询自动安装；其来源、授权与恢复仍须对应交付计划，不能扩大为任意新版静默升级。

| 检查结果 | 呈现与下一步 |
| --- | --- |
| 有可用更新 | 分别显示酒馆与启动器当前／发布版本，符合兼容与恢复条件时提供安装 |
| 当前已是最新 | 明确所查正式／Beta 通道，提供返回及适用版本说明 |
| 本机版本高于发布／无法确认 | 分别表达，不自动降级，不将未知当最新 |
| 检查失败、限流或缓存结果 | 显示失败或上次检查时间，按预算与冷却提供重查；缓存不冒充刚确认的最新版本 |
| 核心可用、启动器检查慢或失败 | 核心更新能力与启动器检查结果分别说明，不能让可选 APP 查询吞掉全部核心更新机会 |
| 上次任务未解决 | 提供原任务检查／恢复；仅在未修改且目标确已变化等合法条件下允许检查新版，不清空历史重试依据 |
| 查看版本说明／日志 | 请求系统打开对应发行页或查看本次检查日志，保留失败上下文及返回 |

资源按受信来源、固定版本、平台、大小和完整摘要校验。国内查询与完整下载、备用源、慢源切换和适用续传必须有依据；切源仍核验相同内容，不能把校验错误当作普通网络失败掩盖。缓存满足身份时复用，目标或身份不一致则拒绝复用。具体供应商和远端当前状态由分发配置与发行证据维护。

### 一次发起与结果

用户保留原来的检查和安装更新按钮。两项都有适用新版时，一次点击提交本次已确认的目标，依次完成核心更新与 APP 替换；需要重开 APP 时自动交接并续接结果，不要求用户再次查找、点击安装另一项。只有一项有变化时只执行该项。诺拉的桌面更新请求复用该入口，并按同一固定计划和实际组件结果回报；没有APP的部署仍只更新核心。

诺拉请求绑定本实例；仅检查版本不打开启动器、不提交或覆盖安装任务，明确授权更新后才允许按需唤起已经核验的APP，不另建安装器或常驻服务。重复提交／重连读取同一任务，不覆盖另一任务；APP重开后继续同一计划，只有核心或APP变化时只执行适用部分。旧APP不支持统一请求、缺失程序及记录损坏分别说明，按[旧版接入边界](nora.md#autonomous-update)处理，不能将已受理或核心单项成功报告为全部成功。外部核心更新后，单独APP更新及失败重试先保持APP本体身份校验，再安全刷新当前核心描述符；更新器、清单或实例不匹配仍拒绝，不通过整体重新采信APP字节绕过校验。

执行前核验资源、实际安装及各阶段需要的兼容组合，固定本次两项目标和恢复依据。先核心还是先 APP 由适用协议和可恢复组合决定，不作为永久产品规则；不能只因某一顺序代码较短就跳过兼容校验。调用方退出后的续跑、维护互斥与原退出保护继续有效，受控 APP 重启不等于新增日常关窗放行。

| 两项执行结果 | 用户结果与后续 |
| --- | --- |
| 本次需要更新的项目均成功并通过验证 | 报告全部完成，显示实际核心及 APP 版本；任务结束后可正常使用 |
| 一项成功，另一项失败并已恢复，保留下来的程序组合有明确兼容依据且实际验证通过 | 保留成功部分，报告“部分完成”，说明失败项、实际版本和重试动作；不把部分完成报告为全部成功 |
| 失败后形成的组合不兼容或兼容性未知 | 不按兼容部分完成放行；使用已核验的恢复路径回到可用程序组合，保留用户数据；恢复未确认时明确受影响动作及原因 |
| 写者、替换效果或恢复仍未确认 | 保留任务和证据，查询同一结果或执行对应恢复；不凭单项成功解除尚存的危险修改 |

兼容部分完成结束后，重试只补失败项，并重新核验保留项和固定目标仍适用；不重复替换已经成功且仍有效的核心或 APP。兼容声明、当前文件身份、实际运行和恢复结束分别举证，版本号较新或进程能启动本身不足以证明组合兼容。两项协调复用既有任务与恢复事实，不另建一套相互矛盾的权威记录。

启动器程序、诺拉／酒馆内容和基础运行环境分别识别版本，按实际变化分别交付，内容更新不顺带强制重装全部环境。具体进程语言、交付目录和凭据格式由实现方案管理。

历史安装以保留数据迁至当前支持版本为目标；来源版本、入口与数据形态分别验收。旧二进制已经损坏的更新入口，不会因新版源码修改自动改变；救援工具、保留数据覆盖更换启动器和普通在线更新分别记录适用范围与结果，不凭几个旧版本推断全部兼容。

本地候选测试包的在线更新限制、Beta 与正式目录隔离属于交付边界，详见[平台与集成](#integration)；它们不证明正式用户的在线更新会失败。

## 十三 错误、恢复与重试入口（L-14）

错误页说明：原始失败、程序及数据是否修改、当前可用动作，以及日志入口。只按后台允许动作展示配置模型、重新输入配对码、继续同步、继续／重试、重新检查、恢复旧版本、启动已恢复旧版、下载完整新版启动器、查看日志及返回等操作。

| 状态 | 用户结果与限制 |
| --- | --- |
| 原程序未改动 | 说明未替换，核验可用后可继续使用或合法重试；历史失败不永久阻断 |
| 核心更新中断且备份可恢复 | 展示可恢复版本及恢复按钮，保持窗口等待；恢复后核验运行与任务结束 |
| APP 自更新中断 | 展示启动器恢复结果与“恢复旧启动器”；涉及自身替换时可能停止服务并重开 |
| 核心与 APP 都有待处理恢复 | 先处理阻断后续的 APP 交接，再按核验结果开放核心恢复，不并行竞争 |
| 文件已恢复但启动未通过 | 明确文件已恢复、服务未就绪，按条件提供“启动旧版本”；不虚报全部恢复完成 |
| 旧记录缺少运行状态 | 明确数据来自原备份，较新内容另存并未自动合并；需要时手动启动，不宣称所有新内容已合并 |
| 无法确认恢复依据 | 保留数据、日志与备份，展示具体原因及检查；不靠删除任务目录解除 |
| 版本过旧或执行协议不兼容 | 按指导打开正式下载页；失败说明可从项目地址查找，不能不经验证重放原失败安装 |
| 双更新部分完成 | 显示两项实际版本与失败项，按兼容规则保留成功部分或恢复 |
| 保留数据卸载中断 | 保留“更多→卸载”和日志等适用入口，阻止竞争安装，说明仍待完成 |

“恢复详情”可展开最初失败、APP／核心恢复检查、版本、日志和备份位置。查询恢复状态不能覆盖用户展开状态或丢失首因。允许恢复 APP 的独立证据与核心运行状态分别判断，不能把未知一概当作全部无恢复入口。

## 十七 人物互动与品牌入口（L-18）

| --- | --- |
| 正式版本基础统计 | 按既有规则发送启动器负责的操作阶段、结果及限定技术信息；不由详细日志开关控制 |
| “自动上报故障日志” | 控制详细诊断及相应日志投递；新诊断选择默认开启，保留已有明确关闭选择 |
| 读取与修改设置 | 可用时显示已保存值；保存期间禁用开关并显示状态，失败恢复原值并明确未保存，不覆盖隐私说明 |
| 关闭详细诊断 | 按协议停止相应详情投递、处理待报详情；基础统计与操作任务继续，已接收数据不能由本机开关撤回 |
| 重新开启 | 对之后适用操作生效，不补采关闭期间或未授权操作的私人证据 |
| 网络失败／接收端不可达 | 本地记录待报／缺失状态，按有界队列和退避处理；不阻断安装或把待报当送达 |
| 窗口前启动失败、崩溃或卸载失败 | 采用适用的生命周期日志和脱敏投递；权限、磁盘、强杀等条件可能导致证据缺失，不能保证每次送达 |
| 隐私边界 | 不上传聊天／世界正文、模型回复、Key、配对码、配置全文或原始崩溃内存；本地模型调用向所选服务发送的内容与故障上报分别说明 |

界面读取上报设置失败时说明失败，不能默认显示保存成功；不可用测试／开发模式不伪造生产采集状态。当前标签能否充分表达“仍有基础统计”的问题见差异登记，不在本轮擅改文案或采集策略。

## 十九 界面连贯性、键盘与可达性（L-20）

| 范围 | 必须保留的设计约束与验收 |
| --- | --- |
| 布局锚点 | 同类安装、模型、配对、更新、错误和恢复流程沿用共同步骤／标题位置；辅助页和日常页保留各自已确认位置，不因状态变化突然跳动 |
| 表单几何 | 模型名称、认证方式、标签、输入框与操作行按已有对齐规则；字段显隐不遮挡提交和反馈 |
| 长内容 | 正文、辅助说明、表单、恢复详情、菜单与日志在指定区域内滚动；操作可到达，不用裁切隐藏完整控件 |
| 更多弹层 | 点击打开聚焦关闭按钮；关闭按钮、遮罩及 Escape 关闭后回更多入口；Tab／Shift+Tab 在可用菜单按钮间循环 |
| 返回和焦点 | 返回或日志关闭后恢复合理入口焦点，保留普通键盘操作及可见焦点；正文区域点击不产生误导性的整框粉色选中效果 |

| 动态效果 | 遵守减少动态效果偏好；后台状态刷新不反复触发跳动、滚动和整段动画 |
| 支持环境 | 对实际窗口、系统缩放、长路径／错误和支持平台检查可达性；源码 CSS 或 DOM 存在不能代替真实窗口视觉验收 |

现有主窗口为固定内容尺寸，具体参数见覆盖审计；小屏／高缩放下是否需改变窗口策略属于待确认设计，不能只凭网页响应式样式宣称全部显示器可用。

## 二十 窗口、退出与平台生命周期（L-21／PB-04／PB-06）

| 场景 | 已确认行为 |
| --- | --- |
| 日常空闲关窗 | 按 PB-04 保留现有关闭行为，不新增统一停服动作 |
| 安装、模型保存、目录选择、更新或恢复期间请求退出 | 沿用现有等待保护，说明任务尚未结束；只提供当前阶段原本支持的取消动作，不新增“更新中主动关窗”功能 |
| 更新已接管，诺拉停止、调用方异常退出或连接中断 | 独立任务继续，随后可读同一终态；这不等于日常关窗按钮主动放行 |
| 维护结束后正常退出／重新打开 | 先确认任务不再占用，再按日常退出／查询规则操作 |

| 平台／入口 | 当前源码行为及产品边界 |
| --- | --- |
| Windows 关闭主窗口 | 走退出应用流程；等待确认本实例诺拉与酒馆停止后退出，停止失败保留可用窗口和错误提示 |
| Mac 日常关闭窗口 | 无本窗口维护请求时可只关窗口，进程和后台服务可能继续；Dock 激活可重新创建窗口，不等于退出应用 |
| Mac 退出应用／系统请求退出 | 走完整退出流程，检查任务、停止受管服务并核验；失败不伪装已退出 |
| 正在安装、配置、选择位置、更新或恢复 | 沿用维护等待保护，按阶段提供原本支持的取消；Mac 个别 close 分支保护范围另列待核验 |
| 自更新／恢复主动重启 APP | 由已准备的交接控制退出与重开，不受普通用户关窗行为替代，不以重开本身宣称更新完成 |
| 第二次打开／再次激活 | 复用或恢复窗口，不重复接管任务或启动另一套实例 |

取消两端统一停服要求不授权重新设计托盘、开机自启、后台常驻、自动退出或更新中主动关窗。进程归属不明时不强杀其他应用；无 Python 的空安装退出与已安装但运行环境缺失分别处理。

<a id="uninstall"></a>
## 二十一 卸载、取消与保留数据重装（L-22／PB-08）

用户进入卸载后明确选择保留数据、彻底卸载或取消。聊天辅助备份与程序恢复准备的区别见[共同备份规则](README.md#data-and-models)。

| 用户选择 | 删除与保留范围 | 执行前提与失败处理 |
| --- | --- | --- |
| 保留数据卸载 | 删除本实例程序及适用缓存，保留聊天、角色、世界、配置、凭据与应保留的备份 | 核验目录和进程；真实未恢复修改先恢复。失败保留现场，说明具体未确认效果 |
| 彻底卸载 | 删除明确确认目录中的本实例程序、数据与备份 | 明确展示不可恢复范围，取得对应再次确认；核验目录、服务与维护进程停止。不要求先把历史更新恢复成能运行的旧程序 |
| 取消 | 不开始卸载删除 | 回到原使用流程 |

保留数据重装应识别原内容并按其归属继续使用，不能悄悄新建一套数据来冒充恢复成功。操作不影响其他 Hermes／酒馆、IM 客户端或云端账户；删除本地 Key 文件不等于撤销服务商 Key。卸载细节沿用[卸载说明](../launcher-uninstall.md)。

Windows 菜单入口启动系统卸载程序，随后应用退出；系统卸载也会通过同一清理协议检查范围。用户取消系统卸载后可能需要重新打开启动器，不能承诺原窗口自动返回。Mac 使用应用内确认并交接独立清理，挂载卷运行会先提示正确安装 APP。开发模式不执行真实删除。

清理失败保留程序及现场，给出实际错误／结果日志。Windows setup 的覆盖更新调用旧卸载器时采用专用升级分支，不因此提示清空数据或执行普通卸载清理。保留数据卸载中断的继续、重装识别、未知／外部目录及后台进程保护必须按对应场景验收。

## 二十二 非页面集成与交付隔离

| 能力 | 范围与约束 |
| --- | --- |
| 独立更新器、技能与历史本地交接 | 独立核心更新保留无APP部署路径；桌面统一请求按[共同更新规则](README.md#shared-update)核验本实例APP，检查不唤起、授权更新才按需唤起。过期、未授权或已接管请求不盲目回放 |
| 正式、Beta、本地候选、界面模拟 | 标题和目录按模式区分，候选使用独立数据与端口；开发 HTML 模拟完成不证明真实业务可用 |
| 本地候选在线更新 | 普通候选包明确限制在线升级，按测试包／Beta 方案验收；不将此限制套用到正式包 |
| 上报隔离 | 普通开发／Beta／候选与经显式授权的接收端测试构建分别处理，不能静默使用生产采集 |
| 外部链接 | 普通网页限定允许的 HTTPS 或回环 HTTP 等既有规则；ClawChat 客户端使用固定协议入口，系统打开失败要区分。主窗口禁止跳到任意外站 |
| 后台辅助进程与崩溃记录 | 由启动器管理范围内产生的生命周期证据补报，后台错误不替代主任务首因和真实终态 |
| 已暴露但无普通 UI 的桥接能力 | 配置文件打开、底层修复或任务快照等不等于现有产品新增按钮；只按调用方和既有权限使用，详见覆盖审计 |

| 编号与用户目标 | 必须证明的结果 | 规则追溯 |

| <a id="pr-02"></a>**PR-02 日常进入**：下次使用无需重新安装或创建故事 | 原配置、世界和会话能继续使用；启动／停止只影响本实例 | PB-04／PB-05 |

| <a id="pr-13"></a>**PR-13 备份与卸载**：清楚保留什么、删除什么，按选择执行 | 聊天辅助备份与程序恢复准备分开；保留数据卸载／重装继续原数据，失败保留原内容和必要恢复依据，彻底卸载按确认范围操作 | PB-05／PB-08 |

## 二十四 当前实现差异、待确认与证据入口

| 编号 | 事实／问题 | 当前处理 |
| --- | --- | --- |
| D-01 启动时自动启动酒馆 | 控制器在已安装且系统就绪时可自动尝试一次启动酒馆，早于普通日常操作 | 记录为现状；是否将其定义为长期默认策略尚无单独确认，不在本轮改变或扩展为自动启动诺拉 |
| D-02 窗口适配边界 | 固定尺寸与 CSS 响应式同时存在，不能据 CSS 推断极小工作区／高缩放原生可用性 | 当前尺寸作为实现参数记录；完整支持范围需原生视觉证据，改变窗口策略先确认 |
| D-03 本机启动器版本展示 | 安装信息当前从版本查询结果取启动器版本，查询尚未返回时可能显示待确认 | 不把网络结果当本机版本的唯一产品依据；记录实现限制，本轮不修改版本读取代码 |
| D-04 Mac 关闭保护分支 | close 处理直接检查活动请求／模型忙；选择目录或独立后台任务的保护是否与完整退出一致，尚未原生复现 | 已确认维护等待规则保持，源码疑点单列，不能宣称已验证所有 Mac 关闭场景 |
| D-05 诊断开关说明 | 当前开关名称“自动上报故障日志”，实际详细诊断与基础统计分开 | 设计正文明确真实作用；是否调整面向用户的说明需单独确认，不擅改采集或授权策略 |
| D-06 普通外链失败反馈 | 项目、服务商和社区的普通链接经窗口处理交系统打开，该路径目前吞掉打开异常；显式桥接按钮有单独反馈 | 两种入口均登记；用户可见失败效果尚未原生验证，不能把专用按钮的错误处理外推到全部链接，本轮不修代码 |

这些条目覆盖尚需确认／核验的具体边界，不代表新功能授权，也不将全部认定为已证实产品 Bug。用户审阅后，确认的选择在其唯一规则处更新；实现偏离则进入独立修复任务。
