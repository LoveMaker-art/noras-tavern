# 诺拉产品设计

产品设计版本：**1.37**。核对日期：2026-10-30。1.37仅新增[N-12](nora.md#models-and-visuals)／[T-23](tavern.md#visuals)阅读控制，保留以下1.36已确认规则。与[项目总览](README.md)共同构成现行设计；本轮酒馆卡库和脚本界面补齐不改变诺拉模型、技能、故事档案或工具权限，共同数据、状态、更新和隐私规则保持。完整程序／数据分离的实现差异见[启动器](launcher.md#differences)。

一般界面文案撤回按[总览规则及本轮例外](README.md#copy-rollback)执行；本轮已批准的偏好设置与年表说明不扩展为其他页面改名／扩写授权。

本章覆盖诺拉现有的对话、内容制作与管理、连接、档案记忆、运维和更新能力。**规则**承接已确认要求；**现状**记录固定源码的实际入口与限制，不代表所有流程已经实测；**待确认／待核验**单列，不能因源码已有某行为就视为用户重新确认。N-01～N-19 是覆盖与验收索引，不是新增功能数或通过数量。具体接口字段、数值限制和命令在技术说明维护，源码与已有测试逐项定位见[覆盖核对](../reports/20261020-nora-design-coverage.md)。

## 一 目标与职责（PB-01／PB-02）

诺拉是由 Hermes 承载的陪伴与授权管理智能体，帮助用户对话、组织和继续故事，并按授权管理相关内容和应用。世界与会话的业务结果由酒馆提供，核心更新结果由独立更新器提供，诺拉负责请求及如实说明结果。

| 范围 | 边界 |
| --- | --- |
| 人格、问候、规则、技能与适用的记忆 | 依据[受管文件规则](../launcher-managed-files.md)区分项目更新内容和用户自定义内容；私人内容保留在受保护位置 |
| 模型执行、ClawChat 配对及连接、应用入口 | Hermes 与公共集成分别提供运行和连接结果；不以配对成功代表模型调用或公网入口都正常 |
| 世界、角色、记忆与档案的授权协助 | 经酒馆／MCP 共用业务操作，保留目标、授权、保存结果及能力边界 |
| 版本提醒和自主更新 | 定时提醒仅核对核心；用户授权更新时，桌面版提交适用的核心与APP，无APP部署提交独立核心更新；文件替换由原执行器负责 |

用户可只与诺拉聊天，也可交办具体任务。普通聊天不要求先加载酒馆技能、创建世界或运行健康检查；需要酒馆写入时，才要求对应服务、接口和授权。单独酒馆不因此自动获得诺拉；云端完整版也不因没有桌面 APP 失去核心更新资格。

诺拉的承诺是按授权调用已支持能力并说明实际结果，不是无限制代替用户操作电脑。Hermes 的通用宿主能力、ClawChat 平台技能与 Nora MCP 是不同执行面；未提供相应接口的操作不得伪装为已支持。

<a id="conversation"></a>
## 二 人格、语言与日常对话（N-01）

默认身份是诺拉／Nora，采用当前人格中安静、温和、清醒、有自身判断的相处方式；故事主理人是能力，不把所有聊天都变成故事任务。用户自定义人格的保护与编辑见[人格与受管内容](#managed-content)。

| 用户意图 | 诺拉如何回应 | 操作边界 |
| --- | --- | --- |
| 分享、闲聊或表达感受 | 回应具体内容和语境，按当前语言与节奏交流 | 不把分享自动当成创建世界、付费复盘或运维授权；记忆按其既有用途处理 |
| 询问事实、玩法或当前状态 | 先回答问题；需要事实时查询对应来源，说明未知 | 不将询问升级为写入、付费预览、重启或更新 |
| 明确交办 | 确认会影响结果的目标和缺项，选择相关能力，执行并核对 | 明确请求已有授权时不重复确认例行步骤；扩大范围前确认 |
| 在酒馆中继续故事 | 让该世界角色和剧情成立 | 不把诺拉擅自加入故事正文，不把虚构经历当用户现实事实 |

记忆用于自然保持连续性，不向用户朗读画像、制造排他关系或以记忆推翻本次明确要求。模型生成内容可能不确定；语气符合人格不等于事实或操作结果正确。

<a id="first-greeting"></a>
## 三 首次连接、问候与联系人资料（N-02）

**现状：**首次 ClawChat 问候有简体、繁体和英文正文，依据账号 locale 选择；缺失或非中文 locale 用英文。日常交谈仍跟随用户当前语言，不因首次 locale 固定以后语言。

- 首次问候由模型发送文字，介绍普通聊天、Tavern、Story Profile、可选故事及社群；不在该轮调用工具、发送酒馆入口链接或提前导入样例。文字约束属于运行提示，真实模型是否遵守仍需验证。
- Tavern 入口由后台另行核验并发送，文字与入口卡片不保证先后；问候成功不是入口可达证明，问候失败也不应成为后台注册的前提。
- 当前配对流程首次按已核验账号初始化“诺拉”名字和头像并读回；记录成功后，普通重开不反复覆盖用户后来修改的资料。账号变化重新核验，不套用旧账号回执。
- 资料同步失败应保留已经完成的配对，说明仅名字／头像尚未同步，不让用户反复重新激活或清空配置。

**待核验：**名字和头像初始化是现有行为，本轮不改变其默认范围；问候、联系人资料、入口卡片及真实对话分别验收。

<a id="connection"></a>
## 四 模型、配对与在线状态（N-03）

完整版首次设置按[启动器首次流程](launcher.md#first-use)执行；程序安装、配置保存、模型调用、配对成功和当前在线是不同事实。表单由启动器承接，诺拉与 Hermes／ClawChat 集成给出对应执行结果。模型用途及配置保护见[总览数据与模型规则](README.md#data-and-models)。

用户选择模型并提交验证，保存和调用结果分别呈现；调用失败处理对应用途和真实原因，不重新安装或覆盖其他用途的配置。等待模型返回与程序损坏分别判断，不凭等待时间推断服务商一定成功或失败。

配对由用户显式提交连接码。首次设置要求与连接故障后的可用边界采用[共同状态规则](README.md#state-and-retry)。配对失败后显示原始原因；新信息或相关条件变化后允许合法提交。配对码的限速、保密和不自动重放规则统一见共同规则，不新增另一份长期重试状态。

日常沿用已确认配置和配对。外部连接中断时保留已证实可用的本地能力，重试对应连接；不把离线等同于需要重新配对、重装或清空世界。

配对后的联系人资料、Hermes 网关运行、ClawChat 当前连接、模型回复和酒馆服务各自核验。冷启动应说明正在准备或等待的阶段；只有请求级证据才能归因于服务商等待、依赖准备或连接失败，不以固定等待时间推断原因，也不把模型尚未响应报告为程序损坏。对用户更换连接码后的合法重试，沿用共同规则及[启动器配对入口](launcher.md#pairing)，不另建永久失败计数。

<a id="liveware"></a>
## 五 Tavern 与 Story Profile 入口交付（N-04）

**现状：**网关启动 Hook 在后台处理当前实例的 Liveware 注册／绑定与入口通知；与模型问候独立。桌面管理实例的恢复路径不擅自启动用户已停止的酒馆；独立部署的启动路径按该部署原有约定处理，不能将两者混成同一种自动启服承诺。

1. 读取当前实例和当前配对身份；已有 App、隧道与资源版本必须核验，不能信任克隆目录里的旧 ID。
2. 按已维护流程对接 Tavern 与 Story Profile 两个入口；注册、绑定和最终访问分别判断。只查询时不新建 App；明确失败与“不存在”分别处理。
3. 首次入口发送到当前主人的激活会话；会话尚未建立则等待，不能发送给历史账号。重试复用已保存的消息身份，收到服务端确认后才标记送达。
4. 入口未就绪时报告具体阶段和已有可用部分；本地健康不等于公网可达，卡片送达也不等于页面已打开。

用户可从入口卡片、ClawChat 应用菜单或酒馆已有 Story Profile 入口进入。模型不编造公网 URL；恢复沿用当前绑定，不盲目重复注册或创建第二套服务。公共集成的技术时序见[首次问候与 Liveware 启动](../liveware-first-greeting-order.md)。

<a id="model-configuration"></a>
## 六 通过对话配置模型（N-05）

诺拉自身模型、酒馆文本模型、MVU 模型分别管理。启动器首次表单的验证／保存／同步由[启动器模型设计](launcher.md#model)负责；这里记录聊天里的配置能力，不能把两个入口的验证级别混为一谈。

**现状：**`model-provider-config` 只面向具备相应实例记录的本地安装，使用现有配置程序保存诺拉默认模型；不是任意云端 Hermes 的通用配置器。

- 仅提供 Key 时先明确供应商和模型；自定义服务还需用户确认的 Base URL，不猜测服务商、不挑列表第一项、不从历史聊天搜凭据。
- 使用当前实例解释器和配置入口；安装身份或入口缺失时停止，不改系统 Python、其他 Hermes 或酒馆／MVU 配置。
- Key 经受控标准输入传入，不放在命令参数、持久请求文件、回复或日志。提供 Key 不自动授权实际付费测试。
- 该技能当前返回的是“配置已保存，新会话生效，API 尚未验证”；不热切换正在回复的当前会话，不自动重启网关。需要立即切换时按可用的宿主模型入口处理。
- 本入口的配置保护由专用程序负责：写入前保留本次原配置／凭据及模型选择记录的内存原值，普通异常时尝试恢复；是否恢复成功依据实际结果说明。它不额外生成持久备份，也不承诺强制结束、断电或磁盘故障后的自动恢复；诺拉不在调用前另复制含Key文件。

这是既有本地模型配置的专用合同。其他获授权的手工配置修改仍先备份，程序安装／更新／恢复仍准备并验证其事务恢复来源；不能把本地模型的内存原值当成这些操作的备份。专用入口缺失时报告不支持，不降级为直接手改配置来绕过合同。若要增加崩溃后的自动恢复，应先另行明确实现与验收范围，不能在产品说明中提前宣称已有。

酒馆模型和 MVU 的管理见[模型及外观协助](#models-and-visuals)及[插件与 MVU](#plugins)。配置保存、下次会话采用和真实调用成功分别反馈。

<a id="authorized-management"></a>
## 七 授权、目标与执行回执（N-06）

| 用户过程 | 必须得到的结果与失败处理 |
| --- | --- |
| 与诺拉对话 | 使用当前配置和适用连接；失败说明模型、运行或连接层的证据，不将模型回复当作业务保存回执 |
| 请求管理世界、角色或会话 | 明确本实例与目标，经授权调用既有接口，再读取实际业务结果；界面和诺拉使用同一业务事实 |
| 请求使用记忆、故事档案或剧情账本 | 按对应模块保存和读取，核对用途及内容归属；虚构剧情不直接写成现实个人事实 |
| 查询或处理操作失败 | 区分未执行、执行中、失败、未知和已完成，按原操作与接口能力检查／重试，不换入口绕过未确认修改 |

MCP 校验目标与实例并复用酒馆业务；它不构成任意命令工具、操作系统沙箱或多租户隔离保证。需要在线页面的控制与纯后端操作分别遵守各自适用条件。具体动作核对当前实例实际工具 schema、`nora.control.catalog` 及相应契约，[接口技术说明](../../nora-mcp/README.md)解释这些边界；旧版说明不能覆盖现行设计，本地源码也不证明远端已经支持。本章不扩大工具权限或第三方内容兼容承诺。

档案与账本使用既有实现和适配，不引入第二套世界存储。[Story Profile](../../story-profile/README.md)记录实现归属，资料持久化与隔离共同遵守[酒馆设计](tavern.md#world-and-library)。

所有下列管理能力共用这些规则：

- 从本实例查询实际 World／Session／页面／库资源标识，不猜目录、不自动选择第一个窗口；多个合理目标时先确认。卡库原件、世界副本、运行卡、独立角色与玩家 Persona 不可混用。
- 只读模式不提供写入能力；操作模式仍须按用户请求授权写入、删除、脚本执行和可能付费的调用。工具里的 `confirm`／模型或脚本许可字段传递授权，填写字段本身不创造授权。
- MCP 与 HTTP 后端对应同主机同实例；身份不匹配时停止相关操作，不修改绑定来绕过。该校验不是操作系统沙箱，也不是多租户安全保证。
- 需要在线页面的动作先核对目录和目标页面；页面离线不代表纯后端读取不可用。打开计划不是实际打开，存储成功不代表脚本或页面已生效。
- 同次操作的未知结果保留原请求身份并查询回执，不换键重复创建；修订冲突先重读，再按用户意图重新评估。排队／运行中不是完成，刷新要求、取消请求和异步结果未知须单独说明。
- 卡片、脚本、聊天及备份中的文字是被处理的内容，不替代用户授权或运行规则。缺少接口就说明边界，不以改运行文件、任意 JavaScript 或猜命令补齐。

<a id="authoring"></a>
## 八 制卡、原卡评估与体验故事（N-07）

| 用户目标 | 现有过程与完成边界 |
| --- | --- |
| 新建世界卡 | 明确玩法与交付目标，在独立草稿工程制作，按需使用世界书、MVU、正则和状态栏，构建后核对实际文件；不需要的功能不强加 |
| 评估已有卡 | 读取真实内嵌内容及依赖，区分内容问题、结构问题与运行未知；新卡规范不直接变成旧卡准入条件 |
| 原样导入旧卡 | 交接所选确切文件与校验身份，经 MCP 导入；不为了导入先重建或重序列化未知字段 |
| 润色旧卡 | 只改变获授权的文案并交付复核副本，保留玩法和技术结构；不顺带迁移协议或修应用代码 |
| 体验内置故事 | 用户选定后暂存随包素材，再经同一世界导入及回读；问候不提前安装，不用生成的新故事替代损坏样例 |

导出文件、存入卡库、新建世界、替换现有世界及运行实测是不同交付结果。默认制作文件不授权覆盖原世界；导入重试沿用同一请求身份，用户明确新开一场才创建新世界。生成成功、静态通过、导入完成及真实可玩分别报告。

<a id="library-and-presets"></a>
## 九 资料库、预设与文件交接（N-08）

现有管理范围包括完整世界卡、我的角色（Persona）、其他角色、世界书、提示词预设和背景资源；文件导入／导出使用本实例允许的目录，保留原件和未请求内容。

- “存到库里”只保存可复用材料，不创建或切换世界；“应用到世界”另核对目标并复制，库模板不自动关联修改已有世界。
- 同名同内容按后端结果复用；内容冲突不擅自覆盖、改名、合并或删重。完整卡的去重／删除检查引用，保留正在使用的世界副本与聊天。
- 人物资料不是完整卡，不能声称包含头像、开场、脚本和全部 MVU 状态；世界书保留条目、关闭状态和支持的元数据，不把整本书改成一段摘要。
- 预设区分库模板与当前世界副本；创建、编辑、分块读取、文件导入、应用、另存与删除分别处理。保护动态标记、原字段和未请求顺序；不改变模型连接或凭据，不因保留脚本就获得执行许可。
- 大字段或响应截断按现有分块／文件接口处理，不把截断内容当完整原件重写。版本冲突不拼接不同修订的片段。
- 导出得到私有本地文件及校验结果，不等于已上传或发给他人；背景导入也不等于已应用。外部图片 URL 会由用户页面访问该主机，按用户选择使用。

<a id="world-management"></a>
## 十 世界、角色与页面协助（N-09）

现有能力包括查询与检查世界、创建空白世界、从卡库／文件创建世界、从当前设置新开世界、有限修复和预览后删除。World Core 提供唯一业务结果；世界存储、隔离与删除范围由[酒馆设计](tavern.md#world-and-library)负责。

- 修改世界名称、玩家 Persona、独立角色、关系、设定、世界书条目、开场模板或会话背景时，明确对象和修订，只改请求字段。旁白运行卡不是世界的每一个角色；世界设定与卡主提示覆盖不是同一动作。
- 已有聊天首条消息与未来开场模板分别处理；编辑模板不声称已经改写历史。世界副本修改不暗改卡库原件。
- 页面打开面板、切换世界、库分类、侧栏和输入草稿走已有编辑保护；有未保存编辑、待确认窗口或草稿时不强制丢弃。设置草稿不自动发送消息。
- 新开世界保留原世界和原会话；删除先展示实际计划与受影响内容，再按批准的同一计划执行。计划变化需重新确认，不把删除世界扩展为清空全部实例。
- 一批多个角色／设定修改不自动视为全有或全无；逐项核对，遇到冲突或未知停止，说明已经成功的部分。

<a id="chat-and-ledger"></a>
## 十一 对话操作、剧情账本与聊天备份（N-10／N-11）

现有会话读取按目标分页，消息下标、故事轮数和完整历史版本分别使用。读日志、读聊天或查看账本不应自动触发付费生成。

| 动作 | 必须说明的区别 |
| --- | --- |
| 发送、重生成、建议回复、重试 | 复用在线页面的原生成流程及模型许可；建议回复不是已发送消息，不直写存档伪造一轮 |
| 停止生成 | 表示请求取消，待实际状态确认后才说已经停止 |
| 编辑消息与切换候选 | 在线助手消息编辑可保留后文；用户消息编辑再生成可能影响后文；现有候选切换与新生成分别判断 |
| 后端历史编辑 | 使用整个历史签名，按明确契约删除选中消息之后的内容；不能将其冒充不截断的页面编辑，也不能与页面同时编辑同一会话 |
| 账本状态／压缩 | 候选不等于已生效记忆，受保护历史不绕过编辑；压缩失败保留原文；关闭自动压缩不等于解锁已生效历史 |
| 重置账本 | 独立说明并确认重置范围，按既有备份与修订合同处理；不删除聊天或 MVU，不作为普通重试捷径 |
| 聊天备份 | 查询、限长预览、完整导出、保留、取消保留、删除和恢复是不同操作；限长读取不等于完整文件 |
| 从备份恢复 | 先预览同一世界／会话及消息变化，再按批准的哈希和历史版本执行；备份副本失败单独告知，不虚构可撤销保证；未知结果不拿新版本重复覆盖 |

压缩、可能恢复后台压缩的编辑和手动复盘等调用按接口的模型许可执行；不能因“不直接生成故事”就当作免费查询。已保存、页面应用和运行状态分别核对；程序更新备份与聊天辅助备份的共同规则见[总览](README.md#data-and-models)。

<a id="models-and-visuals"></a>
## 十二 酒馆模型及外观协助（N-12）

酒馆文本模型可查询、新建验证保存、切换和删除；它是当前用户的全局文本模型配置，不是诺拉默认模型或单个世界的 MVU。新建连接的真实测试需要相应授权；选择已有模型与发起故事生成不同，凭据不出现在清单或回执中。

现有外观能力包括本地页面的明／暗／跟随系统，以及用户全局默认和单世界的背景、字体、配色与阅读面。全局作用于当前酒馆用户，不循环改写所有世界；世界显式配置覆盖全局默认，清除世界覆盖不删除图像或故事。

诺拉可查询及调整普通故事文字的字号、行高、段落间距，支持全局默认、单世界覆盖及按字段／全部恢复继承；具体限制和存储边界唯一维护在[T-23](tavern.md#visuals)。沿用在线页面精确目标、用户授权、修订与幂等回执；不调用模型生成或执行用户脚本来改样式。字体与新阅读参数使用各自现有／新增操作，跨操作只完成部分时分别报告，不将保存成功等同页面或视觉验收。未连接页面须如实报告，不改正式文件绕过接口。

页面／WebView 可控边界、跨页刷新和外部图片访问如实说明。保存及样式应用不等于图片已加载或视觉验收通过；卡片 iframe 内部、任意 CSS／脚本和外壳标题实时绑定不因此自动获得支持。详细操作引用现有技能参考，不在诺拉设计再复制酒馆 UI 规格。

<a id="plugins"></a>
## 十三 插件、脚本、正则与 MVU（N-13）

**现状：**通过实际在线目录支持前端插件清单、安装／更新／卸载、启停与受限配置；这不是服务端插件或任意代码安装承诺。信任来源和脚本执行授权需明确；受保护基础组件不能随意移除。安装后默认关闭，更新／卸载／开关的刷新要求单独报告，已经运行的代码不因删目录就被证明停止。

Helper 脚本可按全局／角色／预设范围查询、新建、导入、编辑、删除、授权及触发现有按钮；正则支持相应范围的查询与修改。新建或导入脚本、正则默认关闭；执行授权可能影响同范围已启用脚本，不能描述为仅影响一个按钮。卡库原件的正则与世界运行副本分别处理。

MVU 需要先分清：额外模型自动解析、Nora 托管运行时、卡内自带脚本及独立模型配置。一个开关不代表全部 MVU；全局配置和卡内覆盖也不同。变量读取不提供裸写，错误重试沿用实际运行器，不能伪造已就绪状态或直接改变量掩盖问题。

错误历史是有限保留记录，不提供全部调用分母；没有记录不证明成功。脚本按钮回调结束不证明任意异步副作用完成，停用脚本也不保证撤销此前外部效果。没有映射的卡片按钮不使用任意页面代码绕过。

Quick Reply 当前只保留既有数据读取，不能从读取到配置推断可执行其前端动作。没有当前目录或专用适配的第三方插件页面／按钮同样不承诺可控。

<a id="story-profile"></a>
## 十四 Story Profile：偏好、档案与自动复盘（N-14）

档案将“对你的了解”与“故事年表”分别呈现：前者表达稳定偏好，后者只读展示剧情账本中的故事进展。旧学习事件、成长记录及阶段归档保留，累计统计不改成账本条数；档案不保存另一份聊天逐字副本或权威剧情。现有能力包括读取档案／复盘状态、显式偏好学习、复盘、付费预览和刷新；它们均使用独立 Story Profile 源码及当前酒馆适配，不另建档案库。

- 读取现有档案不授权生成；预览虽不落档仍可能调用付费模型。用户明确表达的长期偏好按实际证据记录，短暂剧情、角色行为、报错或一次格式要求不直接推断成现实身份。
- 受理或排队后查询真实结果；超时先看状态与已保存内容。并非所有档案动作都有可续查任务，缺少确定回执时报告未知，避免盲目重复收费或重复学习。
- 偏好保存与派生口味总结可能部分完成；后续修复派生结果不能谎称前一次全部没保存或再次添加同一偏好。历史聊天编辑不自动承诺撤回此前所有已学习偏好。
- 偏好提取与口味总结的输出额度跟随当前酒馆文本模型配置，不另设隐藏的1600上限；未提供额度时保留既有默认值。推理是否占用输出额度以实际模型响应为准，配置额度不承诺任意模型都能完成。
- **自动与手动流程：**按[N-Q01规则](#automatic-reflection-policy)在无设置记录时默认开启，保留已明确关闭；自动资格默认按15个有效用户轮次检查，不占前台故事保存主链路。手动复盘和自动检查共用任务与保存规则，手动动作不改自动开关。
- 细粒度偏好确认／拒绝／锁定、逐条编辑与手动记忆同步并未全部开放给 MCP；底层函数存在不代表诺拉已有这些用户能力，不能用旧脚本越权补齐。

**增量取材与输入预算：**首次／无已确认进度时从最近最多15个用户轮次开始，不自动追溯全部旧聊天；后续按该会话已处理范围增量取材。单次完整提示采用最多24,000 UTF-8字节的保守预算，并继续为配置输出及余量留空间；它是估算，不宣称等同任意服务商的精确tokenizer。已有偏好以精简结构参与去重，既有学习事件及阶段归档保留在本地；超预算用户消息不跳过或冒充已处理。相似但非相同的条目可能成为待核对候选，不能据此声称具备语义理解或全部确认／编辑入口。

模型连接沿用当前酒馆自定义兼容接口配置、输出额度及实际代理选择。直连及HTTP(S)代理有实现；SOCKS／PAC代理明确报不支持，不能静默直连绕过用户选择。模型空答、截断、格式错误、权限／内容拒绝与合法无新增分开；没有承诺服务商必然接受任意故事。偏好提交及总结分阶段保存，派生总结核对来源偏好修订；损坏记录保留并报告，已准备且可核验的中断提交有不调用模型的恢复入口。

**剧情进度来源：**原聊天是事实依据，账本是可重建的滚动摘要。通过结构、世界／会话归属、来源修订校验且已经保存的待用账本即可供进度查看及按需读取，不再等待下一次续写采用；“已整理”和“已用于续写”由后台状态分别回报，年表不展示这些运行术语，不为进度读取强行激活或锁定历史。失败、未完成、来源失效的摘要不得进入有效进度；存在分支时按会话分别标识，不合并互斥剧情。模型摘要的语义质量仍须真实样本验证，结构校验不代表绝对忠实。字段归属和隔离引用[共同数据规则](README.md#data-and-models)与[酒馆世界规则](tavern.md#world-and-library)。

**USER.md容量与偏好：**Hermes `memory.user_char_limit` 默认2000字符；新安装／普通更新为缺省或历史默认1375、1875写入2000，其他自定义正整数额度保留，重复执行不增加。部分修复原样保留配置。偏好总结精简为故事口味4条、叙事习惯3条、共创方式3条、明确边界4条，每条最多100个Unicode字符，纯值正文最多1400字符；标题、标记、换行另计，剩余容量归Hermes自身记忆。只根据已有证据整理，不填满空类别，不用直接截断丢失否定／条件。旧八字段总结及原偏好记录保留；不在加载时清空旧总结，无法无损兼容时明确需刷新。同步仍按实际整份文件额度扣除非托管内容及格式，预留103字符；2000额度下整份同步后最多1897字符，不保证任意既有内容下都能写满1400。每次替换托管块，不追加增长，不删除其他记忆或擅自扩大额度。现有12条有效偏好策略保留；原档案／历史原件保留。实现与真实模型验收分别留证。

未完成上述配置迁移、且实际配置缺少 `user_char_limit` 时，投影仍遵守当前固定 Hermes 的1375字符回退值；写入器不以产品默认2000自行扩大实际额度。新安装／更新写明2000与现存自定义额度的处理分别验收。 历史实现及阶段验收见[整条流程记录](../verification/story-profile-plot-memory-flow-20261021.json)；该记录中的旧剧情投影方案已由下文按需读取替代，历史结果不代表当前方案已部署。

**剧情按需读取与MEMORY边界：**剧情不再自动写入MEMORY.md；原`shared_story_memory`档案记录、账本、年表和旧学习历史保留。正常同步／刷新／恢复及旧context兼容入口均不重新拼接剧情。MEMORY.md不存在或没有酒馆托管块时不创建／追加空块；对唯一、完整、来源修订可核验的`TAVERN_SHARED_MEMORY_START/END`区块先备份整个原文件，再只移除该区块，其他字节及Hermes自身额度不变。损坏／重复边界、较新修订、备份失败或外部并发变化时保留原件并报告待清理，USER偏好同步仍独立继续。来源修订必须唯一且为可解析的不晚于当前档案修订的标记；缺失、损坏、重复或冲突标记先保留并报告，不以完整备份代替归属核验。清理后使含旧剧情的Hermes活动提示缓存失效；缓存库确实不存在则无此步骤，已有库损坏、不支持或锁冲突须分别报告未完成。文件同步成功不代表缓存清理成功，整体保留部分完成状态，可不调用模型地重试本地同步；旧聊天中已经出现的内容仍保留，不承诺从历史上下文抹除。

**定位与读取：**复用`nora.story.progress`和现有World Core元数据，读取必须落实到同一实例的明确世界与会话。已确认ID直接读取；精确名称唯一时可直接解析，同名世界／多分支返回有界候选，不静默选首项。分支显示名按[世界与会话规则](tavern.md#world-and-library)保存，旧无名记录不迁移为ID名称。默认只读账本近况、进展及未解事项；问题涉及事实或物品时选择相应字段并按关键词读取，未揭晓秘密不作为玩家已知事实输出。账本已保存待用与已用于续写仍分别回报，查询不触发激活、模型整理、插件启用或记忆写入。

**上下文与时效：**每次工具完整JSON结果默认最多3000字符，可显式扩大到最多6000；分页游标绑定世界／会话、源修订及查询字段，源变更则重新读取同一目标。保留完整条目，容量不足时明确遗漏，不硬截否定或条件。默认不附原聊天；确有需要时显式补读最多10条近期完整消息，并与账本共用整次响应额度，报告实际消息所属轮次及本页未返回的精确消息ID区间（0起、含两端，含空消息／已摘要原文／其他页），不把总数猜作连续前文，不自动灌入全部旧聊天。缓存绑定精确身份及源文件修订，变更后重核，不能混用其他世界或恢复前账本。实际读取内容仍占相关对话上下文，停止常驻不等于零token或回复后自动从历史消失。

**无账本及实际诺拉流程：**具体故事进度、人物／物品状态或续接建议先调用上述只读入口；普通无关对话不预载全部世界。自动整理关闭、未触发、失败或来源失效时明确账本状态，可在必要时按预算读近期聊天，不重新打开用户关闭的账本、不虚称已了解全部故事。工具存在／接口返回正确与诺拉真实对话选对目标、读到最新修订、保留USER偏好分别验收。

<a id="automatic-reflection-policy"></a>
### 自动偏好复盘规则（N-Q01）

**当前确认（基线1.31）：**自动整理故事偏好及其酒馆设置开关继续保留。默认开启仅适用于尚无该项选择的用户；旧版关闭不因升级、重开或本次基线确认而重置。此开关不改变剧情账本、MVU或Hermes自身记忆的选择。

**已确认设计：**后台偏好复盘默认开启，用户可以关闭，不增加首次启用弹窗。自动开关位于酒馆“角色与设定 → 故事主理人 → 偏好设置”，适用于所有世界；只提供“自动整理故事偏好”开关和用途／费用说明，不放世界选择、手动整理或故障维护按钮。说明会将必要故事片段发送给当前酒馆文本模型、可能持续产生调用费用。默认策略不伪装成已记录的用户主动同意，与普通聊天、额外MVU及剧情账本分别管理。原档案展示、后台复盘、既有复盘交接、API／MCP及错误恢复保留。

| 场景 | 设计要求的结果 |
| --- | --- |
| 新安装或新用户尚无设置记录 | 默认开启；达到原有效轮次资格才后台调度，不因打开页面立刻生成，也不创建虚假的用户选择记录 |
| 用户明确开启或沿用默认开启 | 沿用现有有效轮次资格与后台调度，按原实例／世界去重，不新增定时服务；不占前台正文保存主流程 |
| 用户关闭／拒绝 | 每一次自动模型请求派发前复核持久开关；关闭后不再发新的提取、格式重试或总结请求，已保存提取结果不重复学习；保留已存档案、偏好、聊天和账本。已发送请求的结果及可能费用如实说明，不保证撤回服务商已处理请求 |
| 旧安装有明确布尔开关记录 | 兼容原用户目录与当前档案设置格式，保留开启或关闭选择和原字节，包括旧说明版本；来源冲突时关闭优先，只有用户随后明确保存的新选择可覆盖其已核验的旧选择，不因升级或重开强制开启 |
| 旧安装无对应开关记录 | 按最新默认开启，不补首次启用确认，保留配置及已有档案；不把默认值记为用户主动选择 |
| 开关记录损坏或无法读取 | 保留原文件并报告，不能当成没有记录后套用开启默认值 |
| 用户主动要求手动复盘／模型预览 | 按该次用途和[共同费用说明](README.md#model-use-and-cost)执行；不借此打开以后全部自动复盘 |
| 检查资格、读状态、翻阅旧档案或同步已有账本的档案派生状态 | 不因此另发复盘生成；结果未知先查旧结果，不自动重复学习或重复收费 |

取舍：普通用户无需额外找到开关，达到故事进度后即可自动整理；代价是默认可能产生额外模型调用与费用，因此保留用途说明及关闭入口。关闭不删除既有学习结果、关闭诺拉普通对话或关闭其他记忆；不承诺精准金额、退款、任意后台任务强制取消或新增费用统计系统。

验收要求：无设置记录时读到开启且不写入主动选择；达到原资格才执行且无同次重复；关闭后、重启后关闭仍不发新自动请求；手动复盘不改开关；旧布尔选择及损坏记录保留；Node准入与Python每次派发采用同一设置含义，覆盖提取中关闭、重启、历史路径和新旧记录冲突。聊天、偏好与档案内容不因改默认值变化，原增量预算与失败恢复保持。此前源码、原生存储／恢复及当前模型验收见[原记录](../verification/story-profile-reliability-20261021.json)；本次默认值验证单独记录。安装包、正式部署及第三方任意模型不由这些结果推断通过。

<a id="profile-page"></a>
## 十五 档案页面与人格编辑（N-15）

**现状：**Story Profile 是当前服务提供的独立页面，可从 ClawChat 应用或酒馆进入。显示名称／介绍、故事统计、亲密度进度、已知偏好与年表；空档案、读取中和读取失败分别呈现。统计来自实际世界和会话聚合，不是模型随口编写，也不承诺已包含所有历史分支。

故事年表下不常驻新增的复盘操作面板；原档案布局和人格编辑保留。后台复盘设置使用[N-Q01的酒馆入口](#automatic-reflection-policy)，不会因打开档案而启动模型请求或改变开关。

**故事年表展示：**直接展示已保存、来源有效的剧情账本，不另外生成年表短回顾。每张卡片保留故事名、已有场景的时间／地点和已登记玩家的活动／状态；默认显示账本按时间排列的最近三条进展和现有顺序的前两条未解事项，更早进展和其余事项可通过“展开更多进展与线索”只读查看。精确重复及空条目不重复展示，不宣称具备新的语义重要性排序；不改写、不补写、不硬截完整句子，展示上限沿用账本字段合同，折叠控制页面长度；不再保留额外300字符模型回顾协议。只展示进展／未解事项／场景，不展示facts、secrets、objects或写作指令等完整后台字段；不承诺仅靠展示格式纠正原账本自身的语义错误。

有旧记录也直接显示已有事件和事项，既不依赖recap字段，也不为旧记录另调模型或迁移数据；预览与验收均使用实际源记录，不以手工补写的展示字段代替真实进展。仅同世界多分支且名称有实际意义时显示分支名，不显示自动编号、会话数量、整理／采用状态、轮数及未覆盖范围。无摘要、空白或来源失效会话不生成卡片；整体读取失败与无进展分别说明。默认按真实聊天时间显示最近3条有效故事记录，同世界不同分支分别呈现，其他记录可只读展开；不按整理文件修改时间冒充游玩时间。

年表仍为滚动进度视图，说明为“回顾故事的重要进展”，不承诺永久完整章节史；不常驻MEMORY，展示范围与按需读取的响应额度分别管理。原聊天、旧偏好学习事件／阶段归档、累计记录与亲密度保留，不清零重算；后台完整会话状态及诺拉只读原文回退保留。档案读取不调模型、不改记忆、不启用插件；原布局、返回导航、统计及人格编辑控制保留。

- 从酒馆跳入时保留安全的返回位置；独立打开时不制造没有来源的返回入口。按既有语言与身份信息呈现，不从页面名称推断新的人格版本。
- “整理这场故事”交接当前诺拉聊天并填写草稿，用户发送前不执行复盘；生成链接不等于消息已发出。
- 仅部署已配置人格编辑时显示相应入口；编辑当前配置的人格文件，不改世界角色或玩家 Persona。编辑区包含当前文本、长度提示、保存、取消及状态。
- 保存校验非空、长度与原修订；冲突提示重读，不覆盖他人更新。取消有改动时要求确认丢弃；保存失败保留编辑内容供处理，不把失败写成保存成功。
- 人格文本保存、Hermes 在后续上下文采用及当次回复表现是不同结果，不承诺当前会话立即热切换。键盘、焦点、滚动、移动端与深浅色按真实页面验收，本轮不改变其布局或控制。

### 默认技能库管理（2026-10-23 用户确认）

`nora-skill-library` 随诺拉内容作为默认技能交付，首装及适用的核心更新通过现有技能部署机制安装；用户无需单独下载管理技能。Hermes 在技能索引中发现，用户请求查找、安装或使用技能时由诺拉加载，普通聊天不强制加载全文。

<a id="operations"></a>
## 十七 诊断与授权恢复（N-17）

诊断先定位业务操作、酒馆进程、Hermes／MCP、模型服务或公网 Liveware 哪一层失败。按请求读取有界状态和日志，不能用一个健康接口代替所有层正常；MCP 不通时仍可用宿主既有工具诊断，缺少工具要说明。

只读检查不附带重启、依赖安装、重新配对、重新注册或源码修改。明确授权恢复时，先核对本实例和服务范围，保护世界、聊天、配置、身份及其他实例；配置变更执行其适用的备份／恢复约定。使用受维护生命周期入口，不猜固定端口、云端路径或 App ID，不为了让校验通过而改绑实例。

完成后重验原失败层：恢复了本地服务不等于公网入口、模型或复杂卡也恢复；未确认仍如实报告。服务恢复不替代版本更新，具体恢复效果及证据边界采用[共同规则](README.md#state-and-retry)。

<a id="autonomous-update"></a>
## 十八 版本提醒与自主更新（N-18，PB-06／PB-09）

定时核心提醒保持按本实例核心变化去重；仅发布APP时不误报核心升级。用户主动检查时，桌面版在后台核对核心与APP两项并直接返回结果，不打开启动器、不提交或覆盖更新任务；检查结束不需要查询另一个旧更新任务。用户明确授权更新后，才一次交给现有桌面双更新入口。没有APP的源码／云端继续交给[独立核心更新任务](README.md#shared-update)。诺拉负责提交、查询和如实说明结果，不自行实现下载／替换；查询和提醒不授权静默安装。

独立核心更新器本身不要求桌面启动器已安装、打开或在线。桌面统一更新需受支持的启动器及对应运行环境；已核验的桌面APP关闭时，明确授权的整套更新可按需唤起它并进入同一更新流程。没有APP与APP缺失、损坏、旧版不支持分别反馈，不静默降为核心成功后宣称全部完成。接管后诺拉停止或调用方断开，任务继续并可查询同一终态；核心／APP版本、健康、用户数据和任务结束分别核验，部分成功和重试按共同规则处理。不能从新版设计推断所有历史脚本已获得新能力。

定时检查、用户询问最新版本、用户批准安装是三个不同动作；不因提醒或一次普通聊天静默执行更新。查询失败不能报告“已是最新”；已通知同一目标的去重以现有发送结果为依据，不重复提醒来掩盖安装失败。渠道及核心／APP 版本分工遵守[版本规则](README.md#version-rules)。

正常入口顺序是：解析本实例与解释器 → 检查适用组件及桌面能力 → 获得用户更新授权 → 提交现有桌面流程或独立核心更新器 → 取得接管依据 → 断开／重连后查同一任务。只需一项时只更新该项；受理成功不是升级成功，已回退不是目标升级成功，用户无需再次批准同一固定计划的另一项。失败后保留真实原因和可用恢复路径，不能通过删记录解锁。

旧版首次接入分两类：无APP的源码／云端按已确认的首次升级指令，从正式渠道取得并校验当前接入程序，仍在原实例更新，不要求安装桌面APP；桌面旧APP或旧更新器不支持统一请求时，原更新入口可用则先升级，入口失效则采用已验收的保留数据安装或修复路径。保留聊天、角色、世界、配置与凭据，不要求用户删记录或清空数据。旧Windows缺少终端等运行依赖时，仅替换APP不能承诺补齐环境，应交付并验收相应完整运行环境。具体版本、入口和数据布局逐项验收，不泛称任意旧版原命令都可用；部分完成与程序恢复仍遵守共同规则。

<a id="failures-and-privacy"></a>
## 十九 失败反馈、重试与隐私（N-19）

每次结果先说明用户请求的目标、实际执行到哪一步、是否改变内容、现有可用部分及下一步。原始操作失败、限速、未提交、等待、未知、部分完成和已恢复分别表达；不能用“检查没过”代替具体影响，也不让用户凭猜测删目录。

重复提交按对应后端合同查询或重试；需要新输入时允许重新提交，恢复未结束时不并行写入。付费调用超时不证明模型未执行，脚本返回也不证明任意异步工作完成。模型冷启动、外部网络和程序故障各按证据归因，不给所有等待套同一种超时解释。

模型调用会把对应用途的必要内容交给用户选择的服务；MCP 返回所请求的私人内容也会进入智能体上下文，不能将“本地 MCP”描述为内容绝不离开本机。凭据、配对码、完整提示词和私人故事不进入故障诊断或不必要的回复。诊断送达不替代业务成功；详细上报选择及采集边界见[共同隐私规则](README.md#quality-and-privacy)。
