# 世界卡库复用流程

最初在 codex/library-workflow 与本地 8800 测试；现按用户授权整合到本地 main，不推送或发布 GitHub。下方历史验证记录保留其当时的测试范围。

## 保留与改变

- 保留完整卡文件、创建新世界流程、扩展启用授权、预设库及现有世界。
- 世界卡库内分为世界卡、角色、世界书；角色下再分我的角色、其他角色。
- 此分类只调整导航：世界卡仍为完整卡，其他角色仍使用 character 资料，我的角色仍使用 persona 资料，不迁移或混合两类数据。
- 角色资料保存名字、介绍、性格及常驻/触发规则；不推测一张卡中的多个人物。
- 已有角色的结构化 profile 额外字段也保留；不附带聊天状态或跨角色关系。
- 我的角色保存玩家名字与描述，不将玩家当作 NPC。
- 世界书保存全部条目和原有开关、触发参数；不因禁用而丢弃条目。
- 不把角色资料宣称为完整卡：头像、开场白、脚本、正则和 MVU 不随角色资料复制。
- 不迁移、不删除用户历史数据，不改变现有世界绑定。

## 操作路径

1. 库中导入或新建资料，只存库、不应用。
2. 完整卡详情可单独另存角色资料；内嵌世界书详情可另存独立世界书。
3. 角色设定编辑的添加入口可手动创建或从角色资料库选择。
4. 世界设定编辑的添加入口可手动创建或从世界书库选择。
5. 我的角色编辑中可从库选择；替换前确认目标世界。
6. 角色编辑和我的角色编辑可以将当前表单另存到库；不同时保存世界。
7. 世界书详情可以另存整本；单个世界设定编辑可以另存仅该条目的世界书。
8. Nora 通过相同后端接口保存及读取资料，不能绕过校验直接改 JSON。

## 视觉

完整卡保留封面；资料和世界书用紧凑列表，名称为主、类型/来源为辅。
顶部三个一级分类标签在窄屏横向滚动；角色页下方显示紧凑的“我的角色 / 其他角色”二级切换。搜索和导入在同一行。
详情长文本可滚动，底部操作区固定，显示当前目标世界。
从设定进入的选择器只展示适合该设定的资料，不出现创建新世界。
管理动作放在详情管理区；另存与应用使用不同按钮和不同反馈。

## 数据与安全

角色资料/我的角色存于用户 World Core 根目录的 library-profiles，不属于任何世界。
世界书继续使用 ST 原有 worlds 文件与 Nora 的独立世界副本机制。
同类型同名同内容复用；同名不同内容拒绝并要求改名，不静默覆盖。
写入采用原子 JSON；资料导入只接受白名单字段，不执行脚本。
应用前检查生成状态、世界 ID 和修订号；预览后切世界不可写入新世界。
应用角色生成独立 ID；世界书复制为世界所有资源；修改/删除库不回写已应用的世界。
跨角色引用和外部脚本依赖不自动重映射，不能声称拆出来的资料等同完整卡。

## 验收

- 用临时目录与临时世界覆盖存储、同名冲突、重复提交、损坏项、路径、并发及隔离。

- 构建并更新本地 8800；核对服务响应和新资源。未经允许不打开浏览器。
- 技术测试与真实视觉验收分开报告；现有用户世界不作为写测试对象。

## 完整卡自动入库与去重（2026-09-11）

- 上传完整卡直接存库，以及从文件或库创建世界，均经过后端完整卡入库检查；内部空白世界卡除外。
- 比较解析后的卡内容、PNG 非卡信息块和 CHARX 附件的 SHA-256；忽略导入时间、聊天定位及导入来源等存储元数据，不按名称判断相同。
- 相同内容复用已有原件；同名但设定、世界书、脚本、封面或附件不同，保留为不同卡。
- 入库时清理本次内容对应的无引用重复 PNG。世界运行卡、聊天目录、附件目录、群组及设置引用的文件保留；不做全库破坏性迁移。
- 原始容器保存在用户 World Core 的 `library-cards/sources`，索引在 `library-cards`；保留 CHARX 附件，避免从库创建世界时只剩 PNG。
- 每个新世界仍有独立运行卡和会话。入库成功后即使世界创建失败，原卡仍留在库中，失败世界的运行资源按原补偿机制处理。
- 完整卡列表使用后端目录，不再将每个世界运行副本都显示为新增原卡。
- 老安装若仅存世界运行卡，保留一条标记为“已有世界快照”的入口；它不是找回的原始上传文件，不自动改写历史卡。
- 本轮未更改角色资料、玩家资料、独立世界书的保存规则，未拦截旧 ST 原生管理界面的 `/api/characters/import`。

- 使用临时目录和临时 HTTP 服务验证写入流程，测试结束清理；未向现有用户世界发送消息或调用模型。

- 前端构建通过，仍有既有体积建议警告；未使用浏览器，视觉效果由用户查看。
- 未合并 main、未推送 GitHub、未发布版本。
