## 1. 目标和范围

### 可观察的目标

- 数据不丢：保存、备份、恢复分别报告结果；失败不破坏之前有效的数据。
- 世界不串：编辑、恢复、删除世界 A，不改变世界 B 或库原件。
- 删除可解释：执行前能说明目标、共享引用、保留内容和不可恢复范围，执行后结果与之对应。
- 占用可控：恢复数据有数量、期限与空间策略，用户有查看和管理入口。
- 用户可自由编辑：只治理明确归程序管理的数据，不因内容变化自动还原用户文件。

| 类别 | 范围 |
| --- | --- |
| 保留 | 库原件与世界副本隔离；JSON/JSONL/PNG 格式；原子保存、版本校验、操作重试；必要的完整快照 |
| 重构 | 数据归属识别；备份创建、去重和保留；一致性恢复；删除协调；终态记录精简；受管维护文件清理 |
| 暂缓 | 数据库迁移、增量备份、通用内容寻址存储、物理去重、完整世界回收站 |
| 不在范围 | MVU 协议/提示词/模型行为调整、其他 UI 重设计、自动修复用户文件、清理非受管目录 |

并发边界（2026-09-29 用户确认）：**一个酒馆服务、多页面并发**。两个独立服务同时写同一用户目录不纳入本次，也不通过单独给备份加锁来声称整体支持；跨进程协调另立范围。

“删除世界”与“删除库素材”是不同操作；“恢复聊天”不等于“恢复完整世界”；“回退程序版本”不能找回已彻底删除的数据。

## 3. 每阶段执行与通过规则

1. **开始前**：读本文、检查前置阶段和相关决策，确认授权；记录工作区状态、当前问题证据、保留/修改范围。
2. **实现时**：只做该阶段确认范围；复用现有模块，替换旧职责而非并行叠加另一套机制。
3. **验证时**：逐项关联下面的验收 ID 和适用的 V 编号，记录命令、环境、测试用例、结果与局限。UI 检查需符合用户的浏览器使用授权。
4. **结束时**：回读本文，更新勾选、阶段状态与证据记录；明确行为变化、未通过项和回滚限制。
5. **进入下一阶段**：前置条件已满足。未通过的必需项不得略过；范围调整或不适用项必须写明理由并经确认，不能自行降低标准。
6. **部署时**：另获授权，备份受影响运行文件，核实部署文件与运行健康；健康检查不能替代用户流程验收。

### 状态用语

- 未开始：没有实施本阶段。
- 进行中：已有工作，但清单未全部通过。
- 待验收：代码或技术检查已完成，仍缺所需流程/视觉/环境证据。
- 通过：全部适用验收项有证据，无未解决的高风险偏差；须注明通过环境，不代表已部署。
- 暂停：写明原因和恢复条件。

证据等级分别记录：已分析、已实现、技术验证、用户结果验证、已部署。设计阶段的“通过”仅表示设计门槛通过，不冒充程序功能完成。
