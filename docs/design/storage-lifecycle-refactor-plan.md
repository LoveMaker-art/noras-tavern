# 数据存储与生命周期重构：执行及验收基准

创建日期：2026-09-28。当前状态：**方案已记录，重构未开始**。

本文是本项工作的唯一执行与验收基准。后续涉及备份、恢复、世界删除、导入存档清理或终态记录精简时，先读本文；每阶段交付前，逐项对照本阶段清单和跨阶段验证矩阵，更新本文的状态与证据。不得仅凭代码已写完或测试数量标记阶段完成。

本文的建立不代表获得实施、真实数据清理、部署、提交、合并或发布授权。新增用户要求或证据推翻原方案时，先记录变更及影响，再继续执行。

## 1. 目标和范围

### 可观察的目标

- 数据不丢：保存、备份、恢复分别报告结果；失败不破坏之前有效的数据。
- 世界不串：编辑、恢复、删除世界 A，不改变世界 B 或库原件。
- 删除可解释：执行前能说明目标、共享引用、保留内容和不可恢复范围，执行后结果与之对应。
- 占用可控：恢复数据有数量、期限与空间策略，用户有查看和管理入口。
- 用户可自由编辑：只治理明确归程序管理的数据，不因内容变化自动还原用户文件。

| 类别 | 范围 |
| --- | --- |
| 保留 | 库原件与世界副本隔离；JSON/JSONL/PNG 格式；原子保存、版本校验、操作重试；必要的完整快照 |
| 重构 | 数据归属识别；备份创建、去重和保留；一致性恢复；删除协调；终态记录精简；受管维护文件清理 |
| 暂缓 | 数据库迁移、增量备份、通用内容寻址存储、物理去重、完整世界回收站 |
| 不在范围 | MVU 协议/提示词/模型行为调整、其他 UI 重设计、自动修复用户文件、清理非受管目录 |

“删除世界”与“删除库素材”是不同操作；“恢复聊天”不等于“恢复完整世界”；“回退程序版本”不能找回已彻底删除的数据。

## 2. 已知基线与待确认决策

### 2.1 基线是历史观察，不是未来环境的实时状态

2026-09-28 对本机 8799 的代码与文件盘点发现：

- 6 个有效世界；另有 8 个已删除世界的完整配置记录，约 2.8 MiB。
- 当前聊天约 4.1 MiB；303 份聊天备份约 227.8 MiB，包含过去聊天，不能全部算成当前世界的相同副本。
- 50 份设置备份约 14.4 MiB。
- 8 份原始导入存档与现存卡文件字节相同，约 21 MiB。
- 更新及人工调试备份目录约 678 MiB；该数值不代表全部由日常游玩产生。
- 聊天备份采用约 10 秒尾沿防抖，没有内容去重；分组上限 50，全部聊天备份总数量配置为 `-1`，未见到期/字节预算策略。
- 删除世界清理独占运行资源及账本，但不关联清理聊天备份，并保留完整删除记录；库卡删除路径不连带清理原始导入存档及索引。
- ST 有原生备份浏览/导入功能；Nora UI 未接入完整恢复路径，不能据此声称 Nora 世界恢复已可用。
- 正式更新器已有成功后保留最新 1 份回退备份的逻辑；人工调试同步没有经过同一清理流程。

观察所在源码：`codex/extension-manager`，当时 HEAD `6a532ca`，包含既有未提交改动；**不能把该提交单独当成完整运行版本**。实施时重新记录分支、提交、差异和部署文件校验值，保留无关改动。

## 3. 每阶段执行与通过规则

1. **开始前**：读本文、检查前置阶段和相关决策，确认授权；记录工作区状态、当前问题证据、保留/修改范围。
2. **实现时**：只做该阶段确认范围；复用现有模块，替换旧职责而非并行叠加另一套机制。
3. **验证时**：逐项关联下面的验收 ID 和适用的 V 编号，记录命令、环境、测试用例、结果与局限。UI 检查需符合用户的浏览器使用授权。
4. **结束时**：回读本文，更新勾选、阶段状态与证据记录；明确行为变化、未通过项和回滚限制。
5. **进入下一阶段**：前置条件已满足。未通过的必需项不得略过；范围调整或不适用项必须写明理由并经确认，不能自行降低标准。
6. **部署时**：另获授权，备份受影响运行文件，核实部署文件与运行健康；健康检查不能替代用户流程验收。

### 状态用语

- 未开始：没有实施本阶段。
- 进行中：已有工作，但清单未全部通过。
- 待验收：代码或技术检查已完成，仍缺所需流程/视觉/环境证据。
- 通过：全部适用验收项有证据，无未解决的高风险偏差；须注明通过环境，不代表已部署。
- 暂停：写明原因和恢复条件。

证据等级分别记录：已分析、已实现、技术验证、用户结果验证、已部署。设计阶段的“通过”仅表示设计门槛通过，不冒充程序功能完成。

## 4. 阶段计划和验收清单

### 阶段 0：基线、规则与验证夹具

**前置**：获得开始本阶段的授权。**工作量/风险**：小—中 / 低。

- [ ] P0-1 每类数据明确当前权威来源、写入路径、引用关系及删除条件；标记未知项。
- [ ] P0-2 D1～D6 中本轮所需决策有确认记录；其余保留待定，不伪造授权。
- [ ] P0-3 记录基线空间和现有行为；区分库副本、恢复点、缓存、更新包。
- [ ] P0-4 建立同名世界、共同来源、旧格式、损坏快照、有/无 MVU、有/无账本的隔离夹具及验证清单。
- [ ] P0-5 明确后续修改范围、性能测量方法及可接受阈值；保留现有无关修改。

**回滚/限制**：只读分析和测试数据；本阶段不迁移、不删除真实数据。

### 阶段 1：可靠归属与只读盘点

**前置**：阶段 0 的相关设计通过。**工作量/风险**：中 / 中。

**工作**：复用 world/session/resource ID；为备份等补齐归属、创建时间、摘要、大小及格式信息。索引尽可能可重建，原文件不要求搬家。旧数据分为“确定归属、候选归属、无法识别”；名称和路径前缀不能单独作为删除证据。

- [ ] P1-1 同名、更名世界及跨世界共享资源的归属判断正确（V1、V6）。
- [ ] P1-2 每项盘点结果能解释保留或清理候选原因；候选归属和未知文件不进入自动删除集合。
- [ ] P1-3 索引损坏/缺失时可重建或安全报告，不能误判原件丢失后自动创建空数据。
- [ ] P1-4 盘点的所有路径受控，不跟随越界链接，不修改用户内容（V6）。
- [ ] P1-5 读取旧格式及现有世界正常；记录扫描时间、读取量与目录规模（V7）。

**回滚/限制**：可停用新索引，原文件保持原样；本阶段只生成盘点信息，不执行清理。

### 阶段 2：备份生成、保留策略与可见清单

**前置**：阶段 1 通过；D3、D4 已确认。**工作量/风险**：中 / 中。

**工作**：备份模块统一创建、去重、列举和淘汰。正常聊天保存仍及时完成；备份错误与正式保存错误分开。识别正文/MVU 中间状态；普通快照合并过密保存，破坏性操作前建立必要恢复点。提供时间、世界、范围、大小等清单，以及受控下载/选择删除；恢复功能待阶段 3 通过后开放。旧快照批量淘汰留到阶段 6。

- [ ] P2-1 相同内容重复保存不持续新增快照；有意义的消息/MVU 变化不会被错误去重。
- [ ] P2-2 正式保存成功而备份失败时，结果与提示准确；备份故障不被冒充为生成失败（V2）。
- [ ] P2-3 清楚区分一致恢复点与未完成状态，保留策略遵守确认的数量/期限/预算规则。
- [ ] P2-4 长期无新保存的会话也能按规则到期；正在写入和受保护对象不会被淘汰（V3）。
- [ ] P2-5 预算冲突、超大单份、磁盘不足时行为明确；正式数据不参与预算删除（V2）。
- [ ] P2-6 旧备份可读；新逻辑没有与旧逻辑双写；测量前后保存延迟和磁盘增长（V7）。

**回滚/限制**：可停用新策略；已删除快照不能通过回退代码恢复。真实旧备份不在本阶段自动清除。

### 阶段 3：聊天一致性恢复

**前置**：阶段 2 通过；D2 明确。**工作量/风险**：中—大 / 高。

**工作**：第一版建议只恢复仍存在世界的聊天。恢复前检查目标身份、快照格式、当前版本及生成/保存/压缩状态；协调消息、MVU 状态、账本和运行态刷新。对旧快照缺失的内容明确限制或拒绝，不调用模型补造。现有 ST“将 JSONL 导入当前角色”不能直接作为 Nora 世界恢复实现。

- [ ] P3-1 恢复前展示时间、目标、影响范围和不包含的数据；错误世界/会话被拒绝（V1）。
- [ ] P3-2 聊天、MVU 和账本一致；有/无这些能力的夹具均覆盖，恢复后可继续使用（V5）。
- [ ] P3-3 候选回复、编辑消息、压缩历史及旧快照缺失信息分别有明确处理结果。
- [ ] P3-4 恢复前保护当前有效状态；中断后保持有效状态或明确可重试，不留下半恢复（V2、V4）。
- [ ] P3-5 生成中、MVU 保存中、账本工作中及多页面冲突有一致处理，禁止绕过已有校验（V3）。
- [ ] P3-6 本阶段支持的恢复流程在目标测试环境演示通过；没有声称能够恢复已删除的完整世界（V8）。

**回滚/限制**：先用隔离数据；代码回滚不能代替恢复事务的数据恢复。完整世界回收站若获批准，先修订本文再扩展范围。

### 阶段 4：世界与库的删除流程闭合

**前置**：阶段 1～3 通过；D1、D6 明确。**工作量/风险**：中—大 / 高。

**工作**：通过现有世界模块协调删除，先形成删除/保留计划，执行前复核版本和引用。世界删除处理独占资源、聊天、账本以及用户确认的恢复点；库卡删除清理卡及索引，无引用原始存档才可回收。共享资源和库原件保护不变。

- [ ] P4-1 删除计划与实际结果逐项一致；部分失败不显示“全部删除成功”。
- [ ] P4-2 同源或同名的其他世界、共享资源、库原件未被误删（V1）。
- [ ] P4-3 删除后延迟备份、后台保存、旧页面和重复请求不能重新写出该世界数据（V3、V4）。
- [ ] P4-4 删除库卡后索引及原始存档引用同步；仍有引用或无法确认的对象保留并说明。
- [ ] P4-5 中断后可安全继续删除；目标或引用改变时重新确认，不按过期计划强删（V2、V4）。
- [ ] P4-6 UI 与 MCP 复用同一操作、校验和结果语义；MCP 不接受任意文件路径删除（V8）。
- [ ] P4-7 删除确认明确备份去向、不可恢复范围及更新包可能仍含历史数据（D6）。

**回滚/限制**：彻底删除不可逆；阶段验收使用专用数据。真实世界清理必须另获明确授权，不能用自动备份抵消授权要求。

### 阶段 5：终态记录及维护文件治理

**前置**：阶段 4 通过。**工作量/风险**：中 / 中—高。

**工作**：完成/删除终态可转换为最小凭据；进行中及可重试失败操作保留恢复资料。保留必要 ID、摘要、结果及时间，维持防重放能力；格式版本化并兼容旧记录。暂存和缓存按归属与可重建性处理。正式更新器只管理自己的回退包，人工调试备份单独管理。

- [ ] P5-1 旧记录可读，精简后不会被校验器当作损坏或遗失记录（V7）。
- [ ] P5-2 终态精简后重放旧请求不重新创建已删除世界；进行中/失败现场不被压缩或清理（V4）。
- [ ] P5-3 暂存只在不再用于重试后清理；缓存可重建；不把用户文件识别为垃圾（V6）。
- [ ] P5-4 更新成功/失败/回滚分别验证保留规则；仅淘汰有明确归属的回退包，不按目录内所有条目通删。
- [ ] P5-5 人工调试备份与正式回退包分开；说明是否包含用户数据，失败恢复现场受保护。
- [ ] P5-6 记录空间收益和额外复杂度；物理存储去重不借机扩展到本阶段。

**回滚/限制**：读写格式回退需兼容性设计；尚无兼容读取能力的旧程序不能直接覆盖新格式运行。受控迁移前保留经授权的恢复材料。
