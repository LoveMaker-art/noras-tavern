# MVU 共用核心与旧卡兼容评估

日期：2026-09-17。独立分支：`codex/mvu-native-semantics`，基线：`195f81282839e9de3d3af2b44555880b010ff1c8`。

## 结论

不需要舍弃全部优化，也不建议另外内嵌一整套原版插件。当前运行时本来就在固定版本的原 MVU 上构建；问题在于部分本地适配改变了语义，以及增强请求策略影响到了旧卡。

采用一套执行器、两种明确的协议策略。无声明的卡走 legacy；主世界书有效声明 `[nora_mvu/1]` 才走 Nora。Zod 的有无不是协议选择条件。保留旧卡自己的变量结构，不迁移卡或存档。

## 本次实现的界限

| 环节 | 旧卡 | Nora 声明卡 |
| --- | --- | --- |
| 模型任务与返回格式 | 保留旧任务和旧格式；不要求输出 NoraMvu | 使用统一 Nora 协议及可表达的字段约束 |
| 外部世界书 | 恢复固定版本原 MVU 的全局、聊天、Persona 世界书筛选规则 | 保留未标记的共享事实；继续区分剧情与更新条目 |
| 额外模型状态补充 | 不额外安装 Nora 的状态块补充监听器 | 保留状态块补充 |
| 命令执行 | 共用原 MVU 执行器，保留原命令路径 | 结构化协议转换后进入同一执行器 |
| Zod 新建容器 | 修复为先尝试对象，再尝试数组，由 schema 校验决定 | 共用修正后的适配器，仍先检查 Nora 操作约束 |
| 批内有成功也有失败 | 保留已接受的结果，后台记录数量与拒绝原因，不显示“部分更新”提示 | 拒绝整批候选，按既有预算纠正 |
| 保存、切世界、替换回复 | 共用保存确认、过期结果阻断、旧快照保护 | 相同 |

没有新加另一套插件或协议翻译框架。没有修改用户卡、模型配置、已有测试对话、主分支脏文件。没有修改重试预算，没有添加提示词段落。聊天补全适配器和 Tavern Helper 仍由宿主提供，不能因此宣称整个 ST 环境相同。

### 为什么不全部换回原核心

1. 已识别的容器创建错误位于本地 Zod 适配器，不是更换命令执行核心就能自动消除。
2. 上下文污染位于请求筛选/补充阶段；只替换执行器也不会解决。
3. 保存确认、切世界隔离、去重、重试从上一轮快照计算、失败保留原回复等属于宿主的可靠性能力，直接丢弃会恢复这些风险。
4. 双份核心会增加状态写入、事件触发和插件生命周期冲突的机会，还要持续维护两套版本。

因此应恢复确实改变旧卡语义的部分，而不是按“凡修改皆删除”处理。

## 证据与验收范围

先新增失败回归，复现了两项缺陷：缺失对象/数组容器的 insert 被错误拒绝；旧卡请求仍受到 Nora 状态补充和外部世界书策略影响。然后修改实现，验证旧卡/Nora、内联/额外模型、有无 Zod、六种操作、保存失败、切世界、重复事件、失败重试保留快照等路径。

离线对照回放采用原测试卡实际使用的上游 beta `4a3645f19705e9e73bb4df3a8e731d5ff994ce80` 及其 Zod 辅助脚本，与本分支比较相同初始状态和相同模型返回文本：

- 冻结的 9 条 ST 更新 + 1 条 Nora 更新，最终状态全部一致，也与各自原有保存结果一致。
- 两个针对缺失档案/列表的新增反例，修复前本地拒绝、上游接受；修复后状态一致。
- 无效枚举反例仍拒绝非法字段，同时保留该批合法更新，与原版状态一致。

这些是对已有输出的回放，不是重新调用模型的 10 轮，也不是成功率统计。9 条 ST 样本中有 7 条实际包含被拒绝的操作；原版关闭错误通知时看起来正常，不能将其计为全部操作成功。反过来，这也不能把 Nora 的问题都归结为显示：两个插入反例是真实语义缺陷。

当前 Nora 执行源固定于 `7fe9ae7cfe01f13d606f7a2e533a458431fe318c`；未悄悄升级为 beta。对照通过不等于两个版本所有功能相同。

## 尚不能宣称解决的边界

1. 原卡自定义回调若消耗命令却不提供结果证据，revision 18 允许按原回调结果保存一次，后台保留 `MVU_EXECUTION_UNVERIFIED`，不宣称全部命令被接受，也不因缺少 Nora 计数而重试。Nora 声明卡仍拒绝此类未验证结果。仍不能宣称任意第三方脚本完全兼容。
2. revision 18 仅对 Nora 声明卡要求 Nora schema 注册。旧卡由原脚本维护 Zod 生命周期，不会因为未实现 Nora 专属事件而阻断；这不等于保证任意外部脚本能正确加载。
3. 本地值解析不恢复上游辅助脚本的任意 JavaScript 求值；安全边界与原实现有差异。
4. 保存文字和变量不是数据库原子事务；保存确认失败仍报告不确定，不自动重放增量。
5. revision 18 恢复旧协议的 system 示例清理规则，Nora 声明卡继续保留示例。事务重试等仍有有意差异。不能声称整条请求逐字一致。
