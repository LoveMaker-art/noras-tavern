# 启动器稳定性整顿验收

本轮集中处理安装、更新、恢复和卸载的关键风险。源码验收与最终安装包验收分开记录；本轮禁止打包、推送和发布。正式用户版本仍是酒馆 2.4.5／启动器 2.1.2，当前修改属于未发布的候选源码。

## 必须满足的结果

| 范围 | 必须兑现的结果 | 阻断条件 |
| --- | --- | --- |
| 安装与更新 | 消费实际封存计划；执行结果须由维护记录和后端验收确认 | 清单、来源、目标实例、实际版本或权威记录不符 |
| 结果显示 | 展示缓存写失败或结构损坏不改变真实维护结果；重开后用同实例记录恢复显示和端口 | 无法确认权威端口、服务状态或维护结果时，不猜测成功 |
| 恢复与重试 | 保留原始失败、原固定目标、失败现场及用户数据；重试沿用真实预算 | 未确认恢复、身份变化或次数耗尽时，不增加写入 |
| 保留数据卸载 | 停服并保持互斥；保留用户数据、凭据、配置和备份 | 未完成事务无法安全保留、服务未停或归属不明时，不删除 |
| 彻底卸载 | 两次确认当前根；旧恢复证明缺失不永久阻断清理；删除前持锁再次检查现场服务 | 当前根、APP、维护执行器或服务离线无法确认时，保留文件 |

## 本轮具体修改

- **结果与缓存分开**：`installer/state.json` 无法写入或字段损坏时，保留真实维护结果及本机缓存警告；操作记录和后端验收失败仍会阻断。模型保存后 checkpoint 失败也保留已保存事实与原始原因。
- **重开和恢复显示**：先使用当前实例或同实例已确认维护记录确定端口；成功安装／更新／修复，或已核实回退后，必须再与实时目录、版本、commit、端口及就绪状态匹配，才能清理旧界面错误。原始失败、事务和故障证据不被删除。
- **写入确认丢失**：真实提交已经落盘但 ACK 丢失时，确认 writer 和执行器闭合后，仅在同操作身份、epoch 和固定目标匹配时同步返回快照序号。结果仍为失败、未确认和未知，保留原始原因；不伪造成功、自动重试或放宽并发检查。
- **卸载历史与现场分开**：KEEP 继续保护未完成恢复；ALL 可清理已确认当前安装的旧事务残留。辅助程序接管 writer 后重新确认服务离线，避免停服与删除之间的重启空档。未知端口的 ALL 只能使用只读现场归属检查，不能猜端口。
- **卸载归属检查**：缺 Python 不再等同于无法清理，也不等同于服务离线。绑定当前源码／APP 资源，检查实际端口和进程；中文路径严格解码。Mac 环境变量绑定的外部 Hermes 后台、内联入口，以及 Windows 相对或未知入口无法证明与目标无关时，保留文件。
- **验收执行与门禁**：新增真实故障回归并接入三平台运行环境准备之前；旧 Windows 制品复用也必须证明该门禁成功。源码 runner 使用绝对入口；Windows 测试先停并等待自己的子进程，再删除目录。需要托管 Python 的 fixture 创建并核验独立真实 venv，不将系统解释器冒充托管环境。

## 源码验收入口

```sh
node "$PWD/tooling/checks/verify-launcher-stability.mjs"
```

使用既有锁定的桌面依赖与独立测试 Python；原生进程检查需 `psutil==7.0.0`，恢复检查需 `PyYAML==6.0.2`。CI 构建 job 独立安装这两项测试前置，不能借用另一个 preflight job 的环境。入口通过现有 `tooling/run.mjs` 创建隔离的真实源码投影，逐项运行计划消费、操作结果、缓存故障、修复重试、目录事务和卸载回归。任何非零退出、信号终止或工具超时都阻断后续检查。

该入口接入三平台构建的运行环境准备之前，失败不能由 `continue-on-error`、过滤测试或绿色上传步骤覆盖。复用已构建 Windows 制品时，也必须有这一步明确成功的来源证明。门禁本身由 `tests/launcher-stability-gate.test.mjs`、`tests/release-workflow.test.mjs`、`tests/launcher-windows-reuse.test.cjs` 验证。

源码 fixture 使用真实临时文件、生产计划与维护模块；部分执行依赖仍由 fixture 提供。它不能证明新 Windows NSIS、Mac App、自更新交接、三平台首装和保留后重装已经可用。

## 本轮验证记录（2026-10-12）

Mac 最终统一入口退出 0：13 个 Node suite 共 **472 项通过，0 失败／跳过／取消**；4 个 Python 模块共运行 111 项，**110 项通过、1 项 Windows 原生路径检查跳过**。Node 部分约 135.6 秒，Python 部分约 5.0 秒。实际进程与临时磁盘故障覆盖缓存不可写、损坏缓存、确认回退重开、提交 ACK 丢失、固定目标重试、历史残缺、停服后服务重现、中文目录及误删边界。

Windows 在对应源码投影中运行相同 13 个 Node suite 和 4 个 Python 模块，两组均退出 0：Node 共运行 472 项，**469 项通过、3 项 POSIX chmod 权限检查跳过**，约 162.8 秒；Python 运行 111 项，**108 项通过、3 项平台专属检查跳过**，约 21.9 秒。Python 跳过的是需要 Windows 特权的符号链接创建、由真实 Windows 长路径用例代替的模拟路径限制，以及 POSIX 权限恢复。真实 Windows 长路径恢复参与本次检查；跳过项没有算作通过，Mac chmod 的结果也不能证明 Windows ACL 行为。

独立复核发现的 Mac 外部 Hermes 归属漏判和 Windows 系统 Python／managed venv fixture 错配，均以定向回归修正。Windows 普通 source Python 的旧 fixture 先实际失败（`ENOENT`，尚未到 checkpoint）；相同普通 source Python 已确认依赖前置后，最终测试创建真实临时 venv 并成功验证保存后的 checkpoint 故障，571.96 毫秒、没有跳过。Windows source Python 和 venv 都位于本轮独立测试目录；未修补失效的旧测试路径或用户安装。最终门禁、工作流、源码布局和复用检查 **72 项全部通过**，包含独立 job 的 Python 依赖前置和新的操作状态回归。

失败记录同样保留：较早 Mac 门禁曾因 metadata 场景的旧快照失败；真实 native commit 丢 ACK 可重现该 CAS 症状，但原失败缺少 guard secondary，不能断言具体触发原因。新回归保留此类详情。较早 Windows 331 项运行包含失效测试 Python 路径、1 项跳过和活进程清理顺序错误，不作为最终通过证据，也不把它们归为产品故障。

本机原始日志及摘要：verification-result.json（原私有证据位置：`../../artifacts/launcher-stability-20261012-1791780374036/verification-result.json`；当前工作树未保留）。其中绑定当前未提交源码摘要、Mac／Windows 原始日志及校验值；不将旧源码投影摘要冒充最终源码摘要。证据目录被 Git 忽略，不进入发布源码。Windows 使用官方 Node 24.21.0 和独立 Python 3.11.16，Mac 使用真实 Node 24.19.0 和独立 Python 3.12.14，测试依赖为 psutil 7.0.0／PyYAML 6.0.2；不是系统中的 Bun shim。

## 放行前仍需的最终制品验收

未来获准构建后，每项证据必须绑定该次固定源码和最终安装包字节：三平台首装及真实启动、最近正式旧版运行／停止两种状态更新、用户数据保留、故障恢复、KEEP 后重装、ALL 实际删除范围，以及最终下载清单消费。源码通过不能替代这些证据，也不能追认旧候选包的失败为成功。

剩余放行阻断：

- 没有新最终安装包的三平台真实用户流程证据。本轮按授权未打包、提交、推送或发布；CI 接入已通过配置验收，但没有远端实际三平台运行结果。Windows ACL 故障恢复也不能借用 POSIX chmod 的通过结果。
- 真实公网更新超时根因仍未闭合。此次本地网络 fixture 证明固定资源、重试预算和失败处理；测试机 SSH 的间歇性连通变化不能证明 launcher 下载超时是同一个故障。
- 早期启动及退出后卸载的诊断盲区已在后续源码收敛中接入持久队列，并经 Windows／Mac 与真实本地 Worker 验证；详见 [产品收敛对账](launcher-product-convergence.md)。修改未发布，不能宣称正式用户诊断链已更新或所有历史事故已经关闭。
