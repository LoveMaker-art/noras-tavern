# 剧情账本运行治理设计

状态：独立分支 `codex/ledger-runtime-design` 已实现、完成针对性技术验证，并经授权备份同步到本机启动器 8799；插件清单和账本设置已完成浏览器流程验收。未合并、未推送、未发布。真实模型压缩质量和 Windows/koboldcpp 验收仍未完成。
基线：本地 main `688bc5e1478070b1b395754f2740546e3abb6342`。
工作分支：`codex/ledger-runtime-design`。

## 1. 用户结果与范围

剧情账本帮助长聊天保持记忆，但不能因为后台整理拖累正文，也不能在用户关闭后继续重试和写入。用户能知道当前会话是否正在整理、为什么失败、配置依据是什么。

保留：原始聊天、active/pending 区分、历史签名、实体与 JSON 校验、历史保护、备份恢复凭证、世界及会话隔离、现有扩展窗口。
修改：后台任务生命周期、预算、失败策略、状态与配置入口、对应 MCP 与技能说明。
不自动修改：已有世界的 enabled 状态、已经生效的记忆、聊天、角色、世界书、MVU、模型连接或密钥。
暂不包括：替换账本存储格式、引入向量数据库、专用记忆模型、自动探测所有服务、全局请求代理、大规模数据迁移。
重置记忆是独立数据操作；其实施与验收不能混入默认升级迁移。

## 3. 配置窗口

入口保留在扩展管理中，名称统一为“剧情账本”。保留其他扩展的处理器、安全授权和专用入口。

常规区域：

- “自动整理”开关，按当前世界/会话生效；开启有费用确认。
- 单行运行状态：等待空闲、排队、整理中、取消中、已关闭、失败暂停、无需整理。
- “已使用记忆覆盖 N 轮”；待用结果单独显示，不冒充已生效。
- 上下文容量：默认继承当前模型；显示容量与来源，例如“8192 · 模型配置，服务未核实”。
- 失败暂停时显示有明确动作名称的“重新整理”，并说明可能产生模型费用；状态读取重试与模型重试必须区分。

高级区域折叠：上下文容量覆盖、压缩输出上限、总超时。使用数字输入，不能使用任意 JSON 文本框。容量覆盖是本会话的预算声明，不自动修改模型服务容量。

高级区域之外独立放置低强调的“重置剧情记忆”，明确不删除聊天，有影响预览、确认和备份。不存在静默批量重置。

关闭操作必须可以取消当前会话的后台整理；如果正文在生成，取消不能中止正文。对开启、预算修改和重置仍需遵守正文生成与保存保护。
窗口关闭不等于后台任务取消；关闭窗口不得隐式保存未提交配置。状态使用现有刷新机制或限频轮询，离开窗口后停止轮询。
布局沿用现有 plain-sheet、setting 行、主题变量；不嵌套卡片、不增加单独大号操作栏。手机数字字段允许换行。

## 4. 配置所有权

所有入口共用后端配置与状态，前端和 MCP 不另存一份。
会话配置可缺省并继承软件默认：enabled、contextLimitOverride、outputTokenLimit、timeoutSeconds；更新采用 patch，未提供字段不重置。
初始建议：outputTokenLimit=2048，timeoutSeconds=300，超时允许 60 至 1800 秒。最终默认值需按真实压缩质量验证，不是模型通用保证。
保留已有 enabled 和 active；新配置字段使用兼容默认，不批量重写旧数据。

模型配置在任务启动时读取并形成私有不可变快照，至少包含 endpoint、model、上下文声明和必要连接参数。不能在等待队列后误用用户已切换到另一世界的模型。
若当前全局 oai_settings 无法证明对应目标世界的模型，应通过现有世界/模型绑定解析；无法解析时拒绝后台调用，不新增另一套模型资料库。
配置 revision 用于 UI/MCP 防止旧页面覆盖。模型连接或关键预算改变后需要使旧任务结果失效。

## 5. 上下文预算

容量来源：显式会话覆盖或当前模型配置；服务真实容量仅在有可靠适配器时读取。双方已知时取较小值。无法确定容量时暂停，不根据模型名称推断、不默认按 50000 发送。
第一版不承诺自动探测 koboldcpp；先正确使用配置值并标注未核实。

预算算法：

```text
C = 有效上下文容量
O = 压缩输出上限
S = 分词器不匹配与消息包装的保守余量
F = 实际序列化的规则、旧账本、实体、消息包装等固定输入
聊天可用预算 = C - O - S - F
```

优先使用现有匹配分词器；仅有估算时显示估算来源并采用更大余量，不能声称精确计数。
所有重试都重新计算完整 messages，包括纠正提示。固定输入已超限时返回明确预算错误，不继续尝试。
仍按 15 轮确定候选范围，但按预算分段；每段必须保留完整证据，并在下一段重新计入增长后的账本。
单轮过大时，先实现明确的暂停错误，不静默截断、不凭空跳过；若要实现跨段长单轮，需要另行验证回合边界与合并语义。
只在当前候选完整处理且校验通过后发布；中间失败不把部分覆盖冒充完整覆盖。
输出被 length 截断归类为预算/输出不足，不仅作为通用 JSON 错误重复同一请求。
不沿用正文 400 tokens 限制，也不强迫模型把上下文容量更改为配置值。

## 6. 可取消任务与正文优先

沿用 core 管理账本数据，提取一个负责账本任务生命周期的 scheduler；merge 接收 signal 与预算后的调用快照，不独自决定重试和总期限。
使用 AbortController、有限队列和任务 epoch。关闭必须取消排队、取消运行、阻止重试及迟到发布。重新开启后旧任务仍不得发布。
取消结果不得覆盖较新的配置和错误状态；主动取消不是 compression-failed。
模型 I/O 不持有聊天写锁。状态查询不能触发模型或修复写入。

利用既有正文生成活动协议接入调度，不另建一套聊天活动状态：

- 第一版保持每用户一个后台压缩槽；用户任何正文生成活动均阻止新的后台压缩，避免不可靠地判断共享模型。
- 同一服务端点上的正文开始时要求后台压缩让出，取消完成后才授予正文调度许可。
- 网络断开不等于上游计算停止；对 koboldcpp 实测取消传播。无法确认停止时按服务端点资源策略等待有限释放时间并明确反馈，不能宣称绝对不并发。
- 正文活动释放必须覆盖成功、异常、停止、页面断开和租约失效；已有生成/保存保护不能被替代或削弱。
- 排队不能持有会话恢复锁；恢复可以先撤销未执行任务。运行中的任务须取消并确认不再发布后恢复。
- 不在每次 status/poll 或失败时重新入队；正文成功保存且达到条件、显式启用/重试是受控触发点。

如现有活动协议不能覆盖正文前的服务端请求许可，应先补足这个明确边界，不为整站所有第三方插件建设通用请求代理。

## 7. 错误与重试

一个候选任务最多两次模型尝试，共用总期限；第一版宁可暂停，不追求高次数重试。
JSON/实体校验失败允许一次纠正；临时 429/5xx 可在剩余次数内退避，429 尊重 Retry-After 且不能超出总期限。其他 HTTP/configuration/budget 错误直接暂停。
任务终止后记录失败批次签名及配置 revision；相同证据与配置不会因刷新、保存或重启再次自动请求。
新历史出现也不默认解除模型配置错误；显式重试或相关配置更改才重新评估。已应用记忆与原始历史保持可用。
“重新整理”有模型费用确认、幂等键、并发保护；重复点击不能绕过熔断创建并行任务。
失败摘要保存 errorCode、阶段、尝试数、耗时及时间，不保存模型原文。

## 8. 重置语义

按当前世界/会话执行，默认同时关闭自动整理，避免清完马上自动重新生成。
等待正文/保存结束，取消后台任务，取得会话独占保护，备份并写入新的记忆 epoch/恢复凭证，再清 active/pending/失败状态及对应派生投影。
历史解锁只在没有发送中 reservation 且原聊天完整可读时完成。后续重新读状态，不继续使用前端缓存的旧账本。
原文超过当前上下文时，预览明确提醒，不承诺模型会看到全部旧历史；使用既有上下文处理，不引入静默额外删减。
跨文件无法原子提交时，应有可恢复事务凭证，不能留下聊天已解锁但旧账本继续有效的半状态。
本操作实施需要单独的数据行为验收；不得作为升级时自动执行的清理。

## 9. MCP、技能与日志

扩展现有 nora.ledger.configure 参数，保留旧 enabled-only 调用；status 返回 effectiveConfig、capacitySource、taskPhase、暂停原因及覆盖范围。
compress 仍是调度请求，不返回“已压缩”假成功；与 UI 使用同一失败暂停和费用边界。
重置若实施，增加唯一 nora.ledger.reset，要求准确 scope、revision、confirm 和明确重置授权；不能复用删除世界接口。
技能只修改现有 chat-ledger.md 的操作规则，不新增重复长篇主技能。说明关闭保留生效记忆、重试收费、reset 不删聊天。

沿用已共享的脱敏日志写入与轮转，不新建第二套基础日志框架。
记录 task/request ID、world/session、正文或账本类型、阶段、预算/计数来源、排队与调用耗时、终止原因、finish_reason。
不记录密钥、完整 URL 查询参数、提示词、账本内容、回复原文。状态可关联日志编号。
请求跟踪是独立定位正文 120 秒截断的必要证据；本设计不预先断言截断来源。

## 10. 实施顺序与验收

1. 在受控服务与虚拟时钟测试中锁定取消、预算、有限重试和迟到发布问题。
2. 实现 model 的 signal/预算输入、core 的生命周期与失败暂停，再接入现有正文活动边界。
3. 完善现有窗口、MCP 和短技能说明；不部署前先验证行为一致。
4. 另行实现并验证重置操作的备份和中断恢复。
5. 用户授权后部署本机；再由同类 Windows/koboldcpp 环境验证慢模型和取消传播。

必须通过：

- 174 秒等慢请求不在 120 秒被账本硬截断，总期限到达会明确结束。
- 8192 配置下序列化请求加输出、安全余量不超预算。
- 单轮过大、旧账本过大、纠正提示超限、finish_reason=length 都有确定结果。
- 排队关闭、运行关闭、快速关闭再开启、配置切换、世界切换、正文开始、重启，都不发生旧任务发布或重复收费循环。
- 正文优先且取消不杀正文；不同世界不会通过同一服务端点互相争用后台槽。
- 不合规 JSON 最终暂停，刷新和原聊天保存不解除熔断。
- 旧 active、原始聊天、历史签名、恢复及 MVU 的保护回归通过。
- UI 与 MCP 更新同一配置，旧 enabled-only 调用有效，未传字段不重置。
- reset 有备份、无聊天删除、没有旧引用，故障可恢复。
- 日志可追踪原因且不泄露原文/密钥。

证据级别分开报告：源码分析、实现、受控验证、本机真实流程、Windows/koboldcpp 实机验证、部署。未完成的级别不得用测试数量代替。

## 11. 实施结果与边界（2026-10-01）

已实现：默认总任务期限 300 秒、可配置上下文上限/输出上限/期限；完整轮次拆分与请求预算检查；取消及迟到结果发布保护；正文生成优先；失败后停止自动反复调用；现有配置窗口和 MCP 参数对齐；备份后重置记忆；复用共享日志写入器记录脱敏诊断。

配置更新使用版本检查且只修改传入字段。关闭不删除生效记忆和原聊天；重置是单独确认操作，不在升级时自动执行。状态查询不调度模型。模型每个拆分请求最多两次尝试，整个整理任务共用总期限。

技术验证：95 项账本、聊天保护、HTTP 路由及客户端相关测试通过；15 项 MCP 控制与真实 stdio 发现测试通过；MCP 构建、后端相关文件 ESLint 检查通过。另以本地 HTTP 假服务实际等待约 125 秒后完成请求，验证账本适配器不再在 120 秒切断；没有使用真实模型额度。

当前限制：

- token 预算仍用项目已有保守估算，加 15%（至少 512 token）余量，不是模型匹配分词器的精确计数；没有自动探测 koboldcpp 服务容量。
- 上下文配置优先继承现有模型配置；手工上限只能收紧已知配置，不能替用户扩大服务容量。
- 使用现有活动世界标记检查模型作用域；标记缺失时沿用原有全局模型配置，不是新增一套完整的逐世界模型解析器。
- 日志包含预算来源和任务阶段；状态接口提供 effectiveConfig/taskPhase，以及目标世界作用域内的模型名称和配置容量。界面明确标为“模型配置容量”，不冒充服务探测值。窗口已完成本机桌面和手机宽度浏览器验收。
- 网络请求失败会进入暂停，避免自动付费循环；429/5xx 和格式纠正仅做有限尝试。
- 已验证客户端取消与迟到写入保护，未验证 Windows/koboldcpp 是否在连接取消后停止实际推理；用户正文被截断的 120 秒来源仍需真实请求链追踪，不能认定与账本是同一路径。
- 一个旧集成契约测试依赖酒馆助手压缩产物的旧变量名，main 的同一产物也不符合该断言；未修改无关产物来掩盖该基线问题。

本机运行文件已备份并替换；原世界、角色、世界书与聊天文件未修改。真实模型验收和 Windows 实机验收尚未执行。

## 12. 插件清单与配置交互复核（2026-10-01）

本轮将内置插件定义和状态解释集中到一个共享目录投影，供后端插件库、扩展管理和侧栏使用。五个内置插件固定显示，包括默认启用的剧情账本，不再依赖当前世界声明或历史启用记录决定是否出现。用户第三方插件来自同一清单；基础设施模块仍不作为用户插件展示。

安装、启用、当前页面加载和当前世界使用是不同状态。库读取完成后将同一加载快照通知侧栏，避免启动初期的旧快照与后来打开的管理窗口相互矛盾。读取和展示不触发脚本授权或模型请求。

账本设置采用当前世界/会话窗口，显示自动整理、运行状态、记忆覆盖、模型名称和配置容量。高级设置默认折叠，保存按钮随高级设置出现；重置是独立确认操作。保存完成后读取后端结果，更新基线和 revision，支持连续保存；失败保留输入，未保存退出需要确认。正文生成期间禁止启用、修改预算、重试或重置，但允许关闭后台整理。状态轮询不覆盖草稿，离开窗口或切换世界后停止。

针对性验证：9 个测试文件共 116 项通过，覆盖共享插件清单、账本设置、插件库、侧栏、HTTP 路由、运行策略、原有编辑入口和对话框保护；改动 UI 控制器 ESLint 和前端构建通过。此前的后台慢请求验证见第 11 节，本轮没有调用真实模型。

本机浏览器实际验收范围：

- 仅操作“MCP验收0930普通”会话；三处均展示相同的五个内置插件及加载状态，普通世界未因此启动酒馆助手或 MVU。
- 从插件库详情进入扩展管理，再进入剧情账本设置，入口可达。
- 默认自动整理开启；实际模型名称和配置容量正确显示。
