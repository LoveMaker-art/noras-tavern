# 启动器面向用户的错误说明

2026-10-01，在 `codex/launcher-error-diagnostics` 实现。范围是把操作失败、模型反馈、日常状态警告及更新检查中的技术报错转换成中文说明；保留原有操作、重试、返回、继续同步、日志入口和服务控制按钮。没有新增诊断授权方式，也没有改变基础统计与详细故障包的采集边界。

## 用户看到什么

已知错误展示三部分：问题名称、当前影响、下一步建议。例如：

> 无法确认酒馆进程归属。
>
> 启动器没有接管或结束这个进程。
>
> 请保留当前进程和日志，勿按提示中的 PID 强行结束程序。

> 模型已验证，酒馆同步未完成。
>
> 配置已保存，尚需完成酒馆同步。
>
> 请选择“继续同步”，无需重新填写 API Key。

操作失败卡片把第一行作为标题，其余行作为说明；模型反馈和状态提示保留换行。退出停止失败对话框也使用同一套说明，原有选择不变。更新检查仍保留版本、可更新状态及阻止安装的兼容性要求，包括要求的最低启动器版本。

这些说明依赖固定业务错误码、系统错误码、HTTP 状态及来源，不从任意日志文字猜测根因。已知分类不代表已覆盖所有故障。未知错误显示“原因尚未确认”，保留安装和数据并引导查看日志；不会断言已回滚、权限不足或缺少依赖，也不建议反复卸载重装。

## 当前分类

18 类技术情况：

|证据类别|用户说明或建议|
|---|---|
|权限拒绝|检查所需文件访问权限及明确的安全软件拦截提示|
|文件或目录不存在|检查安装盘、目录及安装包完整性|
|磁盘空间不足|清理安装盘和系统临时目录所在磁盘|
|DNS 失败|核对网络、地址和代理|
|连接被拒绝|检查目标服务是否运行及地址、端口|
|连接中断|检查网络和代理后重试|
|TLS 证书错误|检查日期和证书，保留安全校验|
|超时|先确认当前运行状态，保留安装和备份|
|取消|确认状态后决定是否继续|
|HTTP 401|模型服务检查 Key；更新服务反馈访问问题，无需修改模型 Key|
|HTTP 403|模型服务检查账号及模型权限；更新服务检查访问限制|
|HTTP 429|稍后重试并检查服务配额|
|其他 HTTP 异常|服务异常；5xx 明确建议稍后重试|
|无法识别的响应|核对接口，持续异常时保留日志|
|空响应|核对接口和模型名称后重试|
|响应过大|核对接口，持续异常时保留日志|
|完整性或兼容性校验失败|使用对应系统的完整包，保留安装和数据|
|窗口意外退出|重新打开并确认后台任务和服务状态|

11 类业务情况：

|固定码|用户说明或建议|
|---|---|
|`TAVERN_OWNERSHIP`|无法确认酒馆归属，没有接管或结束未知进程|
|`GATEWAY_IDENTITY`|无法确认 Nora 后台身份，没有启动第二个后台；重启后复核|
|`TAVERN_PORT_OCCUPIED`|预定端口占用；检查已有酒馆，不随意结束未知程序|
|`TAVERN_UNHEALTHY`|启动检查未通过，尚未确认酒馆可用|
|`UPDATE_RECOVERY_REQUIRED`|上次更新需恢复；保留目录和备份，通过恢复提示处理|
|`MODEL_SYNC_PENDING`|配置已保存，可继续酒馆同步，无需重填 Key|
|`PAIR_CODE_REJECTED`|配对未完成；获取新配对码，不反复提交相同码|
|`NODE_UNAVAILABLE`|自带运行环境不可用；使用完整安装包修复|
|`RUNTIME_EXTRACTOR_UNAVAILABLE`|Windows tar 与 PowerShell 均无法启动；检查系统组件，保留现有安装和数据|
|`RELEASE_COMPATIBILITY`|发布暂不可安装；保留具体版本要求并提示完整发布包|
|`LOG_OPEN_FAILED`|系统无法打开日志；通过安装信息打开目录，或检查系统的文件打开方式|

业务码优先于通用技术分类。例如 Gateway 身份检查可能同时有 `EACCES`，用户看到身份保护说明，开发诊断仍保留权限拒绝证据。源文件 `error-presentation.js` 集中管理说明，Python 生命周期、服务与桥接提供固定业务码。

## 原始证据与展示分离

主进程在向界面转换说明前保留原始异常及原因链，已有本地诊断器负责脱敏、限制大小和日志轮转。错误说明不会改写原始 Error。Electron 的 `ipcMain.handle` 抛错只向界面传递 message，因此在该边界前完成分类。依据：[Electron 官方 IPC 文档](https://www.electronjs.org/docs/latest/api/ipc-main#ipcmainhandlechannel-listener)。

更新检查返回失败结果而没有抛错时，也先保存 `diagnosticError` 再转换提示。状态轮询的同一错误只记录一次；正常状态恢复后再次出现会重新记录，避免持续刷日志。旧界面接收到未转换的英文异常或堆栈时，使用保守中文提示，不把技术转储直接作为主说明。

本地日志是尽力记录：磁盘不可写、强制退出等情况仍可能缺少证据。详细故障包继续仅在主动授权后采集；基础阶段、耗时和运行状态继续按既有要求上报。详见 [诊断设计](launcher-install-diagnostics.md)。

本轮 73 项 Node 回归、57 项 Python 回归通过。覆盖技术码映射、模型与更新认证区分、未知错误、业务优先级、真实 IPC 注册回调、渲染器文案拆分、更新阻止结果与最低版本、状态日志去重、桥接业务码传递，以及既有退出、模型恢复、归属与生命周期保护。清单请求的 403 或超时按技术原因提示，只有明确的更新清单校验或最低版本拒绝才附加兼容性业务码；不因失败结果位于 `compatibilityError` 字段而建议升级启动器。

证据等级为源码已实现、相关技术验证通过。测试没有执行完整 Electron GUI、Windows 打包实机或发布验收；本轮没有替换已安装启动器、发布安装包或部署接收端。此前授权应用的本机 Node 归属热修复是独立交付，不能证明这里的新提示已在已安装 GUI 中生效。

## 日志反馈与状态不可用补齐（2026-10-01）

“查看日志”现在处理失败返回和异常，在原恢复页显示反馈，保留恢复说明、备份位置及原按钮。系统打开文件失败保留原始原因链；界面显示中文建议。成功仅表示已请求系统打开文件，不断言用户已看到文件。

状态查询失败返回 `statusUnavailable`，不再返回合成的“已停止”和“安装需修复”事实。首次安装尚未具备运行环境时继续使用原安装探测；已有酒馆但缺少查询所需 Python 时明确视为查询失败。

界面保留最后确认的安装信息，但将当前服务标为“状态未知”，显示自动重新查询提示。暂时禁用服务控制、酒馆打开及 ClawChat 运行入口，保留更多和安装信息入口；不据旧快照自动启动或升级。原 5 秒轮询不变，查询恢复后自动恢复日常状态与按钮。模型表单、未保存输入和恢复页内容不因轮询异常被清空。

这次追加的 64 项 Node 定向回归通过，包括 6 项新增故障与恢复回归。使用实际控制器函数、恢复页按钮回调及主进程状态/日志 IPC 回调，在隔离 DOM/API 夹具中复现并验证；不是 Electron GUI 实机或视觉验收。未修改本机安装、打包、发布或部署接收端。
