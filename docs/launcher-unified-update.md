# 统一更新

用户仍只看到一个版本检查入口和一个更新按钮，不需要区分酒馆更新与启动器更新。

## 执行顺序

1. 选定一个发布版本，读取同一发布的系统清单。
2. 如果需要更高版本的启动器，获取对应平台的轻量 ZIP 和校验清单。先检查兼容性、文件大小和 SHA-256，再准备替换。
3. 现有 Hermes Python 启动独立替换进程。程序校验并解压新应用，旧启动器才退出。程序目录先改名保留，新程序原位接替。不会移动 Hermes 或酒馆目录。
4. 新启动器加载页面后确认启动，并自动继续同一个发布版本的组件更新，不再次选择最新版本。
5. 酒馆更新仍走共享更新器。没有变化的模块不下载、不替换。

## 更新事务与失败恢复

启动器不再先停服、更新完成后再独立启动。它把原运行状态交给共享更新器，由同一个事务依次执行备份、停服、文件替换、实例验证、恢复运行状态与最终健康检查。文件替换不等于更新成功。

- 两个服务原来都运行、只运行一个或都停止，分别恢复对应状态。此前 ClawChat 已连接时，恢复后也必须确认连接。
- 最后启动或完整性检查失败，与文件替换失败进入同一回滚路径：恢复程序、配置、安装记录及事务涉及的世界数据，再检查旧服务状态。
- 回滚后旧服务仍启动失败，记录 `files-restored-start-failed`，不声称已恢复可用。
- 下载及兼容性检查在停服之前；不支持 `bootstrap.managedLifecycle: 1` 的更新目标拒绝执行，不以不完整的恢复能力继续覆盖文件。新事务要求启动器至少 1.1.0。
- 受管更新执行期间，取消和外层超时不强杀事务进程；保留处理状态和日志。内部启动验证有超时，失败交回事务处理。
- `tavern/tavern-updates/transaction.json` 记录提交或恢复结果及备份路径。未完成、恢复失败或损坏的事务记录会阻止普通启动和重复更新，避免覆盖恢复现场；不会转成首次安装。
- 日常状态和启动读取已完成的安装验收记录，不比较技能、Hook、示例、定时任务等文件与安装时是否一致；用户修改不会触发同版本修复。显式安装、更新仍执行交付验收，不通过重写校验值掩盖失败，也不降级。

## 安装验收与日常启动

- `installation_state` 只读取历史验收与安装阶段记录。周期状态查询不调用 `inspect` / `files_ready`，不重新计算技能哈希。
- `inspect`、`verify_runtime` 保留给显式安装、首次配置完成及更新事务验收。历史 `setupCompleted` 不因用户改文件而清零。
- 配置完成后的普通启动只启动对应进程并核对运行结果；不以安装器旧的模型验证缓存阻止手工配置后的启动，不重验固定技能和任务，不强制执行被用户禁用的注册 Hook，也不重新初始化联系人资料。Gateway 按用户当前配置加载 Hook 和模型，实际启动错误照常报告。
- 酒馆底层普通启动与重启不自动执行安装、依赖修复、源码标记验证或扩展复制；缺少启动入口、配置或实际启动失败会报错，不静默恢复文件。显式 `install` / `sync` 和安装验收保留准备资源的能力。
- 未完成的更新事务、错误实例、端口冲突和实际启动失败仍受保护。已完成安装的日常启动不等于新交付验收，更新不能仅凭历史成功记录宣告成功。
- 本次不调整受控更新清单和覆盖策略；用户明确执行更新时仍按现有清单交付。测试不代替打包后目标机器的启动验收。

异常断电、系统强杀和磁盘故障不保证即时自动回滚。当前会在下次读取时拦截未完成事务、保留备份供恢复，不会自动猜测并覆盖现场。启动器自身替换仍是独立事务：程序启动确认成功后，系统更新失败不会把启动器一并降级。

验证覆盖文件事务、最后服务检查失败、旧服务恢复失败、停止状态保留、损坏记录及真实 Python 子进程通信。服务进程和外部连接在这些测试中为隔离替身，尚不代表三平台用户环境的升级验收。

不需要更新启动器时，直接执行步骤 5；酒馆已是目标版本、只有启动器过旧时，不重装酒馆。不会自动降级。

## 保留与回退

- 保留原数据路径、密钥、世界、聊天。重启通过已有的 `NORA_TAVERN_HOME` 支持指定原安装，不迁移数据。
- Windows 原位替换程序目录，保留 NSIS 卸载程序和已有卸载注册。需要当前用户对程序目录有写权限；无权限时在退出前报错，不自动提权。
- Mac 保留应用路径，校验应用标识和代码签名；Apple 芯片和 Intel 使用各自的包。
- 新程序未在限定时间内确认启动，回退旧程序。回退也失败时保留旧程序备份并记录路径，不删除数据。
- 启动器替换成功后，若酒馆更新失败，保留新版启动器，显示失败并允许重试。酒馆文件回退由共享更新器负责，不把两个回退事务混成一个。
- 重启续跑有一次性标记；异常退出不会无限自动重试。技能请求在重启阶段标记为 `restarting`，不提前报成功。

## 发布要求

每个统一发布必须带三个 `nora-launcher-<platform>-<arch>.json` 清单及其轻量 ZIP。构建工具是 `tooling/release/package-launcher-update.cjs`。轻量 ZIP 不含 `payload`，因此不重复下载 Hermes 和完整系统载荷。

首次安装仍用完整安装包。组件发布可复用上一正式发布的轻量启动器包，前提是启动器版本和受保护源码未改变；发布校验缺失文件、版本不一致或哈希不一致时停止发布。

本次将启动器版本提高到 1.1.0。没有自更新代码的旧启动器不能凭空获得此能力，首次过渡仍需覆盖安装一次。以后使用统一更新入口即可。

替换日志和状态位于数据目录的 `installer/launcher-update/job-*/`；总体任务状态继续记录在 `installer/state.json` 和 `installer/install.log`。程序目录不可写、运行在只读磁盘映像或未完成初次安装时，不保证能自更新，会保留原安装并提示原因。

本轮未发布，也未替换运行中的用户应用。跨平台单元测试不能代替三平台真实打包升级验收。
