# 配对重试与独立部署更新：修复验收记录

日期：2026-10-16。范围仅为配对永久锁定、独立更新单文件入口缺依赖、独立部署误用桌面执行凭据，以及这条更新链路的失败恢复。修改在独立分支 `codex/fix-pairing-standalone-update` 的工作区；没有提交、合并、推送、改动正式入口或正式发布。

## 结论与行为变化

| 问题 | 修复后行为 | 达到的证据 |
| --- | --- | --- |
| 配对失败两次后永久阻止提交 | 两次实际执行失败后进行 30 秒本地冷却；倒计时结束允许用户重新输入配对码。重启保留截止时间，不延长冷却；旧永久锁定记录允许新提交，保留原记录 | 控制器回归；Windows、Mac 原生 Electron 窗口两阶段重试验收 |
| 下载的独立 bootstrap 在准备资源前导入不存在的操作模块 | 独立单文件入口先校验并提取完整 runner，再交由该 runner 更新；不再要求下载目录有源码仓库的辅助文件 | 单文件隔离回归；Linux 真实安装副本的冷入口恢复 |
| 无桌面启动器的旧独立部署要求 APP 凭据 | 正面核验已有独立安装后，持有本安装写锁执行；桌面实例及其损坏绑定仍拒绝降级到独立模式 | 原 2.4.2 技能、bootstrap 入口到候选版本的实际更新；桌面标记拒绝合同通过 |
| 独立更新失败或程序目录移动后中断 | 使用既有持久事务和备份恢复旧程序、配置及原运行状态；程序目录暂时缺失时仍可发现已归属的恢复计划；恢复后结束事务，下一次更新可执行 | Linux 实际端口冲突、真实目录移动后 SIGKILL、单文件恢复及后续更新通过 |

配对日志不再将所有激活进程的非零退出都解释为“配对码过期”；增加有界失败说明并遮蔽本次配对码。原始事件最初两次激活失败的具体原因仍未知，这次验收不能反向证明它们是网络或配对码问题。

## 原生界面发现并一并修正的缺口

1. Electron 38.8.6 的 contextBridge 传递被拒绝的 Error 时丢失自定义字段，导致任务允许重新配对，但界面没有该入口。最小实验确认 Error 仅保留 message，普通 DTO 可保留 operation、guidance 和 allowedActions。preload 现在拒绝已限定字段的普通 DTO，真实后端原始异常仍由原日志系统保存。
2. 通用 controls 刷新会短暂覆盖配对倒计时的禁用状态。已让刷新遵守同一个冷却截止时间；回归先重现该覆盖，再确认修正。
3. 旧、新 SillyTavern 启动均可能轮换自动设置备份，严格恢复校验因此失败。现在只对精确命名的自动设置备份封存原字节，启动后补回缺失项；手工备份、聊天、角色、世界的校验不放宽。复制采用校验后原子落盘，覆盖半复制中断、恢复再次中断和归档被篡改的检查。

## Linux 2.4.2 实测

原主机是 2.4.2 原生 Node 酒馆独立部署，原提交 `3b1bcd4bb196a7ecc68fc279568ec2669377f294`。在同一主机受保护的临时目录复制旧程序和实际酒馆状态，模型及凭据替换为测试占位值，使用独立本机端口，不修改原实例。

旧技能与 bootstrap 的字节保留。验收只将资源选择重定向到本轮本地候选目录，并显式允许 candidate；没有让正式用户获得这份候选。这验证旧入口解析、校验、替换、恢复和再更新，不能作为正式公网 latest 已切换的证据。

| 步骤 | 结果 |
| --- | --- |
| 停止旧程序后占用目标端口，触发新版启动失败 | 返回失败并自动恢复 2.4.2；事务 `restored`，旧服务 HTTP 200 |
| 真实移动旧程序目录后立即 SIGKILL 更新进程 | 确认程序目录缺失、持久恢复计划存在 |
| 从下载的单文件入口重新执行 | 恢复 2.4.2；事务 `restored`，旧服务 HTTP 200 |
| 从恢复后的原 2.4.2 技能入口再更新 | 更新到 2.5.2 候选；事务 `committed`，新服务 HTTP 200 |
| 各验证点的数据比较 | 375 个用户文件逐个 SHA256 不变；模型配置、测试凭据不变；用户自定义扩展保留 |

375 个文件包括自动设置备份。只排除代码已明确接管的 `native/_cache/nora-assets-v3` 与固定内置扩展目录，不排除整个 extensions、backups 或未知目录。首次严格失败的自动备份轮换问题先保留证据再修复，没有删除事务、忽略差异或把失败改记为通过。

结束时停止并核验本轮五个隔离副本的进程，删除这些测试数据副本，保留技术证据。原实例仍为 2.4.2、HTTP 健康；用户要求的 SSH 长连接保持。

## Windows 与 Mac 配对重试

两端使用 Electron 38.8.6、生产 HTML/controller/preload、真实任务控制器和原生写锁。第一进程实际执行两次受控激活失败，查看新输入入口及 30 秒倒计时后关闭；第二进程读取同一失败记录，倒计时结束提交新输入，执行器总调用次数从 2 变为 3，任务 `succeeded`、写锁空闲。配对码未进入持久记录，测试数据文件不变。

这里的激活回复和服务状态由验收控制，不连接外部 ClawChat。成功页面不能证明真实账号激活、真实网关启动或消息调用通过。Windows 临时任务已注销，两个界面进程均结束。
