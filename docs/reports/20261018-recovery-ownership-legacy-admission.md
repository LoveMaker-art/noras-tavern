## 结论及行为变化

三项在下述指定环境和入口通过。未发现本次范围内尚未解决的验收阻断；这不代表所有历史版本、最终安装器及正式公网分发均已验收。先前主线合并时仍有 Mac 原恢复按钮失败和卸载归属拦截，不能将那次合并解释为已完成这两项；本报告提供后续修复证据。

| 问题 | 已证实的原因 | 本次处理 |
| --- | --- | --- |
| Mac 实际恢复按钮失败 | APP 退出后，恢复 Python 继承了 Electron Crashpad 的 Mach 异常端口连接；Crashpad 等该连接释放，恢复进程又等 APP 下全部可执行进程退出，形成循环等待。历史任务还会执行任务目录内的旧 helper | 恢复使用当前 APP 中的已核验 helper，但保留并核验原任务 helper、计划、资源和快照。工作进程仅解除自身继承的 Crash／Resource／Guard 连接，再按原归属要求等待全部 APP／备份内进程退出；无法解除或无法确认则拒绝改动 |
| Mac 卸载／KEEP 被另一实例 Hermes 拦截 | 旧原生兜底仅凭 Hermes 命令形状拒绝，未进一步证明它是否属于目标目录 | 从系统内核读取带边界的 argv 与有限归属环境，绑定 PID、用户、微秒级创建时间、实际 home／解释器路径及完整 lsof 证据。只有证明另一实例无关才放行；本实例、未知、证据变化、路径重叠仍拒绝 |
| 历史入口遇到 APP-only 批次或旧技能资格限制 | 旧 APP 只读普通 latest；若 latest 指到 APP-only，会失去核心接入路线。部分旧技能还要求桌面 APP 凭据，发布新源码不会改变用户机器里的旧文件 | 普通稳定核心保持 GitHub latest 与国内 `stable.json`；APP-only 只推进固定启动器列表。新普通计划同时初始化两目录，新桌面分别查询。旧技能受限时，使用一次官方自包含 bootstrap 更新原核心和技能，不安装 APP、不清空数据 |

改动没有引入新后台服务、第二套更新器、全局进程白名单或历史记录清空。Windows 卸载检查分支未修改；本次“卸载归属”原生结论限 Mac。
