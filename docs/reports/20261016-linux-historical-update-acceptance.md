# Linux 独立部署历史更新验收补充

2026-10-16。在 `codex/fix-pairing-standalone-update` 独立分支继续处理；没有提交、合并、推送、替换正式入口或发布。这里解决没有桌面启动器的 Linux 酒馆更新，不要求安装或修复启动器。

## 已确认与修订

1. 原始 2.4.3 技能在真实 Linux 隔离实例执行 `--apply --confirm`，因“无法核验已安装的新版启动器”退出，尚未创建替换事务。该检查发生在取得新版 runner 前；只修改未来 runner，不能改变用户机器上的旧入口。官方独立入口可以取得本次更新的 bootstrap 和 runner，接管同一安装，无需桌面程序。
2. 前轮 2.4.2 的成功不足以证明其他依赖版本可更新。原始 2.0.0 实例实际被“依赖不能安全复用”拦住，原服务、数据、模型和凭据保留。缺口是独立部署没有准备新锁定依赖的路径。
3. 现在只在已正面核验的 Linux 独立上下文、持有安装锁、目标位于本次私有 staging 时，执行 `npm ci --omit=dev --ignore-scripts`。依赖清单及 package/lock 字节核对成功后才停旧服务。需要安装脚本的锁拒绝执行。桌面实例不进入这条路径，原桌面凭据检查没有放宽。

技能与独立更新指引已同步。旧版已安装的脚本不会因未发布的源码修改而自动变化：旧入口被拦住时，诺拉可以执行官方独立更新入口，更新原酒馆；并非安装第二套酒馆或补装启动器。

## 本轮 Linux 实测

使用原始公开发布的 app、ops、MCP 资产，每个压缩包及归档成员均校验原发布摘要；不是把新版改写版本号。各旧程序分别安装对应依赖并实际启动，再通过旧程序 HTTP 接口创建世界与角色，写入会话和世界书。模型及 Key 使用测试占位值，端口、目录隔离，不连接外部模型或 IM 账号。

目标是本地 **2.5.2 修复候选**，不是线上已发布的 2.5.2 字节。只将资源选择指向固定候选；真实 bootstrap、校验、替换和恢复执行器不替换。

| --- | --- | --- | --- |
| 2.0.0 | 通过 | Tavern、MCP 按新 lock 准备 | 152 项受检，世界、会话标识、聊天、角色、世界书、模型与凭据保留 |
| 2.2.0 | 通过 | Tavern 按新 lock 准备，MCP 复用 | 152 项受检，上述数据和标识保留 |

四例最终均 HTTP 健康、事务 committed，没有安装启动器。比较只排除明确由代码管理的内置扩展和 `nora-assets-v3` 缓存，不排除整个 extensions 或 backups。

2.0 首次由新 core 打开旧世界时，一条已完成的创建任务由 operation/v1 转为 operation/v2，释放原暂存命令；已对照现有 `OperationJournal` 合同验证任务 ID、世界、会话、状态和摘要保留。该转换单独记录，未忽略未知差异或改写基线；其他受检用户文件逐个摘要一致。

升级后的真实诺拉技能入口还执行了环境检查和一次更新：识别 `managed: false`，进入独立 bootstrap，正确返回 `up-to-date`。这验证技能执行链，不代表真实外部诺拉会话已自主完成更新。

## 失败恢复与后续操作

在原始 2.3.0 副本完成新版依赖准备、停止旧程序后，实际占用其端口，阻断新版启动。更新失败后释放故障端口，由真实恢复流程自动还原：旧版 2.3.0、事务 restored、任务失败并结束；152 项用户文件、模型和凭据保留，旧服务 HTTP 健康。另一次明确更新随后成功到候选，事务 committed，世界和会话仍可读取。

这补验依赖 lock 改变时的回退。前轮 2.4.2 的真实目录移动后 SIGKILL、冷入口恢复及再更新证据见[前轮记录](20261016-pair-standalone-update-acceptance.md)。两轮候选身份不同，不混作同一次产物验收。

## 历史范围与剩余阻断

公开发布目录共 122 个正式语义版本，其中 54 个为 2.x。历史源码入口分类为：42 个 raw updater 入口，8 个独立 bootstrap/桌面委托入口，4 个取新版 runner 前附带桌面检查的入口。**分类不是逐版本实测**；实际流程以上表四个原版及前轮 2.4.2 为证据。

仍不能承诺“所有历史版本均已适配”：

1. **1.x Python 旧架构尚未完成兼容。** 服务启动及 productions 数据迁移合同不同；当前代码对无法恢复的非受管 Python 服务会拒绝升级。这是已知限制，不只是没实测。需要单独核对原服务和数据转换，不能用原生 2.x 结果代替，也不能要求用户清空数据或补装桌面启动器。
2. 原云平台 Supervisor 接管、真实 Liveware 注册及外部账号流程，不是本轮通过项；此次是同机隔离 NativeRuntime 实测。
3. 公网 latest 未指向本分支，正式下载仍是已发布代码。尚未冻结正式版本、构建正式安装器或验收正式入口。
