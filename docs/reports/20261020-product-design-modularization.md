## 已接受结果与范围

用户确认按“项目总览与共同约定＋启动器＋诺拉＋酒馆”重组现行产品设计，并将这套设计作为项目内开发的最高产品依据。后续开发须先对照规则；改变已确认行为前说明差异并取得确认。全局执行约束与用户最新明确指令继续适用。

本次仅迁移文档、澄清文档权威和更新工作入口。保留普通玩家优先、完整版配置与配对、现有按钮与关闭行为、核心独立更新、双更新一次发起、兼容部分完成、失败恢复、用户数据保护、按影响交付及关联测试前置。修复器独立维护、未合入的发布提速工具及其证据边界保持。没有产品代码、自动门禁、构建、测试机操作、合并、推送或发布授权。

1. 总览和三份模块设计共同构成明确列举、同版本的唯一现行设计；模块设计覆盖目标、范围、流程、失败、边界和验收。
2. PB-01 至 PB-09、PR-01 至 PR-14、已确认／已取消选择逐项有唯一归属；旧入口和已被引用的锚点仍可到达现行内容。
3. 发布操作、历史证据与现行产品行为分别维护；不把工具计划、测试数量或历史成功改写为已部署能力。
4. AGENTS、贡献说明和文档入口要求开发前核对、产品变化前确认、交付前对账；已授权的例行实现不增加重复审批。

## 续项：启动器全部产品行为覆盖

用户随后明确：覆盖启动器现有的全部页面、功能、交互和异常流程，不能只整理历史重点修复项。前一轮已完成规则归位，尚未完成逐页面／控件规格盘点；本续项补齐这个覆盖缺口，不将前一轮导航检查作为完整设计覆盖证明。

范围：盘点正式 UI、真实控制器、桌面桥接和当前主线后端；为每项现有能力登记入口、前提、动作、反馈、退出／重试、数据影响、平台差异和验收。保留现有控件、产品规则及所有用户数据，不改产品代码，不新增功能，不访问用户测试机、浏览器或真实外部账号，不构建合并发布。设计冲突与尚无确认的选择单列，不能由代码现状自动成为已确认策略。

代码参照为主线 `65a2a7a` 的已发布 2.2.5／2.5.5 源码。原项目目录仍位于更早的提速分支，因此不将其旧主进程当作最新版依据；完成后仅同步文档。执行证据另补至本节。

覆盖验收：正式静态入口、动态按钮、模型／配对字段、弹层及键盘行为、状态／任务／日志、版本／技能更新、目录／安装／卸载、外链／社区／人物交互、窗口和生命周期均有唯一设计位置；真实控制器和桥接 API 逐项对账。现状核对、已确认规则、待决事项和未执行的原生／视觉验收分别记录。

续项结果：设计集合更新为1.15，启动器扩展为24节并建立22类能力的验收目录。30个桥接方法、14个路由、8个管理动作及动态控件已逐项定位；原条款与验收保留。产品选择统一登记在总览，技术疑点单列；详见[完整覆盖审计](20261020-launcher-design-coverage.md)。本轮只完成文档覆盖、静态核对和文档导航，不宣称完成产品原生实测；未提交合并推送或构建发布。

## 续项：诺拉全能力设计覆盖
