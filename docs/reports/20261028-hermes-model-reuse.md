## 实际改动

1. **共用实现**：`model_config.py` 接收启动器和技能请求，`hermes_models.py` 调用当前实例 Hermes 的供应商目录、认证状态、配置读写、运行配置解析和请求适配。删除启动器维护的固定供应商名单及另一套 HTTP 验证实现。没有升级 Hermes 或增加模型 SDK 依赖。
2. **启动器**：保留原模型表单及提交步骤；选项、默认值、认证方式和接口要求来自 Hermes。需要订阅登录时提供原生授权链接／设备码／授权码输入和取消。登录与选择主模型分别完成；普通模型测试直接调用所选模型，不进入备用模型回退。
3. **技能**：沿用本地受管实例范围，新增目录、模型列表、认证状态和原生登录调用；保存仍不自动付费测试、不热切换当前会话。API Key 和授权回复只经当前标准输入传入。
4. **配置兼容与保护**：读取旧模型记录；保留已有命名供应商、自定义请求头、请求参数、环境变量和动态凭据配置。仅更新选中配置。普通保存异常恢复本次原配置，损坏 YAML 原样保留，不让原生自动修复覆盖现场或把含 Key 源码行写进错误。
5. **酒馆边界**：可兼容的空白模型继续按旧规则初始化；订阅凭据、外部认证及酒馆不支持的服务不强行转换。诺拉已保存配置继续有效，酒馆同步结果独立返回，既有酒馆／MVU 选择保留。
6. **交付引用**：两个新共用文件加入源码投影、启动器资源和资源身份校验；只为固定 `model_config.py` 增加已有操作入口的授权和持续输入支持，不开放任意脚本。卸载离线检查只补齐依赖文件清单，没有改变卸载流程。

### 测试执行中纠正的事项

早期使用合成无效 Key 的 Anthropic 测试暴露：原生辅助客户端忽略了候选地址，而本机系统代理又绕过了只检查 socket 地址的隔离措施，产生了一次外部 401 请求。没有使用真实 Key。现已在产品验证调用前核对实际地址，并使用原生 Anthropic 客户端构造候选连接；最终回归同时限制 HTTP 逻辑 URL 和 socket 目标到指定回环端口，清除代理环境并禁用系统代理。最终通过结果来自修正后的隔离运行。
