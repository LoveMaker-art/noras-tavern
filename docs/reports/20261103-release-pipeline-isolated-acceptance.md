## 真实执行发现并修正的缺陷

1. **工作流上下文错误。** 首次派发在运行前被拒绝，任务级env误用`runner.temp`。改到步骤env并补前置负向检查；经SHA核验的actionlint1.7.12对全部五份工作流语义检查通过。未将解析失败说成产品安装失败。
2. **复用任务被误判为多个来源。** GitHub会为未重新执行的成功任务生成新展示ID／attempt，实际执行时间和步骤仍为原值。真实API重放确认旧校验误拒绝。只有同run／提交、完整成功门禁、时间／步骤／执行机完全一致且分属不同attempt的记录才合并，绑定最早生产者；实际不同执行、同attempt重复、错摘要、错run或失败仍拒绝。`7f8556b`修正后207项关联回归及真实API重放通过，最终只校验CI消费三次attempt的实际记录通过。
3. **最终汇总槽位未替换。** 原生恢复成功后出现两份同名`nora-component-acceptance`，唯一性门禁正确拒绝；[首次只校验任务](https://github.com/LoveMaker-art/noras-tavern/actions/runs/41570457959)失败于来源恢复，未进入正式写入。`c1a810a`为该CI槽位补`overwrite: true`，合同回归通过。同一SDK跨attempt覆盖的实际正例来自本轮ARM回执：旧ID被新ID替换且仅保留一个当前槽位。对冻结旧工作流留下的两份成功汇总，先归档两份字节及摘要，再按实际生产时间／任务确认并清理旧成功槽位；失败诊断未借此放行或删除。没有声称冻结的`f0bd042`执行了后来新增的字段，也没有为了这一字段重跑全部原生场景。

工作流修订后关联207项通过，五份语义检查通过。测试数量只说明执行范围，验收依据仍是上表各流程和原始事实。

独立上传脚本另有一个核对方法错误：比较了不存在的Beta文件返回的动态404页面哈希。原错误留存；补核对实际稳定／启动器文件字节和Beta持续404，确认正式内容未变。没有重传产品或放宽真实文件摘要要求。
