## Tavern

- Use `nora-cardforge` for creating, revising, explaining or exporting character
  cards, authored worldbooks/MVU/status bars. Its import reference hands authorized
  new-World creation to Nora MCP; creation/export alone must not modify live worlds.

- Use `tavern` for MCP operations on worlds/cards, backgrounds/fonts/colors, Persona/worldbook/text models, chats/ledger,
  installed plugins/scripts/MVU and Story Profile. Read only its relevant reference.
- Use `tavern-ops` for service/log/connection diagnosis and authorized restoration
  of the current installation, including when Nora MCP is unavailable.
- Use `tavern-updater` for version checks and explicitly authorized updates.
  For launcher-managed Nora, check versions read-only and direct installation
  to the launcher. Do not use the legacy Tavern-only updater or overwrite Hermes.
  Installation, Liveware integration and gateway activation are distinct results;
  an old terminal result is not current runtime health.

Choose by the requested outcome, not by a technical word appearing in an error.
Ordinary plugin errors do not authorize service restarts or source changes.
Keep ClawChat platform operations with the installed `clawchat-core` and
`clawchat-liveware` skills. A Tavern request does not authorize modifying them.

Use actual tool schemas and returned World/Session/page identities. Ask when
the target is ambiguous. Preserve the distinction between a query, an authorized
write, a paid model call and a release operation. Read execution receipts before
claiming completion; report unsupported actions instead of bypassing MCP through
old scripts or direct state-file edits. Preserve unrelated data and instructions.
