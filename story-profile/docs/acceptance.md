# Story Profile 内置模块验收清单

## 保留

- 原版 `actor.html`、`actor.js` 与对应样式和交互。
- 原项目的偏好记录、时间线归档、八类口味字段和 Hermes 投影语义。
- 复盘失败不阻断 Nora 正常聊天的行为。

## 替换

- 原 Python Tavern 对话读取方式替换为 Nora World ID 到 SillyTavern chat 的适配。
- 原模型注册表读取方式替换为当前 Nora 有效文本模型适配。
- 原 production ID 复盘游标替换为稳定 World ID 复盘游标。
- Story Profile 源码位于同仓 `story-profile/`，保留独立模块；Nora Tavern 构建时生成内置运行快照 `app/story_profile_runtime`。

## 隐藏

- 模块内部状态、模型提示词和失败重试细节不暴露给 Story Profile UI。
- 生产运行时不直接读取 Story Profile 源码，只读取发布包内经过校验的快照。

## 与剧情账本的边界

- 剧情账本、运行时人物状态和故事连续性提示注入由 Tavern 的剧情账本插件负责，不由 Story Profile 重复生成。
- 已接通成功激活账本的共享故事记忆投影；`USER.md` 投影用户偏好，`MEMORY.md` 投影共享故事，均保留非托管内容。具体限制由 `tests/test_projections.py` 验证。

## 可观察验收

1. 少于 15 个用户回合时不调模型。
2. 第 15 个用户回合完成后只调度一次后台复盘。
3. 同一批对话重复检查不会再次复盘。
4. 模型失败不推进游标；下一次检查可重试。
5. 有明确偏好证据时，成功后档案新增有效偏好，八类口味按证据更新；证据不足时保持空档案，不臆造内容。
6. “对你的了解”和偏好成长年表读取同一份持久化档案。
7. 页面刷新和进程重启后结果仍存在。
8. 正常聊天生成不等待 Story Profile 复盘完成。
9. 正常发送完成后检查当前世界；切换世界时检查离开的世界，且两者都不能把复盘失败传播到聊天或切换流程。
10. Nora 发布归档包含经过校验的 Story Profile 内置运行快照，解压后不依赖同级源码目录。
