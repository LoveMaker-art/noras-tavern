# 配置诺拉模型

配置当前受管本地实例的诺拉主模型，服务目录和协议以已安装 Hermes 为准。用户在聊天中说明目标并完成本人授权，由诺拉操作后台工具，不要求用户自己打开终端。启动器保留既有服务表单，与本技能共用核心配置执行和只读结果；其他服务仍由本技能配置。酒馆／MVU、人格、MCP、回退、其他服务和故事内容保持原样。

## 先确认目标

1. 用下面入口调用 `catalog`，取得本机实际服务 ID、原生 `aliases` 和认证类型；调用 `inspect` 读取当前默认及`models`已配置列表。用户给出的名称匹配某项别名时，使用该项服务 ID，不因别名没有单列成 ID 就判定不支持。这两项不发起模型生成，不返回凭据。
2. 确认服务、模型及必要认证。只有 Key 时先问清供应商；Go 与 Zen 不混用。用户只改一个设置时，保留其他原生字段，不重建整个配置。
3. 告知会用固定诊断内容验证所选模型，可能产生调用费用；取得当次授权后再执行保存。验证不使用用户聊天、人格或故事，不能拿备用模型成功代替所选模型成功。未授权时只查询，不切换。
4. 根据所选服务选择下方直接配置或原生向导。SDK、外部 CLI、地区／项目／租户或本人登录缺失时，明确缺项，再按用户授权处理；不复制另一实例的凭据，不伪装成通用中转。

## 调用入口

从本技能实际安装位置执行 `scripts/configure_provider.py`，使用当前实例的 Python：

- macOS：`"$HERMES_HOME/hermes-agent/venv/bin/python" -B "<本技能绝对路径>/scripts/configure_provider.py"`
- Windows PowerShell：`& "$env:HERMES_HOME\hermes-agent\venv\Scripts\python.exe" -B "<本技能绝对路径>\scripts\configure_provider.py"`

JSON 请求从标准输入传入，非交互时为第一行；PTY 中的 JSON 输入自动隐藏回显。凭据不进入命令参数、shell 拼接、持久请求文件或对话回复，不从历史聊天搜 Key。

入口从本实例核心组件加载共用实现，不从桌面APP加载。核心组件缺失时保留原配置并说明缺项，不要求打开新版启动器，不另复制一套执行代码。

| 操作 | 输入与结果 |
| --- | --- |
| 查询目录 | `{"action":"catalog"}`：返回当前原生服务及已存命名服务；列出不代表账号可用 |
| 读取选择 | `{"action":"inspect"}`：返回服务、模型、地址、协议；不验证连通性 |
| 直接配置 | `action:"save"`、`verify_authorized:true`，加本次模型字段；候选验证成功后才提交 |
| 原生向导 | 同一脚本加 `--wizard`；使用后台 PTY，让原生流程完成服务选择、登录和模型选择 |

用 Hermes 当前工具 schema 中的 `terminal` 后台 PTY 启动入口，再用 `process` 的轮询／输入／提交操作继续；工具字段以实际 schema 为准。入口检查真实 TTY，创建失败时停止本次配置，不把无法输入的后台管道当成授权会话。记录本次进程 ID，逐步读取提示；用户所需登录网址／设备码返回同一对话，由本人授权。不要把整段原生输出或凭据转发给用户。

原生登录期间保持当前网关和诺拉会话运行。句柄丢失、网关重启或超时后，先查原进程状态；无法继续则结束该候选并重新开始，不声称旧输入会话可恢复，也不同时再开一个写者。

## 直接配置：Key、已有认证和高级字段

用户要换回已配置模型时，先读`inspect.models`，按服务、连接及模型确认唯一目标，提交该项`id`，不要求重新提供仍有效的Key，不按模型名称猜连接。当前默认无需重复切换。目标需要重新认证时如实说明；历史未保存的模型不从聊天或日志找凭据重建。

```json
{"action":"switch","id":"<inspect返回的模型配置ID>","verify_authorized":true}
```

此操作与启动器模型列表共用候选验证和保存。添加成功保留可复用旧选择，元数据不存明文凭据；只切换诺拉全局默认，Hermes的单会话／频道指定继续有效，不自动重启或中断本次对话。不要把保存默认报告成所有进行中的回复已经切换。

基础字段为 `provider`、`model`，按需带 `api_key`、`base_url` 和 `auth_mode`。原生服务已保存的凭据可复用；新 Key 只更新所选服务。DeepSeek 没有指定模型时沿用 `deepseek-v4-flash`，其他服务使用用户确认的模型 ID。

用户没有明确指定地址时，原生服务不传 `base_url`；目录里的默认地址只是参考，实际地址交给 Hermes 按账户、套餐、地区及既有原生设置解析。不要把参考地址填回去覆盖其自动路由。用户指定地址时才显式传入，候选仍须实际验证成功。

```json
{"action":"save","verify_authorized":true,"provider":"opencode-go","model":"<Go 模型 ID>","api_key":"<本次 Go Key>","auth_mode":"key"}
```

Go 的地址、模型规范化、协议、稳定 `x-opencode-session` 与 User-Agent 由 Hermes 原生适配负责；不手写协议或自建代理绕过。配置可用与账号套餐权限分开确认。

`native_config` 接收 Hermes 原生的 `model`、`providers`、`custom_providers`、`moa` 章节，按字段合并。用于原生协议、请求头／请求体参数、动态凭据命令、地区／项目及命名服务等。`environment` 接收本次服务所需的原生环境变量，如云区域；不能修改实例路径、解释器或进程控制变量。只提交用户本次要求的字段，先核对本机 Hermes 对该服务的配置定义，不猜字段名，也不整份复制其他实例的 YAML。

```json
{"action":"save","verify_authorized":true,"native_config":{"model":{"provider":"<原生服务 ID>","default":"<模型 ID>","api_mode":"<本机支持的原生协议>"}},"environment":{"<该服务要求的环境变量>":"<本次值>"}}
```

简式 `provider:"custom"` 沿用现有 Nora 管理的命名服务；需要 HTTP(S) 基础地址和 Key，仅用户明确无需认证时使用 `auth_mode:"none"`。完整原生自定义设置放入 `native_config`，保留原服务身份与高级字段。不能用空 Key 假装订阅登录或云认证已完成。

## 原生向导：首次登录和专属流程

运行 `--wizard`，让当前 Hermes 的服务／认证／模型流程在受保护的候选目录执行。已明确授权验证时可加 `--verify-authorized`；否则最终会询问是否验证并切换。MiniMax 的地区参数使用本机原生流程支持的 `--region cn`；其他地区按原生要求选择。

- OAuth／设备码／订阅：把授权步骤交给用户本人；不填写假登录状态。Qwen 等服务需要已有外部 CLI 登录时，如实说明并按授权准备。
- Bedrock／Vertex／Azure 等：保留其原生凭据链、地区、项目／租户和 SDK 要求，不变成统一 Key 表单。
- 本地免认证、ACP／外部 CLI：复用原生服务和本机依赖。ACP 必须明确模型，不能用客户端默默退回的默认模型冒充通过。
- MoA：仅按用户明确指定配置组合；验证可能调用多个参考模型，不称为一次请求／固定费用。任一参考模型未完成都不能报告全组可用。
- 向导未暴露的必要原生字段，在随后隐藏输入的 JSON 中补充，格式是 `native_config` 所接受的章节对象。留空则保留向导结果。辅助模型设置和删除服务不在本技能范围内。

当前最小验证支持本机原生 Chat Completions、Responses、Anthropic Messages、Bedrock Converse 及这些模式下的云／ACP／组合适配。若原生传输不能提供可核验目标的安全最小调用，例如 `codex_app_server`，会返回明确限制并保留旧配置；不能换另一种传输冒充该项已验证。真实账号、外部依赖和这种传输限制须分别说明，不能把目录齐全说成所有服务已实测。

## 成功、取消与失败

- 只有退出码 0，且结果同时包含 `ok:true`、`verified:true`、`validation:"api-response"`，才报告“所选模型已验证并保存，下次新会话采用”。不重启网关，不声称当前正在回复的会话已换模型；建议用户新开会话确认正常回复。
- 取消选择、拒绝验证、登录／调用失败或目标不一致：旧模型和正式配置保持，修正条件后可重试；不清空任务历史、用户配置或故事。
- 验证过程中正式配置被其他操作修改：拒绝覆盖其结果。实例正安装／更新时等待完成，不绕过原有写锁。
- 提交出现普通异常：恢复本次 `config.yaml`、`.env`、`auth.json` 与 `installer/model.json` 原值；若恢复本身失败，明确报告，不宣称已恢复。
- 候选目录仅复制必要配置与凭据，使用本用户专有权限；子进程结束后清理，不生成额外含 Key 的持久备份。不承诺强杀、断电或磁盘故障的自动恢复；外部 CLI／服务商已完成的登录也不因清理本地候选而撤销。
- 脚本不依赖桌面 APP、APP 收据或新版启动器命令。旧启动器对部分原生服务的显示、OAuth／云认证状态识别可能有限；不要为骗过旧检查伪造 Key、改为 custom 或复制动态令牌。配置成功不代表旧 APP 所有维护页都已兼容。

本技能限具备实例记录的 Mac／Windows 受管本地安装，不扩展任意云端 Hermes。酒馆／MVU 配置继续独立保留。
