# 统一字段标准：nora-mvu-fields/v1

制作新 MVU 卡前读取本文件。它是制卡输入标准，不是模型输出协议；
Nora 中模型输出为程序提供的 `nora-mvu/1`，原 MVU 中使用生成器提供的 JSONPatch
基础格式；共用相同字段和 Zod。原卡评估与原样导入不经过此生成器。

## 一份定义，四个去向

`features/mvu.json` 唯一定义字段类型、初值、边界和玩法说明。
生成器据此形成 Zod、初始化条目、模型更新规则以及显示路径校验依据。
状态栏仅引用字段，不重新定义字段。不手改生成脚本或初始化条目。

```json
{
  "format": "nora-mvu-fields/v1",
  "variables": [
    {
      "group": "玩家",
      "field": "能量",
      "type": "number",
      "default": 80,
      "min": 0,
      "max": 100,
      "description": "表示剩余行动能量；明确消耗时降低，休息或补给后恢复。"
    },
    {
      "group": "玩家",
      "field": "背包",
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "名称": { "type": "string" },
          "数量": { "type": "number", "integer": true, "min": 1 }
        }
      },
      "default": [{ "名称": "地图", "数量": 1 }],
      "description": "获得物品时新增或增加数量；消耗后减少，耗尽则移除该项。"
    },
    {
      "group": "世界",
      "field": "人物档案",
      "type": "record",
      "values": {
        "type": "object",
        "properties": {
          "姓名": { "type": "string" },
          "关系": { "type": "enum", "enumValues": ["陌生", "熟悉"] }
        }
      },
      "default": {},
      "description": "确认人物身份后以稳定人物ID新增档案；有明确交往事件时更新关系。"
    }
  ]
}
```

该例的对应关系：

| 用途 | 能量 | 背包中的第一个物品名称 |
| --- | --- | --- |
| 初始状态 | `stat_data.玩家.能量 = 80` | `stat_data.玩家.背包[0].名称 = "地图"` |
| Nora 模型路径 | `["玩家","能量"]` | `["玩家","背包",0,"名称"]` |
| 原 MVU 模型路径 | `/玩家/能量` | `/玩家/背包/0/名称` |
| 状态栏绑定 | 同一数组路径 | 同一数组路径 |
| 校验 | 数字，0–100 | 背包是对象数组，名称是字符串 |

MVU 的人物数据不等于酒馆核心的角色设定数组；不要把创建一项 MVU 档案
宣称为创建了世界里的角色资料。两者是不同数据所有者。

## 字段填写规则

每个顶层变量必须明确填写 `group`、`field`、`type`、`default`、
`description`。缺省值不再猜测：数字用 JSON 数字，布尔用 true/false，
容器用真实数组/对象。空初值也明确写出；枚举默认值必须是候选之一。
`defaultValue`、`recordFields` 和未知属性会报错，不再被静默转换或忽略。

- 分组名是一个键；`field: "关系.阶段"` 表示嵌套路径。
- 键允许字母、汉字、数字、`$`、`-`，中间可有下划线。分组不用点号。
  空段、空白、原型保留字和以下划线开头的只读键不属于此制卡标准。
- 路径不能重复，不能同时定义 `档案` 和 `档案.姓名`。对象子字段写在
  该对象的 `properties` 中；与其他独立变量的路径不得重叠。
- 最多 512 个顶层变量、字段路径最多 16 段，嵌套结构也有深度限制。
  超限直接报错，不截断字段。
- `description` 写“代表什么、单位、何时变化、变化依据”。模型可以误判剧情，
  因而自然语言里的“每轮 +3”不等于强制的增量限制。

## 支持的类型

| type | 额外定义 | 约束 |
| --- | --- | --- |
| string | 无 | 严格字符串，不自动把数字变成文字 |
| number | 可选 min/max、integer、clamp | 严格有限数字；min/max 默认拒绝越界；integer 要求安全整数 |
| boolean | 无 | 严格 true/false |
| enum | `enumValues: ["陌生","熟悉"]` | 非空、不重复的字符串候选，不能写逗号串 |
| object | `properties: {"姓名":{"type":"string"}}` | 显式子字段，全部必填，拒绝未知子字段 |
| array | `items: {"type":"..." }` | 明确每一项类型，支持对象数组，不自动假设字符串数组 |
| record | `values: {"type":"..." }` | 动态键、固定值类型；支持对象档案，键遵循上述命名规则 |

items、values、properties 子节点继续使用同一类型结构，可含 description；
子节点不另写 default。顶层 default 给出完整初始数据，非空容器逐项校验。
更新整个对象或新增对象项时必须提供完整的必填子字段。
删除必填字段会被 Zod 拒绝；动态档案成员和数组元素可删除。

`clamp: true` 必须有至少一个数字边界，表示运行时越界裁剪。
未设置 clamp 时，边界用于拒绝越界。初值即使开启 clamp 也必须已经合法，
避免初始化时悄悄改值。没有隐式 ±999999 边界，不生成 z.coerce.number。
本版不表达 nullable、自定义 transform/refine、派生公式或任意脚本校验；
有这类需求先说明标准缺口，不猜一个近似字段类型。

## 生成与检查

编译元数据 `cfMvuFieldContract` 包含标准版本、类型树和初始状态；
`cfMvuVarGroups` 是同一输入派生的字段清单，不是当前进度。
初始化条目使用 JSON 形式（也是合法 YAML），避免手拼键名和初值发生转义差异。

构建检查输入、初值及生成的 Zod/规则是否一致；生成器本身不运行第三方卡脚本。
回归测试使用实际 Zod 校验生成初值，并有对应 Nora 注册器的命令级测试。
构建通过不是目标实例已注册或已保存的证据。

运行时字段提示有长度限制，复杂的超长 Schema 不保证完整发给模型；真正类型校验
仍由 Zod 执行。严格字段只保证结构，不保证模型对剧情的判断正确。

## 评估原卡与解释变量

原卡可能在 Zod、初始化条目、脚本或世界书里定义字段，缺少上述元数据不等于没有 MVU。
只读追踪“声明/初值 → 更新者 → 校验 → 消费者”，未知外部脚本标为未知，不自动改卡。
回答当前值必须取得具体 World/Session/消息快照；默认值、显示回退值不能冒充当前值。
