# 构建工具

- `source-layout.json`：源码路径到现有交付路径的唯一映射。
- `layout.mjs`：映射、路径冲突与缺失检查，不包含安装业务。
- `run.mjs`：从源码生成临时交付布局后运行开发命令，结束清理自身导出目录。
- `release/`：发布源码导出、平台运行时封装、系统清单与最终资产校验。
- `runtime/`：ClawChat 固定来源、构建审核和包内组件检查。
- `checks/`：架构、兼容性、工作流、索引与运行指标检查。

`release/package-release.mjs` 直接从 Git 源码构建；`checks/index-project.mjs` 直接索引当前源码，输出到忽略的 `.codebase-memory/project-index.json`。其他依赖交付相对路径的内部命令通过 `run.mjs` 运行。完整命令见 [开发说明](../CONTRIBUTING.md)。

映射只改变导出位置，不改写人格、提示词、业务代码或图片。已有发布包使用的旧文件名、模块名、安装目录继续有效。新增交付文件须检查映射、发布白名单、完整组件清单及对应测试。

## 流水线执行规则

发布、安装和界面源码检查在准备运行时前完整执行一次。真实运行时就绪后，仅重复使用原生执行者的旧恢复、受管 Python 诊断、Python 技能交接及可选 Electron 崩溃检查。崩溃检查需要明确提供 `NORA_TEST_ELECTRON`；缺输入记为跳过，不计原生崩溃验收通过。完整维护、历史升级和安装包检查仍分别执行。工作流合同维护完整覆盖清单，去掉重复调用不能去掉唯一完整执行。

Windows、Intel 的 JavaScript 源码检查各有 15 分钟上限，内部取消提前留出实际子进程关闭时间；Python 组和外层步骤另有有限预算。调整前须读取断言、关闭证据及耗时。提高上限不等于产品修复，也不等于远端已通过。

任务按源码提交及目标平台隔离，启动 Intel 单平台验证不能中止正在运行的 Windows 或 ARM 任务。源码及构建输入不变时，用 `gh run rerun RUN_ID --failed --repo LoveMaker-art/noras-tavern` 仅重跑失败任务及依赖，不因一个平台失败重跑全部平台。输入变化时，按影响选择平台，保留旧产物的原身份；不同提交不能拼成一批正式验收产物。

`verified_windows_run` 可保留其他平台失败的已完成任务中，Windows 自身完整通过的交付。提交、仓库、源码及原生步骤、Chromium 传输检查、GitHub ZIP 摘要、安装器及 APP 证据、酒馆运行／停止两种历史升级证据都须核验。总体失败须由成功前置检查后的其他原生平台解释。Windows 证据缺失、取消、过期、变更或不完整仍阻断复用。正式发布消费已经验收的原字节，不重新构建。
